# AI 支援（枝の要約・重要度の提案）を使えるようにする手順書

このアプリの「AI支援」（Phase 32・33。枝の要約・重要度の提案、子候補・分類／並べ替え・重複検出・不足観点の提案）を動かすために、利用者が行う手順をまとめた文書です。属性提案の仕様は `docs/specifications/features.md` の 37 章、構造提案は 38 章、API は `docs/specifications/api.md` の 20 章を見てください。

## 1. 概要（何を外部へ送るか）

AI 支援は、選んだノードの枝の内容を、サーバー（このアプリの Next.js の API ルート `/api/ai-assist/*`）から AI の提供元（Anthropic の Claude API か OpenAI の API）へ送り、提案を受け取ります。提案は自動では適用せず、画面で変更ごとに採用・却下を選んだものだけを適用します。

**送るもの**: 選んだノードを根とする枝の全ノード（折りたたみなどで隠れているノードも含む）の、ラベルとメモの抜粋（ラベルは各 200 文字、メモは各 500 文字まで、合計 40,000 文字まで）と、ノードの ID・親子関係・重要度。要約では、選んだノード自身のメモは送りません。

**送らないもの**: イラスト・URL・タグ・出典・他のマップ。API キーはサーバーの中だけで使い、ブラウザへは出しません。

送る前に毎回、確認画面に送信先（提供元名・モデル名）と送るものを出します。「送信して提案を作る」を押したときだけ送ります。

## 2. キーの取得

使う提供元のキーを 1 つ以上用意します。どちらか一方だけでも使えます。

- **Anthropic（Claude API。既定）**: Anthropic の公式サイトのトップから Anthropic Console（開発者向けのコンソール）へ進んでサインインし、API キーのページを開いて新しいキーを作ります。
- **OpenAI**: OpenAI の公式サイトのトップから OpenAI Platform（開発者向けのダッシュボード）へ進んでサインインし、API キーのページを開いて新しいキーを作ります。

URL を検索結果や他人のメッセージからたどらず、各社の公式サイトのトップから進んでください。どちらも従量課金で、支払い方法の登録が必要になることがあります（「7. 課金の目安」）。

**キーはパスワードと同じ扱いです。** 画面共有・チャット・Git のコミット・ログに出さないでください。漏れた可能性があれば、提供元のコンソールでそのキーを無効にし、新しいキーを作り直してください。

## 3. `.env.local` の作り方

キーは `client/.env.local` に書きます。

1. `client` ディレクトリで、`.env.local` がすでにあるかを確かめます。

   ```bash
   cd client
   test -f .env.local && echo exists
   ```

2. `exists` と出なければ（まだ無ければ）、見本をコピーします。

   ```bash
   cp .env.example .env.local
   ```

   **`exists` と出たら、`cp` を実行しないでください**（イラスト生成のキーなど、既存の設定を上書きして消してしまいます）。その場合は、`.env.example` の「AI 支援」の節の行を、既存の `.env.local` の末尾へ追記します。

3. `.env.local` に値を書きます（例。値はあなたのキーに置き換えます）。

   ```bash
   ANTHROPIC_API_KEY=<Anthropic Console で作ったキー>
   OPENAI_API_KEY=
   AI_ASSIST_PROVIDER=
   AI_ASSIST_ANTHROPIC_MODEL=
   AI_ASSIST_OPENAI_MODEL=
   ```

4. 開発サーバーを起動し直します（`npm run dev`）。環境変数は起動時に読みます。

注意:

- `.env.local` はコミットしません（`.gitignore` で除外済み）。`git status` に `.env.local` が出ないことを確かめてください。
- 値の前後の空白・改行は取り除き、空白だけの値は未設定とみなします。
- **シェルで同じ名前の変数を `export` していると、`.env.local` より優先されます。** 意図しない値が使われるときは、`echo $ANTHROPIC_API_KEY` などでシェルに残っていないかを確かめてください（値そのものを画面共有に出さないように注意）。
- **サーバーの環境で `ANTHROPIC_CUSTOM_HEADERS`・`OPENAI_CUSTOM_HEADERS` を設定しないでください。** 提供元の SDK はこれらの変数を読んで送るヘッダーに混ぜるため、認証のヘッダーや OpenAI の組織・プロジェクトのヘッダーを上書きでき、このアプリが明示しているキー・設定の効果が崩れることがあります。アプリの側では止められないので、運用で設定しないようにします。

## 4. 提供元とモデルの選び方

| 変数 | 既定 | 意味 |
|------|------|------|
| `ANTHROPIC_API_KEY` | なし | Claude API のキー |
| `OPENAI_API_KEY` | なし | OpenAI API のキー |
| `AI_ASSIST_PROVIDER` | 空（自動） | `anthropic` か `openai`（大文字・小文字は区別しない） |
| `AI_ASSIST_ANTHROPIC_MODEL` | `claude-opus-5-5` | Claude のモデル ID |
| `AI_ASSIST_OPENAI_MODEL` | `gpt-5` | OpenAI のモデル ID |
| `AI_ASSIST_ALLOWED_HOSTS` | 空（既定の 3 種だけ） | AI 支援の API を受け付ける Host のホスト名の追加（カンマ区切り）。「LAN の別端末や別名で開く場合」を参照 |

`AI_ASSIST_PROVIDER` の 3 通り:

| 値 | 使う提供元 |
|----|------------|
| 空 | `ANTHROPIC_API_KEY` があれば Claude、無く `OPENAI_API_KEY` があれば OpenAI、どちらも無ければ無効 |
| `anthropic` | Claude。`ANTHROPIC_API_KEY` が無ければ無効 |
| `openai` | OpenAI。`OPENAI_API_KEY` が無ければ無効 |

明示した提供元のキーが無いとき、または `AI_ASSIST_PROVIDER` が 2 つの値のどちらでもないときは、もう一方の提供元へ **自動では切り替えず**、AI 支援を無効（「AI 支援が設定されていません」）にします。

**LAN の別端末や別名で開く場合**: AI 支援の API（`/api/ai-assist/*`）は、ブラウザが送る `Host` のホスト名が `localhost`・`127.0.0.1`・`[::1]` のどれかのときだけ受け付けます（ポートは問わず、大文字・小文字は区別しません）。DNS rebinding（攻撃者のドメイン名を自分の機械の 127.0.0.1 へ向け直す手口）や、LAN 内の別端末から機械の IP を指定した呼び出しで、あなたのキーが使われないようにするためです。スマートフォンなど LAN の別端末から `http://192.168.1.10:3000` のように機械の IP で開くときや、`http://mymac.local:3000` のような別名で開くときは、そのホスト名を `AI_ASSIST_ALLOWED_HOSTS` にカンマ区切りで足し（例: `AI_ASSIST_ALLOWED_HOSTS=192.168.1.10,mymac.local`。前後の空白は無視し、空白だけは未設定とみなします）、開発サーバーを起動し直してください。足さないまま開くと、ダイアログは送信先を確かめられず、`forbidden` の文言「このアドレス（ホスト名）からの AI 支援の呼び出しは許可されていません。…」を出します（`GET /api/ai-assist/status` が 403 `forbidden` を返すため）。足したホストは、同じ LAN の誰でもそのホスト名で呼べるようになる点に注意してください。

**モデルを上書きするときの条件**: このアプリは構造化出力と思考の量の指定を必ず送るため、それを受け付けるモデルだけが使えます。

- Claude: Messages API の `output_config.format`（`type: "json_schema"` の JSON スキーマ）と `output_config.effort`（`"low"`）を受け付けるモデル。
- OpenAI: Responses API の `text.format`（`type: "json_schema"`・`strict: true`）と `reasoning.effort`（`"low"`）を受け付けるモデル（推論モデル）。

受け付けないモデルや存在しないモデル ID を指定すると、提供元が要求を拒み、画面には `upstream-error`（「AI の呼び出しに失敗しました。…」）が出ます。モデルが受け付けるオプションは、各社の公式ドキュメントのモデルの説明で確かめてください。

## 5. 止め方

`.env.local` から `ANTHROPIC_API_KEY`・`OPENAI_API_KEY` の値を消し（行ごと消すか、`=` の後を空にする）、開発サーバーを起動し直します。シェルで `export` している場合は `unset` も行います。以後、AI 支援のダイアログは「AI 支援が設定されていません」を出すだけになり、外部へは何も送りません。キーそのものを使わなくなるなら、提供元のコンソールでキーを無効にしてください。

## 6. 誤りの種類ごとの原因と対処

画面の誤りの文言と、サーバーが返す code の対応です（`docs/specifications/api.md` の 20.3）。

| 種類 | 主な原因 | 対処 |
|------|----------|------|
| `not-configured` | キーが無い。`AI_ASSIST_PROVIDER` の値が不正、または指定した提供元のキーが無い | 「3」「4」の手順でキーと `AI_ASSIST_PROVIDER` を確かめ、開発サーバーを起動し直す |
| `auth-failed` | 提供元がキーを拒否した（値の誤り・無効にしたキー・権限不足） | キーの値（前後の余分な文字が無いか）と、提供元のコンソールでキーが有効かを確かめる |
| `rate-limited` | 短時間の送りすぎか、契約の利用上限（提供元によっては残高の不足）の可能性がある。どちらかは画面からは区別できない | 時間をおいて再度試す。続くときは提供元のコンソールで利用状況と上限・残高を確かめる |
| `timeout` | 120 秒（サーバー）または 150 秒（ブラウザ）で応答が無い | 小さい枝を選ぶか、時間をおいて再度試す |
| `refused` | モデルが内容を理由に応答を断った | 枝の内容を確かめて再度試す。別のモデルへの自動の切り替えはしない |
| `invalid-output` | 応答が JSON でない・形が違う・要約が空や上限超過・出力の上限で切れた | もう一度試す。続くときはモデルの上書きをやめて既定のモデルに戻す |
| `forbidden`（「このアドレス（ホスト名）からの AI 支援の呼び出しは許可されていません。…」） | 許可していないホスト名（`Host`）での呼び出し、別のサイトからの呼び出し、または `Content-Type` が `application/json` でない呼び出しとして拒否した | `localhost` 以外（LAN の IP・別名）で開いているなら、そのホスト名を `AI_ASSIST_ALLOWED_HOSTS` に足す（「4」）。アプリのページを開き直して再度試す。別のサイトや拡張機能から呼んでいないかを確かめる |
| `too-large` / `invalid-request` | 本文が 256 KB を超えた、または送る内容の形が正しくない | 小さい枝を選ぶ。ページを開き直して再度試す |
| `upstream-error` | モデル ID の誤り・受け付けないオプション・提供元の障害（5xx）・接続の失敗・想定外の例外 | モデルの上書きを確かめる（「4」）。時間をおいて再度試す。サーバーのログの `[ai-assist] provider=… kind=… status=…` で HTTP ステータスを確かめる |
| `network` | ブラウザからこのアプリのサーバーへの通信が失敗した | 開発サーバーが動いているか、接続を確かめる |

サーバーのログ（`[ai-assist] provider=… kind=… status=…`）には、提供元・誤りの種類・HTTP ステータスだけを出し、キー・プロンプト・応答の本文は出しません。

## 7. 課金の目安

どちらの提供元も従量課金です。1 回の「送信して提案を作る」で 1 回の要求を送ります（自動の再試行はしません）。

| 課題 | 送る量の上限 | 出力の上限（`maxOutputTokens`。思考・推論のトークンを含む） |
|------|--------------|------------------------------------------------------------|
| 枝の要約 | 200 ノード・ラベルとメモの抜粋の合計 40,000 文字 | 4,000 トークン |
| 重要度の提案 | 100 ノード・ラベルとメモの抜粋の合計 40,000 文字 | 12,000 トークン |
| 子の候補（078） | 80 ノード・ラベルとメモの抜粋の合計 40,000 文字 | 8,000 トークン |
| 分類・並べ替え（079） | 100 ノード・同上 | 12,000 トークン |
| 重複・類似（080） | 120 ノード・同上 | 12,000 トークン |
| 不足観点（081） | 80 ノード・同上 | 8,000 トークン |

- 入力には、送る枝の内容のほかに、システムプロンプトと課題の説明が加わります。日本語は 1 文字あたり 1〜1.5 トークン程度として見積もってください。
- 実際の出力トークン数と所要時間は **実 API 未確認** です（実装の時点でキーが無かったため、公式ドキュメントと SDK の型定義で確かめました）。手動テスト（`docs/testing/browser-test-cases.md` の AL 節）で測ったら、ここに記録してください。
- 料金（入力・出力のトークンあたりの単価）は、各社の公式サイトの料金ページで、使うモデルのものを確かめてください。
- 生成中に「取り消し」やダイアログを閉じても、提供元ではすでに送った要求の処理が続き、課金されることがあります。

## 8. 公開時の注意

`/api/ai-assist/*` には **認証もレート制限もありません**（イラスト生成の API と同じく、ローカルで使う前提です）。`ANTHROPIC_API_KEY`・`OPENAI_API_KEY` を設定したまま、インターネット上の公開 URL へデプロイしないでください。誰でもあなたのキーで AI を呼べてしまい、費用が発生します。送信元の確認（`Host` の許可リスト・`Origin`・`Sec-Fetch-Site`・`Content-Type`）はブラウザからの別サイトの呼び出しや DNS rebinding を拒むだけで、許可したホスト名を名乗る直接の呼び出しは止めません。公開する場合は、先に認証とレート制限（利用者ごとの回数・費用の上限）を入れてください。詳しくは `SECURITY.md` と `docs/specifications/api.md` の 20.6 を見てください。
