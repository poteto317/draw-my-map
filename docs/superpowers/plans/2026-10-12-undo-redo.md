# Undo／Redo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: `superpowers:subagent-driven-development`。AGENTS.mdに従い、タスクを1つずつ新しい実装サブエージェントへ渡す。各タスクを別エージェントで仕様適合・コード品質の二段階レビューに通し、指摘解消後に次へ進む。インライン実装はユーザーの明示指示がある場合のみ。

**Goal:** ノードの編集を最大100操作まで元に戻し、やり直せるようにする。

**Architecture:** `NodeMapState`の不変スナップショットを純粋な履歴遷移で管理し、同期refを持つhookを`useNodeLayoutState`に組み込む。Pixiドラッグを明示的なグループにし、既存の保存・復元と、履歴復元時に失効させるUI／非同期処理を配線する。

**Tech Stack:** 既存Next.js 16 / React 19 / TypeScript / PixiJS 8 / Jest / Testing Library。新規依存なし。

**Spec:** `docs/superpowers/specs/2026-10-12-undo-redo-design.md`

**今回の成果物:** 設計書とこのプランのみ。チェックボックスは将来の実装時に使用し、今回は実装・コミット・pushしない。

## Global Constraints

- 履歴はメモリ内のみ。最大100操作を戻せる。JSON／localStorageのV3形式は変更しない。
- 復元対象は `NodeMapState` 全体。座標・親子関係・ラベル・重要度・イラスト・寸法・配置モードを含む。
- パン・ズーム・フォーカス・選択・表示フィルター・生成プレビューは履歴に含めない。
- 成功したUndo／Redoでは選択を解除し、編集中の状態・ジェスチャー・メニュー・生成結果を失効させる。viewportと表示フィルター設定は維持する。
- 履歴に影響する状態遷移は同期refとReact stateに一体で反映し、同一イベント内の連続操作にも対応する。
- 既存の保存・画像出力・イラストAPIの形式と、操作が失敗した場合にマップを保つ契約を維持する。
- 実装は `.worktrees/codex/phase8-undo-redo` の `codex/phase8-undo-redo` ブランチで行い、タスクを順番にサブエージェントへ渡す。仕様・品質レビューを通してから次へ進む。
- 各実装タスクでTDDを行い、client変更後は `cd client && npm run verify` を成功させる。最後にROADMAP.mdを更新する。明示依頼なしにpush・PR作成・マージはしない。

## Review Focus

1. ドラッグ中にUndo・読み込み・ピンチが入り、遅い終了通知が来ても過去の状態を再確定しない（Task 1〜3）。
2. ノードID／ラベルがUndo→Redoで同じ値に戻っても、以前の画像生成結果を復活させない（Task 4）。
3. 空履歴・同値更新・失敗した接続／読み込みはRedoと選択を破壊しない（Task 1・2・5）。
4. 入力中のCtrl+Zとblur後のボタンクリックで、ネイティブ編集とマップ履歴を混同しない（Task 5）。
5. 同じイベントで追加→削除→Undoしても最新状態を使い、復元後の自動保存を旧タイマーが上書きしない（Task 2・5）。

expect(undoMapHistory(h).present).toEqual(a);
expect(redoMapHistory(undoMapHistory(h)).present).toEqual(b);
