# Phase 15 候補004 アウトライン表示・編集 設計

日付: 2026-11-03

## 目的と判断の位置づけ

同じマップをキャンバスと階層的な文章で切り替えて編集する。文章で内容と構成を整理した結果が、そのままマップへ反映されることを成功条件とする。対象は ROADMAP.md の候補004。候補005「Markdown・箇条書きへの書き出し」は含めない。

以下の方式・操作範囲・既定値は、featureフローで委ねられた設計判断としてエージェントが選ぶ。ユーザーが個別に指定・承認した仕様とは扱わない。実装前に独立した設計レビューを行う。

## 現状の契約

- 正本は `useNodes` → `useNodeLayoutState` → `useMapHistory` の `nodes` と `layoutMode`。選択は `useNodes.selectedNodeId`。`MapEditor` が1マップに1つ所有し、マップ切り替え時にkeyで再マウントされる。
- `Node` は `id / parentId / x / y / width / height / label / importance / illustration?` を持つ。親子は `parentId`、同じ親の兄弟とルートの順序は正本配列での出現順。配列全体が深さ優先順である保証はない。
- キャンバスは `useMapDisplayState` による折りたたみ・重要度解像度の部分表示と表示用配置を使う。正本の部分配列や表示用座標を保存してはいけない。
- `addChildNode` は子の末尾、`addSiblingNode` は同じ親の兄弟の末尾へ追加し、成功時だけ新IDを選択して返す。失敗はnull。兄弟直後挿入ではない。
- `insertForest` は配置失敗も含む結果を返し、成功時だけ最初の新ルートを選択する。`addNode(x,y)` は自動配置失敗の結果を返せないため、新しいアウトラインのルート追加には使用しない。
- `reorderSibling` / `changeNodeIndent` / `deleteNodeOnly` はIDと表示ID集合を受け、最新の正本に1回の構造変更を適用する。構造変更はmanualなら既存の座標移動、autoなら全体自動配置を伴う。失敗は正本・履歴・選択を変更しない。
- `deleteNodeOnly` は当該ノードのみ削除して子を昇格させる。`deleteNode` は枝全体を削除する別操作。今回の削除には前者を使う。
- 成功したUndo/Redoと全置換で `documentRevision` が進み、選択が外れる。通常編集では進まない。全置換では履歴も初期化される。
- 自動保存は正本のsnapshotを `useMapPersistence` 経由で保存する。保存失敗時の通知・flush・保護モードへの移行は既存シェルとストレージセッションが担う。

## 検討した方式

1. **キャンバスとアウトラインの表示切り替え（採用）**。同じ正本と選択を使い、中央領域だけを置き換える。現在の右イラストパネルを保ち、3ペイン化せず文章の幅を確保できる。表示切り替え時にキャンバスを再マウントするため、以前のパン・ズーム位置は引き継がない。
2. **左アウトライン＋キャンバス＋右パネルの同時表示**。常時比較できるが、狭い画面で文章幅が不足し、非表示ノード選択をキャンバス側が解除する既存処理との調停も必要。候補004に対して負担が大きい。
3. **全文テキスト編集後に再取り込み**。見た目は文章エディタだが、ラベルと階層からの再構築ではID・座標・重要度・イラスト・履歴を維持しづらい。正本へのID指定の操作で実現する今回の目的に合わない。

## 含む操作と含まない操作

含む: 全ノードの階層表示、選択、ラベル編集、ルート追加、子の末尾追加、兄弟の末尾追加、兄弟の1つ上/下への移動、階層を下げる/上げる、ノードだけ削除、既存のUndo/Redo・自動保存との連動。

含まない: 全文の一括編集/再パース、Markdown表示/書き出し、文章の貼り付けによる一括挿入、複数選択、DnD、アウトライン独自の折りたたみ・フィルタ・検索、枝全体削除、途中の親挿入、別マップへの移動、新しい保存形式、新しい依存ライブラリ、スマートフォン専用UI。これらの既存キャンバス操作はキャンバスに戻して利用できる。

## 画面と配置

- `MapEditor` に表示モード `map | outline` を持ち、初期値は `map`。ヘッダーに「マップ」「アウトライン」の2つの表示切り替えボタンを置く。選択中を `aria-pressed` で示す。表示モードは保存データ・Undo対象に含めない。
- 中央領域は一方のみマウントする。アウトライン時は `MapStage` をアンマウントし、そのwindowリスナー・clipboard・コンテキストメニュー・ジェスチャーを残さない。非表示キャンバスの `useHiddenNodeInteractionReset` がアウトラインの選択を消すことも防ぐ。
- `AppWorkspace` の右側は既存 `IllustrationPanel` を共用する。アウトラインの選択でも同じ対象が表示され、生成・設定・削除は従来どおり。アウトライン行自体には画像を展開しない。
- アウトライン中央の上に操作ツールバー、下に独立して縦スクロールする文章一覧を置く。ツールバーは幅に応じて折り返し、一覧領域には `min-w-0 / min-h-0` を与える。
- アウトライン時の共通ヘッダーにはマップ管理・表示切り替え・配置方式・重要度・Undo/Redo・JSON入出力・画像出力・箇条書き取り込みと既存通知を残す。キャンバス向け検索・解像度・折りたたみ・構造操作・枝移動・枝複製・clipboard説明は表示しない。アウトライン操作は中央ツールバーに集め、表示範囲の異なる操作を混在させない。
- 一覧の説明に「折りたたみや表示の細かさに関係なく、すべてのノードを表示します。兄弟追加は末尾に追加します。」を示す。空のマップは「ノードがありません」とルート追加を示す。

## 階層表示モデル

`nodes` から表示専用の平坦な先行順一覧 `{ nodeId, depth }` を導出する。ルートを配列順に巡回し、それぞれの子も元配列順に巡回する。深さのルートは1。同じラベル・空ラベルでもIDで別行として扱う。ラベルの空表示には既存 `getNodeDisplayLabel` を使い、生ラベルは正本へそのまま保持する。

親→子ID配列とID→ノードの索引を一度作り、明示スタックで巡回する。各行で全配列をfilterしたり、再帰コンポーネントを深さ分積んだりしない。導出はO(n)時間・O(n)領域。スタックに子を逆順に積むことで兄弟順を保つ。表示一覧を正本配列へ書き戻さない。

折りたたみ・重要度・検索条件は一切入力に使わず、構造APIへ渡すID集合も全 `nodes` のIDとする。この全件表示はアウトラインだけの契約であり、キャンバスの各操作には従来の `displayState.visibleNodeIds` を渡し続ける。

平坦なネイティブのリストを使い、階層は字下げと読み上げ用の「階層N」で伝える。独自ARIA treeは実装しない。行の選択ボタンには選択状態と「階層N・ラベル」を示す名前を与える。字下げ量は深さ12までで上限を設け、超過時も実際の深さを行に表示する。長いラベルは折り返し、他の行を横に押し出さない。

正しい永続データは既存codecにより検証されている。表示導出もvisitedで循環を止める。万一到達できないノードがあれば末尾に深さ1の行として一度ずつ表示して構造不正の通知を出し、構造操作を無効化する。自動修復・削除・親の付け替えを保存しない。重複IDも異常として検出し、別ノードへ誤更新しないため編集を無効化する。

## 操作の契約

| 入口 | 正本への操作 | 成功後 |
| --- | --- | --- |
| ルート追加 | `insertForest([{ label: "", parentIndex: null }], { kind: "root" })` | 既存の森追加の配置で末尾に1ルート。返ったrootIdを編集 |
| 子を追加 | `addChildNode(selectedId)` | 子の末尾を選択・編集 |
| 兄弟を末尾に追加 | `addSiblingNode(selectedId)` | 同じ親の末尾を選択・編集。ルートでも可 |
| ラベル編集 | `updateNodeLabel(id, rawLabel)` | 同じ行の選択を維持 |
| 1つ上/1つ下 | `reorderSibling(id, { kind: "step", direction }, allNodeIds)` | 枝全体が兄弟の間を移動。対象IDの選択を維持 |
| 階層を下げる | `changeNodeIndent(id, "indent", allNodeIds)` | 直前の兄弟の末尾の子にする。選択を維持 |
| 階層を上げる | `changeNodeIndent(id, "outdent", allNodeIds)` | 元の親の直後の兄弟にする。選択を維持 |
| ノードだけ削除 | `deleteNodeOnly(id, allNodeIds)` | 子孫を保持して昇格。選択は既存APIどおりnull |

構造操作の座標と兄弟順は既存ドメインの契約を採用し、アウトラインの見た目に合わせた別の並べ替え・再配置はしない。manualでも構造操作は座標を変更しうる。ラベル変更・選択・表示切り替えだけで座標は変えない。

可否は既存の `getSiblingReorderAvailability / getNodeIndentAvailability / canDeleteNodeOnly` を全ID集合で計算する。選択が無いときはルート追加以外をdisabledにする。端の移動、先頭の階層下げ、ルートの階層上げもdisabled。実行時にも戻り値を確認し、配置失敗・対象消滅は既存の日本語formatterによる通知を既存の構造操作通知枠へ出す。新規追加のnull/失敗でも編集欄を開いたり選択を変えたりしない。

削除はツールバーの明示的な「ノードだけ削除」ボタンで実行し、子孫を残す旨を説明する。Delete/Backspaceへ割り当てず、追加の確認モーダルも作らない。失敗時の選択と履歴は維持する。成功後は削除ボタンが無効になるため、一覧の残った先頭行へフォーカスのみを戻す（選択はnullのまま）。一覧が空ならルート追加へ戻す。

## 選択・表示切り替え

- 独立したアウトライン用の選択状態は作らず、行クリック/キーボード選択から `selectNode(id)` を呼ぶ。イラストと重要度の対象も同一IDになる。
- アウトラインを開くと選択行を一覧内へスクロールする。切り替えボタンのフォーカスを勝手に奪わず、Tabで一覧へ入ると選択行（選択なしなら先頭行）へ到達する。
- 行はroving tabIndexで一覧へのTab入口を1つにする。未選択時のフォーカス行IDはUI状態として持てるが、正本の選択とは区別する。
- キャンバスへ戻すとき、有効な選択があれば祖先の折りたたみを展開し、必要な重要度レベルを表示する。`resolveNodeSearchReveal` の既存純粋関数を再利用し、検索専用の文言は使わず「選択したノードを表示するため…」と通知する。フォーカス要求は `useRevisionScopedNodeRequest` の契約で発行する。
- 再マウントしたキャンバスは初期viewportから始まり、選択があればそのノードへ移動する。パン・ズーム位置の復元は今回含めない。`viewportScale` も切り替え時にINITIAL_VIEWPORT.scaleへ揃え、前の縮尺で自動解像度を判定しない。必要レベルの決定にもこの縮尺から導出した表示ID集合を使う。
- マップ切り替えは既存の再マウントで表示モード・編集draft・フォーカスを初期化する。同じマップへのJSON全置換は表示モードを保ち、revision変化で編集中draft/フォーカス要求を無効化する。

## ラベル編集とキー操作

一度に1行だけ編集する。行のダブルクリック、行上のEnter/F2、またはツールバーの「ラベル編集」で開始する。表示は通常テキスト、編集はtextareaとし、既存ラベルに含まれる改行・タブ・前後空白を失わない。HTML/Markdownとして解釈しない。新規追加成功時は空文字で編集を開始する。

draftには `{ nodeId, documentRevision, originalLabel, text }` を持たせる。確定は同じrevisionで対象が存在し、正本のラベルがoriginalLabelのままのときだけ `updateNodeLabel` を1度呼ぶ。古いdraftによる別データ/別編集への上書きを防ぎ、無効なら破棄して通知する。正本へ入力の1文字ごとに書かない。変更なしなら更新を呼ばない。

- textareaのEnterで確定、Shift+Enterで改行、Escapeでキャンセル、blurで確定。確定/キャンセルを同期的な処理済みガードで一元化し、Enter後のblurやEscape後のアンマウントで二重保存しない。
- IME中のEnter/Escapeは `nativeEvent.isComposing` と `keyCode === 229` のどちらでも処理しない。キーrepeatによる確定・編集の再開始・追加を行わない。IMEの通常文字操作を妨げない。
- textareaではCtrl/Cmd+Zはブラウザの文字入力Undoへ任せる。Tab/Shift+Tabはフォーカス移動であり階層変更には使わない。構造変更はボタンをキーボード操作して行う。
- 行選択ボタン上の↑/↓で先行順の前後行へフォーカス・選択、Home/Endで先頭/末尾へ移動する。textareaやツールバーボタンのキーは横取りしない。Enter/Spaceの標準ボタン操作とF2による編集を二重処理しない。
- 確定/キャンセル後は当該行にフォーカスを戻す。blurが別のボタンを押した結果なら戻さず、そのボタン操作を続行する。行切り替えでは前行のblur確定後に次行を選択する。
- プログラムからのUndo/Redoや全置換が先に成功してrevisionが変わった場合、または対象が消滅した場合はdraftのrevision/存在を無効とし、後着blurを無視する。入力外のUndo/Redoは既存 `useMapHistoryShortcuts` を1つだけ利用する。

表示切り替えなど通常のボタンクリックでは先行するblur確定を採用する。ヘッダーのUndo/Redoも同じで、textareaのblurによるラベル確定の後にclickの履歴操作を行う。変更されたラベルを確定してUndoを押した場合は、そのラベル確定だけを1回戻す。Redoを押した場合、先行する新しいラベル確定によってRedo枝が消えればRedoは実行できず、新ラベルを維持する。ラベルが変更されていなければ新しい履歴を積まず、既存のUndo/Redoを実行する。pointerdownでdraftを先にキャンセルする特別処理は加えない。

この通常クリックの順序と、revision変更がblurより先に起こった場合のdraft破棄を区別する。DOMをプログラムで外した際のblur発火には依存せず、全置換・セッション終了ではdraftを無効化する。アウトラインdraftの寿命を越える非同期確定処理や独自debounceは作らない。

## 履歴・保存・セッションと操作制限

ラベル確定1回、追加1回、兄弟移動1回、階層変更1回、削除1回がそれぞれ既存履歴の1単位。追加直後のラベル入力確定は別単位とする（既存のキャンバス追加と同じ）。失敗、選択移動、表示モード、フォーカス、draft入力には履歴を増やさない。正本への構造変更を複数のuseNodes呼び出しに分解しない。

`useMapPersistence` はモードと関係なく常時マウントした同じ1つを使い、全件の正本を渡す。保存失敗でもメモリ上の編集を維持し、既存の失敗通知とJSON書き出しによる救出を残す。「編集確定」と「保存成功」を同じ成功通知にしない。ローカルストレージへ直接書かず、独自の保存済み表示も作らない。既存セッションの競合・保護モード・flushをバイパスしない。

| 状態 | アウトライン行/編集/ツールバー | 共通ヘッダー/履歴 | キャンバス |
| --- | --- | --- | --- |
| 通常map | 未マウント | 従来どおり | 従来どおり |
| 通常outline | 有効 | outline用構成 | 未マウント |
| 取り込み/枝移動/外側ダイアログ中 | 既存editor根のinertで操作不可 | 既存editorShortcutsEnabled=false | 未マウント、または従来の停止 |
| 保護モード/別マップ | editor自体の既存寿命に従い終了 | 既存シェルへ委譲 | 同左 |

アウトラインに別のwindowショートカットを増やさない。新しいpropsは本番呼び出し元に必須にし、enabled、revision、全ID集合、正本nodesの配線漏れを許さない。

## 責務と変更の境界

- 表示用ドメイン: 全件の先行順行・深さ・構造異常の導出のみ。Nodeを変更しない。
- アウトラインUI: リスト/ツールバー/textarea/局所キー操作/フォーカス。キャンバス固有のviewport、Pixi、保存APIへ依存しない。
- アウトライン操作フック: 新規追加の結果処理、編集draftの寿命、選択/フォーカス要求を集約。既存兄弟・階層操作フックとformatterを再利用できる部分は再利用する。
- `MapEditor`: モード、既存正本と通知への配線、キャンバスを戻す際のreveal、共通ヘッダー構成。既存構造ドメインや履歴を二重実装しない。
- イラスト生成は既存のID・revision・元ラベル検証を保つ。アウトラインからのラベル変更でも古い生成結果が新ラベルに適用されない既存契約を崩さない。

ファイル名やフックの分割の細部は計画者が決定できる。新しい汎用エディタ基盤、状態管理ライブラリ、データ形式変更は不要。

## 大きなマップ・深いマップ

アウトラインは全ノードを表示し、新しい件数/深さ制限を正本に課さない。10,000件の幅広い森と10,000段の鎖を表示導出のテストに使い、再帰overflow・二乗探索がないことを確認する。初回は平坦DOMの全行表示とし、仮想化やページ分割は導入しない。スクロールは一覧内、選択行のscrollIntoViewは選択/要求の変化時だけ。毎レンダー全行をスクロールしたりフォーカスしない。

10,000DOM行の操作感はブラウザで確認する。もし実用上の問題が出た場合は計画のscopeを再評価するが、黙って表示件数を切り捨てない。既存manual配置や自動配置が深木/座標境界で追加・構造変更を拒否する場合は既存の失敗契約に従い、アウトラインが独自に制限回避しない。

## 検証と受け入れ条件

TDDで対応テストのREDから進める。少なくとも次を計画に含める。

1. 表示導出: 配列が先行順でない森、兄弟と根の順序、同名/空ラベル、深木・幅広い森、孤立/循環/重複IDで停止し正本を変更しない。
2. 組み立ての結合: 実 `useNodes` とアウトラインUIで、mapで作った親子がoutlineに現れ、ラベル・兄弟順・階層の変更がmapへ戻して反映される。ID/重要度/イラスト/親子関係/未変更フィールドの保持を比較する。
3. 非表示データ: キャンバスで折りたたみ/重要度フィルタを設定してからoutlineへ移り、全ノードを表示・編集できる。構造APIは全件ID集合、mapへ戻したAPIは従来の表示ID集合を受け取る。
4. 追加/削除: 空マップからのルート、子・兄弟の末尾追加、成功後の編集、失敗時の正本/履歴/選択維持。ノードだけ削除で子孫のデータを保持する。
5. 編集: 生の空白/改行の保持、変更なし、Enter/blur一重確定、Escape後blur、isComposingと229それぞれのEnter/Escape、repeat、textareaの文字Undo、ボタン操作を横取りしない。
6. 寿命: draft中にプログラムからUndo/Redoを先に成功させた場合、同じIDを持つJSON全置換、対象削除、別マップ、外側ダイアログ、保護モードの遷移で古いdraftや後着イベントが新しい正本へ書かれない。Undo/Redoが成功してrevisionが進んだケースと、履歴が無くrevisionも変わらないケースを区別する。
