# Phase 34 タスクと属性管理

対象はカード39（project 5、内部ID 137）、ロードマップ候補085〜087。利用者は、作業を表すノードだけに完了状態・期限・担当者を持たせ、枝の親を見て残件を把握できる。用途ごとの情報は、個々のノードに名前を付けて記録する。

## 方式の比較と選定

マップ共通の属性定義を設ける方式では、複数ノードの列をそろえられるが、枝を別マップへ移す際に定義の移植と名前の衝突解決が必要になる。今回は既存の出典やタグと同じく、**ノードが自分の属性定義と値を持つ方式**を採る。独立したノード間では、同じ名前に異なる型を使える。ユーザーアカウント、通知、共有スキーマ、横断検索・フィルターの追加、AIへの入力拡張は対象外とする。新規依存を追加しない。

進捗は子孫の変更や移動で変わる。親に集計値を保存すると別タブ、Undo、部分木の挿入ごとに更新が必要になるため、正本の親子関係から導出し、キャンバスとアウトラインで共有する。

## 保存する値と検証

既存の MapDocument V3 に次の任意キーを足す。入力中だけの未完成値はフォームが保持する。保存済みの値と配列は読み取り専用として扱う。

| キー | 保存内容 |
| --- | --- |
| `task` | `{ completed: boolean, dueDate?: string, assignee?: string }`。タスク化した直後は `{ completed: false }`。期限・担当者は単独で省略可能。解除するとキーごと外れる。 |
| `customAttributes` | ノード当たり最大10件の順序付き配列。各要素は `{ name, type: "number", value: number }`、`{ name, type: "date", value: string }`、`{ name, type: "choice", options: readonly string[], value: string }` のいずれか。値は必須。最終属性を削除するとキーごと外れる。 |

- 属性名、選択肢名、担当者の表示名には既存の `normalizeNodeTagName` の表記規則を使う。生入力は各256 UTF-16コード単位以内に制限し、空白整理後は30単位以内。UI・ドメイン・V3読込で同じ定数、同じ `string.length` を使う（絵文字「😀」は2）。担当者の空欄は未設定。属性名・選択肢名の空欄はエラー。名前・候補を識別する鍵には `nodeTagKey` を使い、表示には正規化後の元の表記を残す。同一ノードの同名属性、同一属性内の同名候補を拒否する。既存項目の改名は自分自身を重複判定から除く。
- 選択肢は1〜10件、順序を保つ。登録する `value` は候補の表示名のいずれかと一致させる。編集画面で選択中の候補を削除・改名して無効になれば未選択に戻し、利用者が選び直してから候補と値をまとめて保存する。最初の候補への自動変更は行わない。
- 日付は西暦0001〜9999年の実在するグレゴリオ暦日。ASCII `YYYY-MM-DD` の固定長で保持し、年月日の範囲と閏年を検証する。2024-02-29は有効、2023-02-29・0000-01-01・日時付き文字列は無効。時刻・タイムゾーンへの変換は行わない。
- 数値は符号付き十進数として入力する。整数、小数、指数表記を認め、前後の空白を除いた空欄・16進数・途中までしか数値に読めない入力を拒否する。変換後に `Number.isFinite` を検査し、非ゼロの仮数がアンダーフローして0になる入力も拒否する。0、負数は有効、負のゼロは0に正規化。JSON読込では有限な number を要求し文字列を変換しない。精度は既存のJavaScript numberに従う。
- `normalizeMapDocumentNode` は V1/V2 の両キーを無視する。V3では未指定を許し、空の属性配列は欠落へ正規化。構造化した要素の未知キー、異なる型の値、上限超過、重複、非候補の値はノード位置・フィールドを示して文書全体を拒否する。taskのbooleanは必須。V3では `task` / `customAttributes` の JSON `null` はキー省略と同義に正規化する（実装・`mapDocumentNode.test.ts` と一致）。配列件数・各生文字列長を先に検証する。キーの付け外し・正規化結果の投影は更新、統合、`projectMapDocumentNode` で共通にする。旧データの再保存時に空の新キーを生成しない。

## 操作別の伝搬

| 入口 | 取り扱い |
| --- | --- |
| 初期ノード、ルート・子・兄弟の追加、親の挿入、新規テンプレート・テキスト取り込み・AIによる新規提案 | 作成直後は両キーとも欠落。親を挿入しても元の子の属性を移さない。 |
| ノードの分割 | 最初の断片（元ID）のみに両属性を残す。新しい断片はタスクにならず、属性を複製しない。 |
| ノードの統合 | `task` は主選択を優先し、無ければ吸収側の元ノード配列順で最初のタスクを丸ごと継承する。複数タスクから期限と担当者を合成しない。カスタム属性は主選択の属性順、続けて吸収側の配列順で名前の鍵ごとに最初の1件を採用。型・値・候補が異なる同名属性でも先の定義を保持する。異名の属性が合計10件を超える場合は統合を拒否して元データを保つ。 |
| ノードだけ削除・枝削除、接続先変更、並べ替え・配置、ロック・折りたたみ、他属性の編集、AIによる既存ノードの更新 | 削除対象とともにその値を削除する。残るノードは両属性を保持する。親子関係やタスクが変化したら表示を再集計する。 |
| 枝複製・クリップボード・部品保存/再挿入・別マップへの枝抽出/移動/取り込み | 通常のノードID再割当てを適用し、両属性と候補順を保持。クリップボード・部品は既存の V3 ノード検証を通る。複製後の編集で元の属性配列・候補配列を書き換えない。 |
| 自動保存、JSON入出力、ライブラリ複製・一括バックアップ/復元・ごみ箱復元 | 既存の V3 正規化・エンコード・投影を経由して両属性を往復。全体の検証に成功してから置換する。 |
| Undo/Redo・別タブ競合・統合のプレビュー再検証 | `domain/history/mapHistory.ts`、`domain/mapLibrary/mapConflict.ts` のノード比較に、taskの全フィールドと順序付き属性配列の構造比較を共有。型、名前、値、選択肢順を比較し、同内容の別参照は等価。属性のみの変更も取り消し・競合の対象。 |
| アウトライン書き出し、CSV/TSV、OPML、画像・PDF・印刷、検索・AI向けの投影 | 既存の各形式が扱う項目を出力する。タスク・担当者・カスタム値と派生バッジはこれらの出力へ含めない。全属性を引き渡す形式はマップJSON・バックアップ・枝/部品。 |

`NODE_ATTRIBUTE_POLICY` に両キーの分割 `original-only`、親挿入 `none`、統合の task `survivor-else-first`、属性 `union` を登録する。既存の全キー契約テストの `SAMPLE`・`DIFFERENT` を更新する。

統合の `NodeMergePlan` に採用したタスクと元ID、残る属性一覧、破棄するタスク件数、同名属性のうち内容が同じ重複件数・異なるため捨てる件数を持たせる。`nodeMergePreview` と `NodeMergeDialog` は確定前に「どのタスク（完了状態・期限・担当者）が残り、他に何件のタスクが消えるか」「属性が何件残り、何件が重複し、何件が同名のため破棄されるか」を該当時だけ表示する。同名で値が異なる場合は該当属性名も示す。採用結果、元ID、表示する件数・名前、および主選択と吸収側すべてのノードIDに対応づけた元の task と customAttributes の構造値（破棄される値も含む）を `isSameNodeMergePlan` で再照合し、古いプレビューでの確定を防ぐ。履歴の確定は統合全体で1回。

## 編集パネルと履歴

`MapEditor → NodeDetailPanel` の独立した「タスク」「カスタム属性」節を使う。読み書きの対象は主選択の1ノード。対象、文書世代、更新関数を必須propsで渡す。

| 状態 | 2節の表示と操作 |
| --- | --- |
| マップでノードを1件選択／アウトラインの有効な主選択1件 | 両節を表示して編集可能。アウトラインは既存の `importanceTargetIds` の有効件数に従い、マップに残った副選択を数えない。 |
| マップで主選択と副選択がある、未選択、マップで関連線・グループを選択 | 両節を隠す。副選択へ書き込まない。アウトラインに戻った場合は同ビューで有効なノード選択を用いる。 |
| ノードの編集ロック・保護ストレージ・プレゼン再生 | 対象が1件なら保存値を読める。全変更操作を無効にし、確定ハンドラでも対象ID、世代、現在の可否を確認する。位置固定だけのノードは編集可。 |

タスク未設定時は「タスクにする」で未完了のタスクを作る。設定後は「完了」のチェック、期限（日付入力）、担当者（自由入力）をまとめて「保存」する。「タスクを解除」で期限・担当者も外し、Undoで復元できる。カスタム属性は一覧から1件ずつ追加・編集・削除する。種類は新規作成時に選択し、既存項目の型の変更は削除と再追加で行う。数値欄、日付欄、選択肢候補欄（1行1候補）と値の選択欄を型に応じて出す。候補欄は改行を区切りに使い、末尾の改行1つを許容する。空の中間行はエラーにする。保存は行の名前・候補・値を同時に反映する。改名は編集開始時の名前の鍵で対象を特定する。一覧から直接削除するハンドラは、表示時のノードID・文書世代・名前の鍵・属性の完全な構造値を渡し、確定直前の対象と照合する。値の変更や、削除後に同名属性が追加された場合（同値を含む）は、属性変更の世代も照合して拒否する。

各フォームは「保存」「キャンセル」を持つ。入力やblurでは履歴へ書かない。確定操作のたびに `useNodes` の最新状態と編集開始時の対象・元の値を照合し、検証後に `applyNonStructuralChange` で1回だけ反映する。タスク作成/解除、属性追加/編集/削除は各1手、同値・拒否は0手。失敗時は値と下書きを保ち、保存成功として扱わない。他の節の変更は最新ノードへ合成し、同じ対象の保存値が変わったら古い下書きで上書きしない。

選択変更・非表示・編集不可への遷移では下書きを破棄する。Undo/Redo、JSON読込、マップ切替など文書世代の更新時は同じ数値IDでも新しい保存値から表示する。`NodeSourcesSection` に倣い、節のkeyには対象IDを使い、同じ対象の世代変更では入力値と通知だけを更新してフォーカスを保つ。編集を開き直すと現在値が入る。入力欄には日本語ラベルを付け、失敗箇所を `aria-invalid` と説明で示す。対象切替・修正で古い通知を消し、同じ失敗の再送信も1回ずつ読めるようにする。入力中のIME確定・キーリピートで二重送信せず、削除後は残るコントロールへフォーカスする。

## 枝の集計と表示

正本の全 `nodes` を `indexNodeForest` に1回渡し、反復走査済みの `postOrder` で各ノードの部分木のタスク数・完了数を親へ加算する。親自身にタスクがあれば1件、子孫のタスクも1件ずつ。タスクが無い中間ノード、関連線、グループ所属、マップ間リンクは件数に加えない。表示対象は「直接の子を1件以上持ち、部分木のタスク数が正」の親。葉のタスクは上位の集計に入る。残件は総数−完了数、完了率は `Math.round(100 * 完了数 / 総数)`。全完了でも「100%・残り0件」を出す。未設定の枝には表示しない。例えば親が未完了、子が完了、タスクのない別の子に未完了の孫があれば、親は33%・残り2件。

複数ルートは独立する。重複ID・親不在・循環等でforestが無効なら空の集計を返し、既存の構造エラー表示に従う。正本のノード配列単位でメモ化したID→集計を両ビューへ渡す。走査は時間・空間とも O(n)、深い枝にも再帰を使わない。折りたたみ、深さ・解像度・フォーカス、ハイライト、画面外カリングはバッジを描く親の集合にだけ作用し、分母は変えない。

- **キャンバス**。既存の `renderMapNodes` の親コンテナに、表示専用の短い下段（例「33% 残2」）を加える。通常の100×60に収まる1行とし、背景と十分なコントラストを持たせる。左右は角のマーカー（半径6＋縁）と左の種別バーを避け、内側に各8ワールド単位を確保。下段の基準高は16、イラストがあれば既存のイラスト領域を上に除いた本文高の最大1/3とする。残りの上段にラベル・アイコン・下線を一組で中央配置し、長文で領域を越えるときだけ縦横比を保って縮小する。下段も件数の桁に合わせ内幅に収める。ラベル編集中は当該ノードの下段を一時的に隠し、既存の入力欄を使う。本文高や内幅を確保できない外部JSONの極小矩形では、読めない重なりを作らず、アウトラインの該当行で同じ値を表示する。作成する表示オブジェクトは描画対象の親のみ。フェード、強調の透過度、ドラッグ中の透過度は親に合わせる。バッジのクリック操作は追加しない。ノード矩形内に置くため保存座標、fit bounds、カリング、接続点・当たり判定を変更しない。
- **アウトライン**。`OutlineEditor` の行ボタンのラベル後に「33%・残り2件」の読取専用テキストを置き、狭い幅では次行へ折り返す。既存の明示的な `aria-label` にも「完了率33%、残り2件」を追加し、Tab移動先や行の選択操作を増やさない。Pixiで非表示になる極小ノードでも全文を読める。
- SVG・PNG・PDF/印刷は既存の画像用描画を使う。リンク印などの編集用表示と同じく進捗バッジは出力しない。画像出力でのラベル位置も既存の画像用レイアウトに従う。

## 実装単位と受け入れ

1. **データ契約と全伝搬**。更新・検証・投影・構造比較・統合プレビューを揃える。V1/V2、属性なしV3、全型の往復、境界値と上限+1、日付/有限数/絵文字/重複の拒否、構造操作と `NODE_ATTRIBUTE_POLICY` のテスト。別参照の同内容と1フィールドだけの変更を、履歴・競合の両方で検証する。クリップボード、部品、バックアップ復元を実際のcodecで通す。
2. **タスク編集と進捗表示**。未設定からの作成・保存・解除とUndo/Redo、フィルター内の孫・複数ルート・全完了・0件・深い枝・不正構造、ロック/保護/複数選択等の可否を検証。実物のMapEditorを介して子の完了を変更し、キャンバスとアウトラインで親の表示が連動することを確認する。画像あり・長いラベル・下線・アイコン・3種の角印の併用、狭い矩形・ラベル編集中の表示も確認する。
3. **カスタム属性編集**。全3種類について追加・値変更・削除とUndo、選択肢の削除/改名と再選択、エラー後の修正、入力中のノード切替・同じIDの文書置換・ロックと古いハンドラからの確定拒否を検証する。
4. **ロードマップ**。実装と検証結果を照合し、候補085〜087、Phase 34 の状態、「現在地」「最終更新」を更新する。全体の次の未完了候補は他Phaseも含めた既存の順序を尊重する。各実装は対応テストのREDから着手し、最終検証は `client` で `npm run verify` を実行する。
