# Phase 4 自動レイアウト設計

## 目的

ツリー構造を左から右へ自動整列し、親子関係を追いやすい配置を保つ。ノード同士の重なりを回避し、自動モード中はノード追加・削除・接続後に配置を再計算する。手動配置と自動配置はヘッダーから明示的に切り替える。

## スコープ

Phase 4の次の項目を実装する。

- ツリー構造に基づく自動レイアウトアルゴリズム
- ノード同士の重なりの検出と回避
- ノード追加・削除・接続時のレイアウト自動更新
- 手動配置と自動配置の切り替え

## ユーザー体験

### レイアウト方向

- 親ノードを左、子孫を右へ配置する。
- 同じ深さのノードは同じX列へ揃える。
- 兄弟の配列順と複数ルートの配列順は入力配列の順序を維持する。
- 複数ルートは左端を揃え、各ツリーを上から下へ並べる。

### 基準位置

- 最初のルートノードの現在の左上座標をアンカーとする。
- 自動モードへ切り替えても、最初のルートのX座標とY座標は変更しない。
- 他のノードはこのアンカーを基準に再配置する。
- ノードが0件のときは空配列を正常結果とする。自動モードで最初のルートを追加した場合は、その追加位置がアンカーになる。

### モード切り替え

- 初期モードは手動配置とする。
- ヘッダーに「手動配置」と「自動配置」の2ボタンを表示する。
- 選択中のボタンは見た目と`aria-pressed`の両方で識別できるようにする。
- 自動モードへ切り替えた直後にノード全体を整列する。
- 自動モード中はノードのドラッグ移動を無効化する。パン、ズーム、フォーカス、選択、ラベル編集は維持する。
- 手動モードへ戻しても現在の座標を維持し、自動整列前の座標には戻さない。
- モードはReact stateのみで管理し、再読み込み後の復元はPhase 5で検討する。

### 自動更新

自動モード中、次のツリー構造変更後に全ノードを再配置する。

- ルートノードの追加
- 子ノードの追加
- 兄弟ノードの追加
- ノードと子孫の削除
- 既存ノード同士の接続による親の変更

ラベル編集、選択、パン、ズーム、フォーカスでは再配置しない。ノードの幅と高さは現行仕様でラベルによって変化しない。

## 責務境界

### レイアウトドメイン

`client/src/domain/nodes/nodeAutoLayout.ts`に純粋関数を置く。

```ts
export function layoutNodeForest(
  nodes: readonly Node[],
): Node[] | null;
```

この関数は次だけを担当する。

- 入力のツリー整合性と数値の検証
- 親子索引、深さ、深さごとの最大幅の計算
- 部分木ごとの必要高さの計算
- 各ノードの座標計算
- 深さごとの配置区間を用いた重なり検出

React state、PixiJS、DOM、viewportには依存しない。

### レイアウトモード型

`client/src/types/nodeLayout.ts`に次を定義する。

```ts
export type NodeLayoutMode = "manual" | "auto";
```

ドメイン計算、Hook、UIが同じリテラル型を利用し、UIからHookの実装詳細はimportしない。

### `useNodes`

`useNodes`はノード状態に対するcommandとレイアウトモードを所有する。

```ts
layoutMode: NodeLayoutMode;
setLayoutMode: (mode: NodeLayoutMode) => void;
```

- `layoutModeRef`をstateと同期し、初回renderから保持したcommandも最新モードを参照する。
- ノード変更候補を作り、自動モードのときだけ`layoutNodeForest`へ渡す共通境界を用意する。
- 自動モードの更新は「ツリー変更候補の作成→レイアウト成功→RefとReact stateの同時更新」の順で行う。
- 自動レイアウトが`null`を返した場合は、ノード、選択、モードを変更しない。
- 子追加と兄弟追加は失敗時に`null`、接続は`false`を返す既存契約を維持する。
- ルート追加は既存の`number`戻り値契約を維持する。自動レイアウト失敗時は割り当て済みIDを欠番とし、ノード追加は反映しない。
- 自動モード中の`moveNode`はノード配列の参照を変更しない。
- ラベル更新と選択更新は自動レイアウトを起動しない。

### `AppHeader`

`AppHeader`は`layoutMode`と`onLayoutModeChange`をpropsで受け取り、モード選択UIと操作案内だけを表示する。

- 「手動配置」「自動配置」ボタンを同じグループへ置く。
- 各ボタンは`type="button"`と`aria-pressed`を持つ。
- 手動モードの案内にはノードドラッグを含める。
- 自動モードの案内には「追加・削除・接続時に自動整列」を含め、ノードドラッグを操作として案内しない。
- レイアウト計算やノードstateは持たない。

### `page.tsx`

`page.tsx`は`useNodes`の`layoutMode`と`setLayoutMode`を`AppHeader`へ渡す。`MapStage`へは引き続き`moveNode`を渡し、モードによる受け入れ判定は`useNodes`に集約する。

## レイアウトアルゴリズム

### 1. 入力検証と索引

2段階の線形走査で検証と索引を構築し、全体を`O(n)`に保つ。第1段階では各ノードを走査して、有限かつ重複しないID、有限の`x`、`y`、`width`、`height`、0より大きい`width`と`height`を検証し、`id -> node`を構築する。第2段階では各ノードの`parentId`が`null`または第1段階で得たIDに存在することを確認し、ルート配列と`parentId -> children`を構築する。

第2段階では、ルートと各子配列へ入力順に追加して並び順を保つ。各段階は入力を1回ずつ走査するため、親が子より後に現れる入力も受理しつつ、親存在確認と順序付き索引構築を線形時間で完了する。

### 2. 循環検出と深さ

ルートから非再帰で走査し、各ノードの深さを記録する。訪問済みIDへの再訪または走査後の未訪問ノードがあれば循環として`null`を返す。再帰呼び出しは使わず、深いツリーでcall stackを消費しない。

深さごとの最大幅を計算し、各列のX座標を次で決める。

```text
columnX[0] = firstRoot.x
columnX[d + 1] = columnX[d] + maxWidth[d] + horizontalGap
```

すべての加算結果を有限値検証する。

### 3. 部分木の必要高さ

非再帰のpost-order走査で各部分木の必要高さを計算する。

```text
childrenHeight = sum(childSpan) + verticalGap * (childCount - 1)
subtreeSpan = max(node.height, childrenHeight)
```

葉の`subtreeSpan`は`node.height`とする。加算、乗算、`max`の結果を有限値検証する。

### 4. 座標配置

各部分木に`top`と`subtreeSpan`の縦区間を割り当てる。

```text
node.y = top + (subtreeSpan - node.height) / 2
childrenTop = top + (subtreeSpan - childrenHeight) / 2
```

子部分木は`childrenTop`から入力順に並べる。最初のルートのY座標を保つため、最初のツリーの`top`を次で決める。

```text
firstTreeTop = firstRoot.y - (firstRootSpan - firstRoot.height) / 2
```

次のルートがある場合だけ、配置済みツリー内の実ノード下端の最大値を`checkedAdd(node.y, node.height)`で追跡する。この実下端に`treeVerticalGap`を`checkedAdd`して候補`top`を求め、候補`top`との実差分を共通gap判定で検証してから次のツリーを配置する。共通gap判定は`checkedSubtract(candidateTop, actualTreeBottom)`でoverflow、精度飽和、負の差分を拒否し、座標規模に応じたULP許容値を`treeVerticalGap * 1e-9`で絶対上限付きにして、意味のあるgap不足を拒否する。最後のルートでは次のツリーがないため、未使用の実下端・候補`top`・gapを計算しない。全ての使用する座標計算で有限値を検証する。

### 5. 重なり検出

深さが異なるノードは、深さごとの最大幅と`horizontalGap`で分離される。同じ深さのノードは、上から下への配置時に直前ノードの実下端を`checkedAdd(previous.y, previous.height)`で求め、`checkedSubtract(current.y, previousBottom)`で実gapを求める。下端計算または差分がoverflow・精度飽和・非有限となる場合、実gapが負の場合は`null`を返す。実gapと`verticalGap`の差は、座標規模に応じたULP許容値と`verticalGap * 1e-9`の絶対上限で判定し、その許容範囲を超える不足を不変条件違反として`null`を返す。

汎用的な全ペアの衝突探索は行わない。列と部分木区間の不変条件で検出・回避し、線形時間を維持する。

### 6. 出力

- 入力配列と入力ノードを変更しない。
- 有効な入力では新しい配列を返す。
- X座標またはY座標が変わるノードだけを複製する。
- 座標が変わらないノードは元のオブジェクト参照を維持する。
- `parentId`、`width`、`height`、`label`、入力順を維持する。

## 間隔設定

既存設定をレイアウトの基準にする。

- 横方向: `CHILD_HORIZONTAL_GAP`
- 同一ツリー内の縦方向: `SIBLING_VERTICAL_GAP`
- ツリー間: 新設する`TREE_VERTICAL_GAP`（`SIBLING_VERTICAL_GAP * 2`）

間隔の数値はドメインモジュール内へ直書きしない。

## エラー処理と原子性

`layoutNodeForest`は次の場合に`null`を返す。

- ID重複または非有限ID
- 親ノード欠損
- 自己参照または循環
- 座標またはサイズが非有限
- 幅または高さが0以下
- 必要高さ、列位置、配置座標の演算overflow
- 配置後の重なり不変条件違反

レイアウト失敗時は一部のノードだけを更新しない。`useNodes`はノード、選択、モードの元のstateと同期Refを維持する。

## パフォーマンス

- ツリー検証、索引構築、深さ計算、post-order、配置、出力生成はそれぞれノード数に対して線形時間とする。
- 全体の時間計算量は`O(n)`、追加メモリは`O(n)`とする。
- 非再帰の走査で深いツリーのstack overflowを防ぐ。
- 自動モードの1commandでstateを中間更新せず、候補ノード配列から1回だけレイアウトを実行する。

## テスト方針

### ドメイン

- 単一ノードの座標を維持する。
- 深いツリーを左から右へ深さ別の列に配置する。
- 分岐ツリーで親を子グループの中央へ配置する。
- 幅と高さが異なるノードでも重ならない。
- 複数ルートを入力順で上から下へ配置する。
- 最初のルートのX座標とY座標を維持する。
- すべてのノード組み合わせが重ならないことを独立した長方形判定で検証する。
- 入力配列、ノード参照、座標以外の値、入力順を検証する。
- 空配列、ID重複、親欠損、循環、非有限値、0以下のサイズ、各演算overflowを検証する。
- 逆順の深いツリーで読み取り回数が線形範囲に収まることを検証する。

### Hook

- 初期モードとモード切り替えを検証する。
- 自動モードへの切り替え直後に整列する。
- 自動モード中のルート、子、兄弟追加、削除、接続後に再配置する。
- 手動モードの各commandは従来の配置を維持する。
- 自動モード中の`moveNode`が配列参照と座標を維持する。
- 手動モードへ戻しても整列済み座標を維持する。
- 初回renderで取得したcommandが最新モードとノードを使う。
- 無効レイアウトでノード、選択、モードを変更しない。
- モード変更commandの参照がノード更新後も安定している。

### UIと統合

- モードボタンの表示、`type`、`aria-pressed`、callbackを検証する。
- モードごとの操作案内を検証する。
- `page.tsx`がHookのモードとcommandをヘッダーへ渡すことを検証する。
- 実際の`useNodes`と`MapStage`を通し、自動モードでの追加、削除、接続後の最終座標とノードドラッグ無効化を検証する。

各実装タスクで対象テストをREDにしてから最小実装を行う。各PRで`client`ディレクトリから`npm run verify`を実行する。

## 対象外

- 上から下へのレイアウトや方向切り替え
- ノードごとの自動レイアウト固定／解除
- 選択部分木だけの再レイアウト
- 手動ドラッグと自動配置の混在
- レイアウト変更のアニメーション
- モードと座標の永続化
- Undo／Redo
- サーバー保存や共同編集

## ロードマップ更新

各PRのマージ後処理で、完了した項目、Phase 4の進捗、現在地、次の未完了項目を`ROADMAP.md`へ反映する。実装PRには先回りで完了チェックを入れない。

## 完了条件

- 左から右のツリー配置で親子関係を追える。
- ノードの幅、高さ、深さ、分岐、複数ルートにかかわらず、ノード同士が重ならない。
- 最初のルートの位置と入力順を維持する。
- 自動モードの切り替えとツリー変更後に配置が更新される。
- 自動モードで手動ドラッグが状態を変更しない。
- 無効入力や演算overflowで部分的な状態更新を行わない。
- レイアウト計算が時間・メモリともに`O(n)`である。
- 新しい外部依存を追加しない。
- すべての自動検証が成功する。
