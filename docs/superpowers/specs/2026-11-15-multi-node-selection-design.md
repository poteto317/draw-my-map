# 複数ノード選択（候補009）設計

作成日: 2026-11-15。対象: Phase 17 の候補009。状態: サブエージェントレビュー 2 周通過・承認済み（設計確定）。

## 決めたこと（ユーザー確認済み・推奨案）

1. 操作: `Cmd`/`Ctrl`+クリックでトグル、`Shift`+クリックで範囲追加、空き背景での矩形範囲選択を追加する。
2. Shift 範囲の順序: 表示中ノードのうち、現在のノード配列順でアンカーからクリック先までを含む区間。
3. 複数選択時の既存操作: 主選択（最後の選択操作で定めた1件。クリック・トグル・範囲・矩形のいずれも含む）だけに作用する。一括編集は候補010に委ねる。
4. アウトライン: キャンバスのみ複数選択。アウトラインは単一選択のまま（主選択だけ同期）。
5. 永続化・Undo: 選択集合はメモリのみ。保存形式は変えない。Undo/Redo で選択集合は復元しない。

### 推奨案の具体化（既存操作との衝突）

- **矩形選択とパン**: 修飾なしの空き背景ドラッグは既存どおりパン。矩形選択は **`Alt`（Option）押しながらの空き背景ドラッグ**とする（推奨「空き背景ドラッグ」をパンと両立させる具体化）。
- **`Shift`+クリックと `Shift`+ドラッグ接続**: しきい値未満の `Shift`+ポインタ操作は範囲選択、しきい値以上の `Shift`+ドラッグは既存の接続ジェスチャー（現状の `dragActivation` と同じ 4px）。

---

## 1. 目的と境界

キャンバス上で複数のノードを同時に選択できるようにし、視覚的に分かり、次の候補010（一括編集）の土台にする。この PR では選択の追加・解除・表示と、既存の単一選択依存操作を「主選択」へ安全に接続するところまでを範囲とする。

### 対象外（YAGNI）

- 選択ノードの一括編集（重要度・色・タグなど）→ 候補010。
- 一括検索・置換、分割・統合 → 候補034 / 035。
- アウトライン側の複数選択 UI。
- 選択集合の localStorage / JSON 永続化、Undo 履歴への選択スナップショット。
- タッチ端末専用の複数選択ジェスチャ（既存のポインタ経路が動けばよく、専用 UI は作らない）。
- 複数選択時の一括ドラッグ移動（主選択のノード移動は現状どおり。複数同時移動は後続）。

---

## 2. 既存実装の調査と制約

- `useNodes.ts`: `selectedNodeId: number | null` と `selectNode(id)`。作成・削除・接続などの結果で単一 ID を更新。
- `MapStage.tsx` / `stageInteractions`: クリックで `onSelectNode`、空き背景クリックで解除、空き背景ドラッグでパン、`Shift`+ノードドラッグで接続、通常ドラッグで移動。
- `renderMapNodes.ts`: `node.id === selectedNodeId` で選択ハイライト（薄青背景・青太枠）。
- ヘッダー操作・ショートカット・右パネル・アウトライン・検索フォーカスはすべて `selectedNodeId` 前提。
- `features.md` 3.3 節: 単一選択と背景クリック解除を規定。

## 3. 選択モデル

### 3.1 状態

```typescript
// 概念（配置は hooks / domain に分ける）
type NodeSelectionState = {
  /** 選択中の ID 集合（順序は持たない。表示順はノード配列順） */
  selectedIds: ReadonlySet<number>;
  /** 主選択。既存 API の selectedNodeId と一致。集合が空なら null */
  primaryId: number | null;
  /** Shift 範囲の起点。単一選択・トグル後に更新。背景解除で null */
  anchorId: number | null;
};
```

- 不変条件: `primaryId === null` ⇔ `selectedIds.size === 0`。`primaryId !== null` なら `selectedIds.has(primaryId)`。
- `anchorId` は集合に含まれていなくてもよいが、通常は含まれる。消えたノードを指す場合は次の選択操作で付け直す。

### 3.2 互換 API

- 既存の `selectedNodeId` / `selectNode(id | null)` は残す。
  - `selectedNodeId` ≡ `primaryId`。
  - `selectNode(id)` ≡ 単一選択に置き換え（`selectedIds = {id}`、`primaryId = anchorId = id`）。`selectNode(null)` ≡ 全解除。
- 新規: `selectedNodeIds: readonly number[]`（配列順はノード配列順で安定化）、`toggleNodeSelection`、`selectNodeRange`、`setNodeSelectionFromMarquee` など。公開面は実装プランでファイル分割に合わせて決める。

### 3.3 ノード消失時とセッション境界

- **同一マップ内で ID が消えるとき**（削除、折りたたみ非表示による選択リセットなど）: 集合からその ID を取り除く。`primaryId` が消えたら集合が残っていればノード配列順の先頭を新しい主選択にし、空なら `null`。`anchorId` が消えたら `primaryId` に合わせる（なければ `null`）。
- **マップ切替・JSON 読込・保護モード突入**: §6 どおり選択を **全解除**する（ID の再利用があっても前マップの選択を持ち越さない）。

## 4. 操作仕様

### 4.1 プレーンクリック（ノード）

- そのノードだけの単一選択にする。`primaryId = anchorId = その ID`。

### 4.2 `Cmd`/`Ctrl`+クリック（トグル）

- **修飾の解釈**: macOS では `metaKey`（Cmd）でトグルする。Windows / Linux では `ctrlKey` でトグルする。**macOS の `ctrlKey` 付きクリックはトグルしない**（既存の `contextmenu` / Ctrl+クリック経路を優先。L-149）。
- 未選択なら集合に追加し、主選択・アンカーをその ID にする。
- 選択済みなら集合から外す。外したのが主選択なら、残りの配列順先頭を主選択（空なら解除）。**外したあとのアンカーは新しい主選択（空なら null）**とする。
- 新規ジェスチャ導入後も、`contextmenu` かつ macOS の `ctrlKey` では進行中ジェスチャをキャンセルする既存保護を壊さない（回帰テストで固定）。

### 4.3 `Shift`+クリック（範囲）

- `anchorId` が無い、またはアンカーが現在の表示中集合に無い場合は、プレーンクリックと同じ（単一選択）。
- ある場合: 表示中ノードをノード配列順に並べ、アンカーとクリック先のインデックス区間（両端含む）を **現在の集合に加算**する（置換ではない）。主選択はクリック先。アンカーは変えない。

### 4.4 空き背景クリック

- しきい値未満: 全解除（現状どおり）。
- しきい値以上かつ **`Alt` なし**（`Shift` / `Cmd` / `Ctrl` の有無を問わない）: パン（現状どおり）。
- しきい値以上かつ **`Alt` あり**: 矩形選択ジェスチャー（4.5）。`Alt`+他修飾の組み合わせでも矩形とする（確定時の集合の扱いだけ 4.5 で分岐）。

### 4.5 矩形選択（`Alt`+空き背景ドラッグ）

- 開始点〜現在点の軸平行矩形（スクリーン座標→ワールド座標）に、**表示中ノードのうち外接矩形が選択矩形と交差するもの**を含める（中心判定は使わない）。
- ドラッグ中はラバーバンド矩形を描画する。
- 確定時:
  - `Alt` のみ（`Cmd`/`Ctrl` なし）: 集合をその結果で **置換**する。
  - `Alt`+`Cmd`/`Ctrl`: 結果を現在の集合へ **加算**する（必須）。
  - 結果が 1 件以上: `primaryId` と `anchorId` を、結果集合のうち **ノード配列順の末尾**の ID にする。
  - 結果が 0 件: 全解除（`primaryId = anchorId = null`）。

### 4.6 `Shift`+ノードドラッグ（接続）

- 既存どおり接続ジェスチャー。開始時に接続元を選択状態にする現行挙動は、**単一選択に置き換える**（複数のまま接続元だけ足すと曖昧なため）。

### 4.7 キーボード

- `Escape`: 全解除（キャンバスにフォーカスがあり、ダイアログ・インライン編集中でないとき）。既存ショートカットと衝突しない範囲で。未実装なら追加してよい。
- `Delete` / `Backspace` / `Tab` / `Enter` / `F` / 枝操作: **主選択のみ**（現状の `selectedNodeId` 経路）。複数選択中でも主選択が対象。主選択が無ければ無効。

---

## 5. 表示

- 選択中の各ノードに現行の選択ハイライトを付ける（`isSelected = selectedIds.has(id)`）。
- 主選択を他と区別する追加装飾は **必須にしない**（YAGNI）。必要なら候補010で検討。
- 矩形ドラッグ中のラバーバンドは半透明の青系ストローク（既存の選択色 `#2563eb` に合わせる）。

---

## 6. 既存機能との接続

| 機能 | 複数選択時の挙動 |
| :--- | :--- |
| 重要度・イラスト・折りたたみ・複製・階層・親挿入・枝移動・ノードだけ削除・検索フォーカス・F | 主選択のみ |
| `Ctrl`/`Cmd`+C | 主選択とその子孫（現状）。複数枝の一括コピーは対象外 |
| アウトライン | `selectedNodeId`（主選択）のみ同期。アウトライン操作は単一のまま |
| マップ切替・読込・保護モード | 選択全解除 |

## 7. テスト方針

- ドメイン/フック: トグル・範囲加算・アンカー欠落・ノード消失時の primary 付け替え・`selectNode` 互換。

- 回帰: 単一選択時の既存ショートカット・ヘッダー操作が主選択で動くこと。
- 仕様: `features.md` 3.3 を複数選択に更新。`browser-test-cases.md` に節を追加。
