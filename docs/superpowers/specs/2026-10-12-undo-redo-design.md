# Undo／Redo 設計

作成日: 2026-10-12

## 目的と範囲

誤操作を戻し、戻した操作をやり直せるようにする。この設計は実装プラン（`docs/superpowers/plans/2026-10-12-undo-redo.md`）に沿って実装済みで、ROADMAP.md に Phase 8「編集履歴」として追記した。

状態管理、Pixi の操作境界、保存、非同期生成にまたがるため、設計書を伴う変更として扱う。以下の操作単位・100件上限・読み込み時の境界は、今回の計画で採用する既定仕様。

## 方式の比較と決定

| 方式 | 利点 | 負担 |
| --- | --- | --- |
| マップの不変スナップショット | 削除した子孫・自動配置・画像を正確に復元できる | 配列の履歴保持が必要 |
| 操作ごとの逆コマンド | 大規模マップでは保持量を抑えやすい | 全操作の逆操作、配置結果、削除部分木の管理が必要 |
| 汎用の履歴ライブラリ | 履歴の基本操作を再利用できる | 現在の同期 ref 更新やドラッグ境界への接続は別途必要 |

**不変スナップショットを採用する。** `NodeMapState`（`nodes` と `layoutMode`）を一体で記録する。変更のない Node オブジェクトと画像文字列は共有し、JSON 化・deep clone を毎回行わない。新規依存は追加しない。

## Global Constraints

- 履歴はメモリ内のみ。最大100操作を戻せる。JSON／localStorageのV3形式は変更しない。
- 復元対象は `NodeMapState` 全体。座標・親子関係・ラベル・重要度・イラスト・寸法・配置モードを含む。
- パン・ズーム・フォーカス・選択・表示フィルター・生成プレビューは履歴に含めない。
- 成功したUndo／Redoでは選択を解除し、編集中の状態・ジェスチャー・メニュー・生成結果を失効させる。viewportと表示フィルター設定は維持する。
- 履歴に影響する状態遷移は同期refとReact stateに一体で反映し、同一イベント内の連続操作にも対応する。
- 既存の保存・画像出力・イラストAPIの形式と、操作が失敗した場合にマップを保つ契約を維持する。
- 実装は `.worktrees/codex/phase8-undo-redo` の `codex/phase8-undo-redo` ブランチで行い、タスクを順番にサブエージェントへ渡す。仕様・品質レビューを通してから次へ進む。
- 各実装タスクでTDDを行い、client変更後は `cd client && npm run verify` を成功させる。最後にROADMAP.mdを更新する。明示依頼なしにpush・PR作成・マージはしない。

## 操作の単位

| 現在の入口 | 履歴単位 |
| --- | --- |
| `addNode` / `addChildNode` / `addSiblingNode` | 1回の追加。自動配置による既存ノード移動も同じ1操作 |
| `deleteNode` | 対象と全子孫の削除をまとめて1操作 |
| `connectNodes` | 接続と付随する自動配置を1操作 |
| `updateNodeLabel` | Enter／blurによる確定を1操作。入力中の文字ごとは記録しない |
| `updateNodeImportance` | 1回の変更を1操作 |
| `attachIllustration` / `removeIllustration` | 画像・寸法・自動配置をまとめて1操作。再生成結果の設定も同じ |
| `moveNode` | UIの連続ドラッグ全体で1操作。直接の単独呼び出しは1操作 |
| `setLayoutMode` | モードと配置結果をまとめて1操作 |
| `replaceMap` | 初回保存復元／成功したJSON読み込みを新しい起点とし、過去・未来・進行中の履歴グループを消す |
| `selectNode`、閲覧操作、生成開始・プレビュー | 記録しない |

追加直後のラベル入力は追加と別操作。Undo1回で確定ラベルが元に戻り、もう1回でノードが消える。ネットワークでの画像再生成をRedoで実行せず、保存済みの画像を復元する。

同値のラベル・重要度・画像・座標・モード、存在しないID、拒否された接続、自動配置失敗は履歴を増やさず、Redoも消さない。配列参照だけで判断せず、ノード配列の順序とNodeの全フィールドを比較する。新しい実変更だけがRedoを破棄する。

## ドラッグと操作の割り込み

ドラッグ閾値を越えて最初の移動を通知する直前にグループを開始し、終了まで表示上の現在値だけを更新する。開始時スナップショットと終了値の差があれば過去に1件追加する。元の座標へ戻った場合は履歴とRedoを開始時のまま保つ。初期位置、子孫位置も全体で比較する。

`pointerup` と `cancel` の両方でグループを閉じる。現状のcancelは移動済み位置を戻さないため、この仕様を維持し、pointercancel・領域外解放・ピンチ開始・ズーム・非表示化による中断でも移動分を1件として残す。クリックだけでは開始しない。

グループ開始は `MapHistoryGroupLease = { isActive: () => boolean; finish: () => void }` を返す。finishは冪等で、内部の世代を照合する。新しいbeginGroupは既存グループを確定し、旧leaseを失効させる。Pixiは毎回のmove前にisActiveを照合し、失効済みなら以後のmoveを通知しない。Undo／Redo（復元不成立でも）・別編集・マップ置換がグループを終了／破棄した後に、古いmoveやfinishが新しい履歴を変更することはない。

Undoは進行中のグループを確定してから1操作戻す。ドラッグの実変更だけがある場合もUndo可能。Redoもグループを先に確定するため、実変更を伴うドラッグ中はRedo不可。別編集はグループを確定してから独立した1操作として実行する。replaceMapはグループを確定せず破棄する。以降の古いpointermoveはキャンセルされたジェスチャーから通知されないことを結合テストする。

実変更を伴うドラッグ中のRedo（false）、空履歴でのUndo、ドラッグ中の別編集ではdocumentRevisionが増えないためジェスチャー自体は継続するが、leaseが失効するのでポインターを押したままでもノードは以後動かない。この挙動はUXとして許容する。

## 復元と副作用

- Undo／Redoは保存した座標をそのまま復元し、自動レイアウトを再計算しない。
- `useNodes` に `documentRevision`（初期値0）を新設し、成功したUndo／RedoとreplaceMapで増加させる。履歴が空の操作は増加させない。ID allocatorはUndo／Redoではresetせず、replaceMap時の既存resetを維持する。
- MapStageは新しいdocumentRevisionで編集・ジェスチャー・メニューを閉じる。既存resetRevisionによるviewport初期化はJSON読み込み／初回復元に限定する。
- `useIllustrationGeneration(nodes, documentRevision)` により、進行中リクエスト・既存プレビューを失効させる。IDとラベルがUndo／Redoで元に戻る場合も旧応答を使わない。
- 復元された現在値を既存300msの自動保存に流す。履歴配列は保存しない。Undo直前の保存タイマーが復元後の値を上書きしないことをテストする。
- JSON読み込み失敗時は履歴も現在値も維持する。進行中のJSON読み込みは既存どおり、最新の読み込み要求が成功した時点でマップを置換する。Undoはファイル読み込み要求自体を取り消さない。

## UIとショートカット

ヘッダーのoperationControls内に `元に戻す` / `やり直す` の2ボタンを置く。実行できない側はHTMLのdisabledを使う。アイコンだけにせず、日本語ラベルとfocus-visible表示を持たせる。

- Undo: Ctrl+Z または Meta+Z（Shiftなし）。
- Redo: Ctrl+Shift+Z / Meta+Shift+Z、およびCtrl+Y（Shiftなし、Metaなし）。
- Alt併用、CtrlとMetaの同時押し、IME変換中、キーリピート、defaultPrevented済みは処理しない。
- input／textarea／select／contenteditable内はブラウザ側に任せる。ノード編集入力も同じ扱い。
- それ以外は、ヘッダーのボタンにフォーカスがあってもマップのショートカットが使える。アプリ対象のキーと認識した場合は履歴が空でもpreventDefaultし、画面上の履歴操作は行わない。
- ラベル編集中に、クリック開始時点で有効な履歴ボタンをクリックすると、既存blurでラベルを確定してから最新の履歴へ操作する。変更を確定した場合、Undoはその変更を戻し、Redoは新しい編集で破棄される。ボタン表示が古くても実行関数側で再判定する。編集内容が同値なら履歴を増やさない。履歴空などでボタンがdisabledの場合は、Enterまたは別の場所へのblurで先に編集を確定してからUndoする。disabledへのクリックによるblurには依存しない。

## 範囲外・制約

履歴一覧・永続履歴・複数マップ・共同編集・差分圧縮・操作名表示は含めない。100件上限は操作数の上限で、バイト数上限ではないため、異なる画像を多数設定すると保持メモリは増える。既存のテクスチャキャッシュの寿命は変更しない。保存失敗時の通知は既存の仕組みを使う。
