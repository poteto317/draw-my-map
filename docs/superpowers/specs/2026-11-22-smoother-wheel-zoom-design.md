# 拡大縮小の感度を上げる（カード #48）

- 日付: 2026-11-22
- 対象: [scrum #48](https://scrum-board-jkcejsb6ka-an.a.run.app/items/48?project=5)「拡大縮小をもっとスムーズに」
- ステータス: 設計承認（レビュー反映済み）

## 問題

拡大・縮小の操作量に対して、実際の倍率変化が小さく感じる。カード文言の「スムーズ」はアニメーションではなく、**操作あたりの変化量**の不足を指す。

## 背景（現状）

- Ctrl/Cmd + ホイール（および主要ブラウザで `wheel` + `ctrlKey` として届くトラックパッドピンチ）は `calculateWheelZoomRequest` が `WHEEL_ZOOM_SENSITIVITY = 0.001` で  
  `requestedScale = currentScale * exp(-delta * 0.001)` を計算する。
- 典型ノッチ相当 `deltaY = ±100`（pixel）では約 ±10.5%（`exp(0.1)`）。
- 右下 +/- は 1 回あたり ×/÷ 1.25（+25%）。ホイール 1 ノッチより強い。
- 修飾キーなしホイールはパンのみ（#47）。タッチ 2 本指ピンチは距離比の即時反映（感度定数なし）。
- ズーム範囲は 0.25x〜4.0x。補間アニメはない。

## 決めたこと（ユーザー回答＋未回答は推奨）

1. **解釈**: 操作あたりの変化量を上げる。補間アニメは追加しない。（推奨・未回答）
2. **対象入力**: Ctrl/Cmd+ホイール（＋ `ctrlKey` 付きトラックパッドピンチ）の感度だけ変更。+/- とタッチピンチは据え置き。（推奨・未回答）
3. **感度**: `WHEEL_ZOOM_SENSITIVITY = 0.0025`（ユーザー選択 **3C**）。  
   `deltaY = ±100` のとき約 ±28.4%（`exp(0.25)`）。+/- 1 回（+25%）よりやや強い。
4. **ズーム範囲**: 0.25〜4 のまま。（推奨・未回答）

## 要件

### 必須

1. `client/src/components/map/wheelZoom.ts` の `WHEEL_ZOOM_SENSITIVITY` を `0.001` から **`0.0025`** に変更する。計算式・正規化・clamp・アンカーは変えない。
2. 修飾キーなしホイールのパン、+/- の `ZOOM_FACTOR = 1.25`、タッチピンチ経路、閲覧履歴への非積載は **#47 のまま**。
3. 感度に依存する自動テストの期待値を更新する。`deltaY: -100`（pixel）かつ感度を使うケースは `Math.exp(0.1)` を **`Math.exp(0.25)`**（または同等の式）に置き換える。対象の目安:
   - `wheelZoom.test.ts`
   - `useMapWheelZoom.test.tsx`
   - `MapStage.test.tsx` / `MapStageVisibility.test.tsx` / `MapStageHistory.test.tsx` など、ホイールズームで `Math.exp(0.1)` を固定しているもの
   - `pageHistory.test.tsx` / `pageMapLibrarySwitch.test.tsx` など同値を固定しているもの
4. `docs/specifications/features.md` の `WHEEL_ZOOM_SENSITIVITY = 0.001` および式中の `0.001` を **`0.0025`** に更新する。
5. `client` で `npm run verify` が通る。

### 対象外

- ズームの lerp / 慣性 / イージング
- +/- 倍率の変更、タッチピンチ感度の変更
- ズーム上下限の変更、スライダーやミニマップ
- 通常ホイールを再びズームにする変更
- ROADMAP の Phase 完了扱い（操作感度の調整であり未完了ロードマップ項目ではない）
- 歴史ドキュメント（Phase 3 設計・プランの過去の数値）の遡及修正は必須としない（現行仕様書 `features.md` のみ必須）

## 設計

変更は定数 1 つと、それに紐づくテスト・仕様書の数値更新に閉じる。モジュール分割や API 変更は不要。定数はファイル内の private `const` のままでよい（export しない）。

### 受け入れの目安

- 同一の `deltaY = -100` 入力で、倍率が約 `×exp(0.25)` になること（テストで固定）。
- パン経路・+/-・タッチピンチの既存テストが退行しないこと。

## 知見（手順 4）

新規 props や組み立て配線は無いため L-060 は適用外。注意点は次のみ:

- 感度に依存するテストの固定期待値（`Math.exp(0.1)` など）を実装の定数と同期する。漏れると GREEN のまま感度が戻る／期待だけ古いままになる。
- 高頻度 `wheel` の値を余分な粒度で state に持たない既存方針は維持（定数変更のみ）。

## 検証

1. 感度依存テストを RED（旧期待値のまま定数だけ変える）→ 期待値更新で GREEN。
2. `cd client && npm run verify`。
