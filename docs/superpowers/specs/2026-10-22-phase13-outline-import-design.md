# Phase 13: 箇条書きからマップを作成 設計

作成日: 2026-10-22
基準: main `ca52652`。作業ブランチは `codex/phase13-outline-import`（`.worktrees/codex/phase13-outline-import`）。

## 目的・範囲

メモや議事録などの階層的なテキストを、少ない操作でマインドマップのノードに変換できるようにする。ROADMAP Phase 13 の次の4項目を、1つの PR で実装する。

1. インデント付きの箇条書きテキストを、親子構造として解析する
2. 取り込む前に、変換結果をプレビューする
3. 確認したノードをマップへまとめて追加し、自動で配置する
4. 取り込み全体を1つの操作として、Undo / Redo できるようにする

## 対象外

- 貼り付け（Ctrl/Cmd+V）の内容の自動判定。キャンバスへの普通の文章の貼り付けは、今までどおり「貼り付ける枝データが無効です。」になる（Phase 9 の仕様を変えない）。
- 箇条書きの取り込み専用のキーボードショートカット。
- ファイル（.txt、.md、OPML など）からの読み込み。入力はダイアログのテキスト入力欄だけ。
- Markdown の見出し（`#`）、チェックボックス（`- [ ]`）、引用（`>`）、コードブロックなどの特別な扱い。すべて記号を取り除いた後のラベルの一部として扱う。
- 記法による重要度・イラスト・折りたたみの指定。追加するノードの重要度は、すべて既定値の `"medium"`。
- 逆方向（マップから箇条書きへの書き出し）。ROADMAP の Phase 15 で扱う。
- マップ全体のノード数の上限。今回の上限は1回の取り込みの量だけに掛ける。
- 取り込んだノードの順序や階層の後からの編集（Phase 14 で扱う）。
- 保存形式（V3）、JSON の形式、`Node` 型、履歴の形式の変更。

## 決めたこと

### ユーザーが決めたこと（2026-10-22）

1. **追加する位置**: 既定は「新しいルート」。ノードを選択しているときだけ、ダイアログで「選択中のノードの子として追加」も選べる。一番上の階層に複数の行がある場合は、複数の木（森）として追加する。
2. **記法**: 行頭の空白（タブ・半角スペース・全角スペース）の量で階層を判定する。行頭の記号（`-` `*` `+` `・` `•`）と番号（「1.」「1)」など）は取り除く。Markdown の見出し（`#`）は特別に扱わず、そのままラベルにする。
3. **長い行**: 文字数は制限せず、そのまま取り込む。200文字を超える行があれば、プレビューで件数を警告する。
4. **ダイアログのテキスト入力欄での Tab**: インデントは入力せず、次の要素へ移る（既存のダイアログと同じ）。

### ユーザーの決定の解釈

ユーザーの決定2の「行頭の記号と番号は取り除く」を、次のとおり狭く解釈する（ユーザーへの確認は、コントローラーが不要と判断した）。

- `-` `*` `+` は、後ろに空白が続くか、その記号だけで行が終わるときだけ記号とみなして取り除く。「-項目」「-5度」「+1」「*注意*」のように記号の直後に文字が続く行は、記号を取り除かずにそのままラベルにする。
  - 理由: 「-5度」「+1」のような値や、強調の `*` を含む文を記号と取り違えて壊さないため。Markdown の箇条書きも、記号の後に空白を置く書き方なので、普通の箇条書きは取り除ける。
- `・` `•` は、後ろに空白が無くても取り除く。
  - 理由: 日本語の箇条書きでは「・項目」と空白を置かずに書くことが多く、`・` で始まる値や文はほとんど無いため。
- 番号は、半角数字（1〜9桁）に `.` か `)` が付き、その後ろに空白が続くか行が終わる形（「1. 」「12) 」）だけを取り除く。全角数字（「１．」）、丸数字（「①」）、括弧で囲んだ番号（「(1)」）、空白の続かない形（「3.14」「1.5倍」）は取り除かない。
  - 理由: 「3.14」「1.5倍」「2026.10」のような数値を番号と取り違えないため。形を絞ると、取り除くかどうかを利用者が予想しやすい。取り除かなかった番号はプレビューのラベルにそのまま見えるので、利用者が気づいて直せる。
- 取り除く記号は1行に1つだけ（「- 1. 手順」は「1. 手順」）。2つ目の記号はラベルの一部とみなす。

### 推奨案として採用したこと（ユーザーには聞いていない）

コントローラーが推奨案として採用したもの:

- インデントの数え方: タブは1段とする。全角スペースは半角スペース2つとして数える。半角スペースでの1段の幅は、入力から自動で決める（決め方は、この設計書の作成者が下で補正した）。
- 空行は無視する。ラベルの前後の空白は取り除く。
- 階層が飛んでいる・食い違っている場合は、拒否せずに補正する。深すぎる行は直前の行の1段下に丸める。どの段にも合わない浅さの行は、それより浅い段のうち最も近い段に揃える。1行目がインデントされていても、最初の行を0段として扱う。補正した行の件数を、プレビューで警告として表示する。
- 上限: ノードは10,000件まで（クリップボードと同じ）。入力は1,000,000文字まで。上限は解析の前に判定する。超えた場合は確定できない。
- 重要度はすべて既定値の `"medium"`。記法による指定は入れない。
- 入り口はヘッダーの「箇条書きから追加」ボタン。ダイアログで「テキスト入力 → プレビュー → 追加」と進める。貼り付けた内容の自動判定と専用ショートカットは入れない。
- 配置: 自動配置のときは、既存の `applyTreeChange` による再配置に任せる。手動配置のときは、取り込む森だけを `layoutNodeForest` で並べて相対座標を作る。新しいルートとして追加する場合は、既存の手動配置と同じくマップの下端から40px下へ平行移動する。選択中のノードの子として追加する場合は、既存の子の追加と同じ規則（親の右側、既存の兄弟の下）を基準にする。
- 履歴: `applyTreeChange` を1回だけ呼び、1回の commit にする（Undo / Redo の1操作）。
- 追加後: 先頭のルートを選択する。ビューポートは動かさない（F キーで移動できる）。通知は「〇件のノードを追加しました。」に、既存の貼り付けと同じ案内（F キー、表示を「すべて」に切り替える）を加える。
- ダイアログ: `MapEditor` の中で開く。`editorShortcutsEnabled = shortcutsEnabled && !importOpen` を作り、`MapEditor` の根の `inert` と各ショートカットに渡す。ダイアログは `inert` の対象から外れる位置（根の兄弟）に描く。`useDialogFocusTrap` と `useReannouncedNotice` を流用し、`dialogMouseClickedAtRef` も共有する。
- ID: 既存の allocator の `nextAvailableIds` で、まとめて採番する。

この設計書の作成者が推奨案として決めたもの（下の各節で根拠を書く）:

- 標準の1段の幅（下の `W`）は、「隣り合う取り込む行の間で、空白の幅が増えた量のうち、最も多く現れた値（同数なら先に現れた値）」にする。コントローラー案の「最も小さい0より大きいインデント」を補正したもの。全体が2文字インデントされた箇条書き（コピー元の入れ子の途中）でも段の幅を正しく求められ、1か所だけ不揃いな行があっても、その行に引きずられずに大多数の行の幅を基準にできるようにするため。
- 階層の補正の警告は、「段を決めた後、親の行より標準の幅と違う量だけ深い行」と「どの段のインデントとも一致しない浅い行」に出す。利用者が警告の行番号を見て、直すべき行をそのまま見つけられるようにするため。
- 「どの段にも合わない浅さの行」は、それより浅い段のうち最も近い段に揃え、その段にこの行のインデントの値も加える。後に続く同じインデントの行が、同じ段の兄弟になり、警告も出ないようにするため。
- 記号だけの行（「-」「1.」など、記号を取り除くとラベルが空になる行）は取り込まず、件数と行番号をプレビューで警告する。
- 記号と番号の判定は「ユーザーの決定の解釈」のとおり。
- 200文字の判定は、記号と前後の空白を取り除いた後のラベルを、コードポイント数で数える。
- 文字数の上限は UTF-16 コード単位（`string.length`）で数える（クリップボードと同じ）。行数の上限は、空行でない行（空行の判定と同じ定義。記号だけの行は数え、空白と制御文字だけの行は数えない）の数で、解析の前に判定する。
- ラベルの中の制御文字（U+0000〜U+001F、U+007F）は半角空白に置き換える。先頭の BOM（U+FEFF）1文字は取り除く。改行は CRLF・CR・LF の3種類で分ける。
- 森の挿入は、`insertNodeSubtree` を拡張せず、新しい関数 `insertNodeForest` を作る。手動配置の共通の規則（マップの下端からの平行移動、子の位置）は切り出して両方から使う。
- 手動配置で新しいルートとして追加するときの x はマップの左端（既存ノードの x の最小値）。空のマップでは先頭のルートを (40, 40) に置く。
- 子として追加する手動配置では、取り込む森を仮の親の下に並べてから平行移動し、兄弟の間隔を40pxにする。
- 追加先の親は、ダイアログを開いた時点の選択を控え、確定の時点で存在を確かめる。無ければエラーにし、黙って新しいルートへ変えない。
- 子として追加した親が折りたたまれていれば、追加に成功したときだけ親を展開する（Tab キーでの子の追加と同じ）。
- 解析は「プレビュー」ボタンを押したときに行う。入力中は文字数の上限だけを判定する。
- プレビューの木は先頭の200件まで表示し、ラベルは先頭80文字（コードポイント）まで表示する。警告の行番号は先頭の5件まで出す。
- 入力したテキストは、キャンセルや Escape で閉じても、同じ編集画面が続く間は残す。追加に成功したら空にする。
- 失敗の通知はダイアログ内に、成功の通知はエディタの操作通知バー（7系統目）に出す。
- ゼロ幅スペース（U+200B）などの書式文字だけのラベルは、空のラベルとして扱わない。
- 手動テストの記号は `P`。

## Global Constraints

- 新規依存なし。`Node`、`NodeMapState`、V3 の保存形式、JSON の形式、履歴の形式を変えない。

- 新しい props とコールバックは必須にする。実際の `Home` から `MapEditor`、ヘッダー、ダイアログまで通す結合テストで配線を確かめる（L-060）。

## 解析の仕様

`parseOutlineText(text: string): OutlineParseResult` は、次の順に処理する。各段階は別の関数で、段階ごとにテストする。

1. 上限の判定（文字数）
2. BOM の除去と行の分割、上限の判定（行数）
3. 行ごとのインデントの測定とラベルの取り出し
4. 標準の1段の幅の決定と、階層の決定・補正
5. 警告の集計

### 改行コード

- 改行は `\r\n`、`\r`、`\n` の3種類を区切りとして扱う（正規表現 `/\r\n|\r|\n/`）。1つの入力の中で混ざっていてもよい。`\r\n` は1つの改行として数える（空行を作らない）。
- U+2028（行区切り）、U+2029（段落区切り）、U+0085（NEL）は改行として扱わない。ラベルの中に残る（制御文字ではないので置き換えもしない）。
- 行番号は、この分割の結果で1から数える。プレビューの警告の行番号はこの番号。
- 最後の行に改行が無くてもよい。末尾の改行による最後の空行は、空行として無視する。
- ブラウザの `<textarea>` の `value` は改行を LF に正規化するため、ダイアログから渡る入力は実際には LF だけになる。解析関数は純関数として CRLF・CR も同じ結果にし、将来ほかの入口（ファイル・クリップボード）から直接渡しても結果が変わらないようにする（L-138）。入力の文字列は書き戻さないので、改行コードを保つ必要はない（L-013 の対象外であることを、ここで明記する）。

### BOM

- 入力の先頭の1文字が U+FEFF なら取り除いてから分割する。BOM が残ると1行目のインデントの測定がずれるため。
- 先頭以外の U+FEFF は取り除かない（ラベルの前後にあれば、前後の空白の除去で消える）。
- 文字数の上限は、BOM を取り除く前の文字列で判定する。

### インデントの数え方

- 行頭のインデントは、行の先頭から続く次の3種類の文字の並びとする。
  - タブ（U+0009）: 1段。
  - 半角スペース（U+0020）: 幅1。
  - 全角スペース（U+3000）: 幅2（半角スペース2つ分）。
- それ以外の空白（ノーブレークスペース U+00A0 など）はインデントとして数えない。インデントの後に続く場合は、ラベルの前後の空白として取り除かれる。
- 行ごとに、タブの数 `T` と、空白の幅 `S`（半角スペースの数 + 全角スペースの数 × 2）を測る。タブと空白は、並びの順序によらず合計する。
- 標準の1段の幅 `W`: 取り込む行（空行と記号だけの行を除いた行）を入力の順に並べ、隣り合う2行の間で `S` が増えた量（後の行の `S` − 前の行の `S` が正のもの）を集める。そのうち最も多く現れた値を `W` にする。最も多い値が複数あれば、入力の中で先に現れた値にする。増えた箇所が1つも無ければ `W = 1`。
  - コントローラー案の「最も小さい0より大きいインデント」から補正した。全体が一律にインデントされた入力（例: 各行に2文字の下駄があり、1段が4文字）でも、下駄の幅ではなく段の差から `W` を求められるため。また、最小値ではなく最も多い値にすることで、1か所だけ1文字ずれた行（例: 2文字の段の中に1文字だけ深い行）があっても、その行の幅が基準にならず、ずれた行のほうに警告が出る。
  - 既知の制限: 増えた量の種類が同数で並ぶ短い入力（例: 増分が2と4の1回ずつ）では、先に現れた値を標準とみなすため、利用者の意図と逆の行に警告が出ることがある。親子関係そのものは `W` によらず下の手順で決まるので、プレビューの木は変わらない。
- 行のインデント値 `v = T × W + S`。タブだけの入力では `W = 1` なので、`v` はタブの数になる。`W` はタブを空白の幅に換算するのと、警告を出すかどうかの判定だけに使い、親子関係はインデント値の大小と一致で決める。

### 記号と番号の除去

インデントの後の残りの部分から、次の順にラベルを作る（`extractOutlineLabel(rest)`）。

1. 制御文字（U+0000〜U+001F、U+007F）を半角空白に置き換える。ラベルの途中のタブも半角空白になる。
2. 前後の空白を `String.prototype.trim` で取り除く（全角スペースやノーブレークスペースも含む）。ここで空になった行は空行。
3. 先頭が次のいずれかに当てはまれば、その記号を1つだけ取り除く（上から順に判定し、最初に当てはまったものだけ）。
   - `・`（U+30FB）か `•`（U+2022）: 後ろの文字によらず取り除く（日本語では後ろに空白を置かないことが多いため）。
   - `-`、`*`、`+`: 後ろに空白（正規表現の `\s`）が続くか、その記号で終わるときだけ取り除く。
   - 番号: 半角数字1〜9桁に `.` か `)` が続き、その後ろに空白が続くか、そこで終わるときだけ取り除く。
4. もう一度、前後の空白を取り除く。
5. ここで空になった行は、記号だけの行。

- 取り除く記号は1つだけ。「- 1. 手順」は「1. 手順」になる。
- 全角数字の番号（「１．」）、丸数字（「①」）、括弧付きの番号（「(1)」）、ほかの記号（`◦` `■` `○` `‣`）は取り除かず、ラベルに残す。
- `#` は取り除かない（ユーザーの決定2）。「# 見出し」はそのまま「# 見出し」になる。
- ゼロ幅スペース（U+200B）は `trim` の対象ではないため、ゼロ幅スペースだけの行は空にならず、見た目が空のノードとして取り込まれる。書式文字を除くと結合文字を含む絵文字の扱いに影響するため、対象外とする（L-602 と同じ判断）。

### 空行と空のラベル

| 行の種類 | 判定 | 扱い | 警告 |
| :--- | :--- | :--- | :--- |
| 空行 | インデントの後の残りが、制御文字の置き換えと `trim` で空になる（`isBlankOutlineRest`）。空白だけの行、制御文字だけの行、空白と制御文字だけの行を含む | 無視する。階層の判定にも `W` の計算にも使わない。行数の上限にも数えない | 出さない |
| 記号だけの行 | 空行ではなく、記号を取り除いた後のラベルが空 | 無視する。階層の判定にも `W` の計算にも使わない。行数の上限には数える | 「empty-label」の件数と行番号 |
| 取り込む行 | ラベルが空でない | ノードにする | 下の「階層の補正」「長い行」 |

空行の判定は `isBlankOutlineRest` の1か所で行い、行数の上限の判定（解析の前）とラベルの取り出し（`extractOutlineLabel` の手順1・2）の両方がこの関数を使う。定義がずれて、上限では数えない行がノードになったり、その逆が起きたりしないようにする（L-136）。

記号だけの行を空のラベルのノードにしない理由: 箇条書きの区切りや書きかけの行が、何も書かれていないノードとして増えると、利用者が後で探して消す手間が増えるため。無視したことは警告で伝える（L-044。黙って捨てない）。

### 階層の補正

取り込む行を入力の順に処理し、祖先の段を積んだスタック `levels` で深さを決める。`levels[d]` は深さ `d` の段で、次の値を持つ。

- `values`: その段に揃えたインデント値の集合（最初は、その段を作った行の `v` だけ）。
- `min`・`max`: `values` の最小値と最大値。
- `lastV`: その段に最後に置いた行の `v`。
- `lastIndex`: その段に最後に置いた項目の添字（子の親を決めるのに使う）。

不変条件: 段 `d` の `values` はすべて、段 `d + 1` の `min` より小さい。

各行（インデント値 `v`）は、次の手順で深さを決める。

1. 最初の行は深さ0。`levels = [{ values: {v}, min: v, max: v, lastV: v }]`。警告しない（1行目がインデントされていても数えない）。
2. 2行目以降は、`levels` が2段以上あり、末尾の段の `min` が `v` より大きい間、末尾の段を取り除く。1段でも取り除いたかを `popped` に控える。
3. 末尾の段を `top`（深さ `dTop`）とし、次の表の最初に当てはまる行で決める。

| 場合 | 条件 | 深さ | `levels` の更新 | 補正の警告 |
| :--- | :--- | :--- | :--- | :--- |
| 一致 | `top.values` に `v` がある | `dTop` | `lastV` と `lastIndex` を更新 | なし |
| 深い | `popped` が偽で、`v > top.max` | `dTop + 1` | 末尾に新しい段 `{ values: {v} }` を積む | `v − top.lastV !== W` なら1件 |
| 揃える | 上のいずれでもない（段の間、最初の段より浅い、同じ段の値の間） | `dTop` | `top.values` に `v` を加え、`min`・`max`・`lastV`・`lastIndex` を更新 | 1件 |

- 「深すぎる行は直前の行の1段下に丸める」は「深い」の行にあたる。どれだけ深くても1段だけ深くし、親の行より標準の幅 `W` と違う量だけ深いとき（2段以上深い、または1段に満たない・半端な深さ）だけ警告する。
- 「どの段にも合わない浅さの行は、それより浅い段のうち最も近い段に揃える」は「揃える」の行にあたる。手順2で、`v` より深い段をすべて取り除いた後の末尾の段（`min` が `v` 以下の段のうち最も深い段。それも無ければ深さ0の段）に揃える。
- 揃えた段の `values` に `v` を加えるので、その後に続く同じインデントの行は「一致」になり、同じ段の兄弟として警告なしで並ぶ。揃える前の値も `values` に残るので、元のインデントに戻った行も「一致」になる（例22の E）。
- 警告は、その行自体のインデントが周りと合わない行にだけ出す。補正の影響で親が変わっただけの後続の行には出さない。利用者は警告の行番号の行を直せばよい。
- 実装は `levels` の末尾から段を取り除く方法にする。取り除いた段は二度と戻らず、`values` の追加は1行につき最大1回（`Set` を使う）なので、全体で入力の行数に比例する時間で終わる。
- 親は、深さ `d` の項目なら `levels[d − 1].lastIndex` の項目。深さ0の項目の親は `null`。
- 結果は常に「各項目の深さが直前の項目の深さ + 1 以下」で、最初の項目の深さは0になる（不変条件。テストで全例について確かめる）。

### 警告の種類と件数

| 種類 | 対象 | 文言 | 取り込み |
| :--- | :--- | :--- | :--- |
| `depth-adjusted` | 上の表で「補正の警告」が1件になった行 | 階層が合わない行を N 行補正しました（3、7、12行目）。プレビューで親子関係を確かめてください。 | する |
| `empty-label` | 記号だけの行 | 記号だけの行を N 行取り込みません（5行目）。 | しない |
| `long-label` | ラベルのコードポイント数（`Array.from(label).length`）が200を超える取り込む行 | 200文字を超える行が N 行あります（9行目）。そのまま取り込みます。 | する |

- 行番号は、各種類の先頭5件まで表示し、6件以上あるときは最後に「ほか」を付ける（例: 「（3、7、12、15、20行目ほか）」）。件数 N はすべての行を数える。
- 件数が0の種類は出さない。表示の順は表の順で固定する。
- 数値は `toLocaleString("en-US")` で桁区切りを付ける（既存のクリップボードの文言と同じ）。
- 200 は `OUTLINE_LONG_LABEL_THRESHOLD` として定数にし、文言はこの定数から作る。
- 警告は追加を止めない。

### 上限

| 上限 | 値 | 数え方 | 判定の時点 | 超えたとき |
| :--- | :--- | :--- | :--- | :--- |
| 文字数 | 1,000,000 | UTF-16 コード単位（`text.length`）。BOM と改行も含む | 入力のたびに（O(1)）と、解析の最初 | エラー「テキストが長すぎます（1,000,000文字以内）。」と、別の欄に「現在 N 文字」。プレビューへ進めない |
| 行数（ノード数） | 10,000 | 空行でない行の数。空行の判定は「空行と空のラベル」の `isBlankOutlineRest` と同じ（空白・制御文字だけの行は数えず、記号だけの行は数える） | 行の分割の直後、記号の除去と階層の判定の前 | エラー「行が多すぎます（空行を除いて10,000行以内）。現在 N 行です。」。プレビューへ進めない |

- 定数は `OUTLINE_MAX_TEXT_LENGTH = 1_000_000`、`OUTLINE_MAX_ITEMS = 10_000` として `outlineLimits.ts` に置く。ノード数はクリップボードの `MAX_SUBTREE_CLIPBOARD_NODES` と同じ値だが、別の機能の上限なので別の定数にし、同じ値であることはテストで確かめない（片方だけを変えられるようにする）。
- 取り込むノード数は行数以下なので、行数の上限で10,000件を超えない。記号だけの行を含めて数えるのは、記号の除去の前に判定するため。空行の判定は記号の除去より前の段階なので、上限の判定でも同じ関数を使える。文言を「行」で書き、利用者が数え方を誤解しないようにする。
- 上限ちょうど（1,000,000文字、10,000行）は受け付け、1つ超え（1,000,001文字、10,001行）は拒否する（L-182）。
- 階層の深さには上限を設けない。ただし、1段深くするごとに行頭のインデントの文字が少なくとも1つ増えるので、文字数の上限（1,000,000）のため、テキストで書ける一本の鎖の深さはタブで最大1,412段（1,412段で998,989文字、1,413段で1,000,403文字）になる。`parseOutlineText` のテストでは、この上限に収まる最も深い鎖（1,412段）を例外なく解析できることを確かめる。10,000段の深い鎖の計算量は、段を決める関数（`assignOutlineDepths`）の単体テストに、取り込む行のインデントを直接渡して確かめる。挿入・自動配置も、10,000段の一本の鎖でスタックを使った反復で終わることを、それぞれの単体テストで確かめる。
- 取り込める行が0件（空の入力、空行と記号だけの行しかない）の場合はエラー「取り込める行がありません。空行と記号だけの行は取り込みません。」。

### 解析の結果の型（純関数）

```ts
// domain/outline/outlineParser.ts
export type OutlineItem = {
  label: string;               // 記号・前後の空白を除き、制御文字を半角空白にした値。空でない
  depth: number;               // 0 が一番上の階層。直前の項目の depth + 1 以下
  parentIndex: number | null;  // items の添字（自分より前）。depth 0 は null
  lineNumber: number;          // 1 始まりの入力の行番号
};

export type OutlineWarningKind = "depth-adjusted" | "empty-label" | "long-label";

export type OutlineWarning = {
  kind: OutlineWarningKind;
  count: number;               // 1 以上
  lineNumbers: number[];       // 先頭の5件まで（昇順）
};

export type ParsedOutline = {
  items: OutlineItem[];        // 入力の順（先行順）。1件以上 OUTLINE_MAX_ITEMS 件以下
  rootCount: number;           // depth 0 の件数
  maxDepth: number;            // depth の最大値
  warnings: OutlineWarning[];  // count が1以上のものだけ。種類の順は固定
};

export type OutlineParseError =
  | { kind: "too-long"; length: number }
  | { kind: "too-many-lines"; lines: number }
  | { kind: "no-items" };

export type OutlineParseResult =
  | { ok: true; outline: ParsedOutline }
  | { ok: false; error: OutlineParseError };

export function parseOutlineText(text: string): OutlineParseResult;
```

- `parseOutlineText` は入力を変えず、副作用を持たない。React のレンダー中には呼ばず、「プレビュー」ボタンのイベントの中で1回だけ呼ぶ（L-467）。
- 正規化（BOM・記号・制御文字・空白）は解析の中の1か所で行い、プレビューの表示、警告、挿入はすべてこの結果の `label` を使う。段階ごとに別の正規化をしない（L-136）。
- 中間の段階の型（`OutlineLine`: 行番号・`T`・`S`・分類・ラベル）はモジュールの間の受け渡しに使い、外へは公開しない。

## プレビューの表示

### 木の表示方法

- `buildOutlinePreview(outline, maxItems = 200)` が、`items` の先頭 `maxItems` 件から入れ子の木（`{ label, children }[]`）を作る。`items` は先行順で、親は常に自分より前にあるので、先頭の一部だけでも木として閉じる。
- 表示用のラベルは、先頭80コードポイントまでを表示し、それより長い場合は末尾に「…」を付ける（`OUTLINE_PREVIEW_LABEL_LENGTH = 80`）。全文は `title` に入れない（長いラベルで属性が巨大にならないようにする）。追加するノードのラベルは全文のまま。
- 表示は入れ子の `<ul>`。各 `<li>` はラベルの文字を持ち、子があれば中に `<ul>` を持つ。階層ごとに左の余白（`1rem`）を付ける。スクリーンリーダーでは、入れ子のリストとして階層が伝わる。`role="tree"` は使わない（読むだけで、選択や展開の操作が無いため）。
- 木は縦横にスクロールできる領域（`role="region"`、`aria-label="変換結果のプレビュー"`、`tabIndex={0}`、最大の高さは画面の高さの40%程度、`overflow: auto`）に入れる。キーボードだけでもスクロールできるようにするため、フォーカスを受け取れる領域にする。深い階層で横に長くなっても、ページ全体は横にスクロールしない。

### 件数

- 領域の上に要約を表示する: 「追加するノード: 1,234件（一番上の階層: 3件、最も深い階層: 5段目）」。段目は `maxDepth + 1`。
- 表示を `maxItems` 件で打ち切ったときは、木の下に「先頭の200件を表示しています（全1,234件）。」を表示する（L-160。一部だけであることを明示する）。全件を表示したときは出さない。

### 警告

- 要約の下に、警告を `<ul>` で並べる（「警告の種類と件数」の文言）。色だけで区別せず、文言の先頭に「注意:」を付ける（L-400）。
- 警告は画面の中の固定の内容で、ライブリージョンにはしない。プレビューの画面の `role="group"` の `aria-describedby` に要約と警告の要素の id を入れ、プレビューの画面に入ったときに読ませる（L-601）。

### 大きな入力のときの性能

- 解析は入力の文字数に比例する時間で終わる（行の分割、インデントの測定、`W` の計算、階層の判定のいずれも1回の走査か償却で線形）。正規表現は先頭への固定（`^`）だけを使い、後戻りが爆発する形を使わない。
- プレビューの DOM は最大200件に抑え、10,000件の入力でも描画するノードの数を増やさない。
- 解析は「プレビュー」ボタンを押したときに1回だけ行い、入力中には行わない。入力中に判定するのは文字数の上限だけ（`text.length` の比較）。
- テストは時間ではなく操作の回数で計算量を確かめる（L-431）。10,000行の深い鎖と、10,000行の兄弟だけの入力を使い、`levels` の操作の回数と挿入での配列の走査の回数が入力の定数倍以内であることを確かめる。

## 追加の仕様

### 追加する位置

| 追加先 | 選べるとき | 親子関係 |
| :--- | :--- | :--- |
| 新しいルート（既定） | いつでも | 深さ0の項目が新しいルートになる。ルートが複数あれば森として追加する |
| 選択中のノードの子 | ダイアログを開いた時点でノードを選択していたとき | 深さ0の項目が、そのノードの子になる。複数あればすべて同じ親の子（兄弟）になる |

- ダイアログを開いた時点の `selectedNodeId` を、ダイアログの状態として控える（追加先の候補）。ダイアログを開いている間は、エディタが `inert` でショートカットも止まるため、利用者の操作では選択は変わらない。
- ただし、開く前に始めた JSON 読み込み（ファイルの読み取り中）が、ダイアログを開いている間に終わると、マップが置き換わり、控えた親が無くなることがある。ダイアログを開いた時点の `documentRevision` も控え、子として追加する確定の時点で `documentRevision` が変わっていれば、親が無くなったものとして扱い、`insertForest` を呼ばずにエラー（「エラーと境界条件」）にする。置き換えた後のマップに同じ ID のノードがあっても、それは別のノードなので、ID が存在するかどうかだけでは判定しない（別のノードの子として黙って追加しないため。L-037）。revision が変わっていない場合も、`insertNodeForest` が最新のノード配列に親があるかを確かめる。黙って新しいルートへ変えない（L-002）。
- ダイアログを開いている間は、Undo・Redo・JSON 読み込みの開始・マップの切り替えが止まる（切り替えはエディタを作り直すので、フックの状態も消える）。そのため、この経路を通るのは、開く前に始めた JSON 読み込みが開いている間に終わる場合だけである。同じ ID が残る場合はフックの単体テストで `documentRevision` を変えて固定し、結合テストでは選択したノードの ID を含まない JSON で配線を確かめる。
- マップの置き換えの後に追加すると、置き換えた後のマップへ追加する（追加先は常に確定の時点の現在のマップ）。

### 森の扱い

- 新しいルートとして追加する場合、深さ0の項目ごとに1本の木になる。木の順序は入力の順。
- 既存のノード配列の後ろに、入力の順（先行順）で追加する。自動配置では、ルートと兄弟は配列の順に並ぶため、取り込んだ森は既存のすべての木の下に、入力の順で並ぶ。子として追加した場合は、既存の兄弟の後ろに並ぶ。

### ID の採番

- 挿入の関数は、検査（親の存在、座標の計算と有限性）をすべて済ませてから、`allocateIds(current, items.length)` を1回だけ呼ぶ。`useNodes` は既存の `applySubtreeInsertion` と同じく、allocator の `nextAvailableIds` を渡す（L-432）。
- 採番した ID は、項目の添字の順に割り当てる。親の ID は `ids[parentIndex]`、深さ0の項目の親は追加先（新しいルートなら `null`、子なら控えた親の ID）。
- 自動配置の再配置（`layoutNodeForest`）が失敗して確定しなかった場合、採番した ID は欠番のままにし、allocator を巻き戻さない（既存の複製・貼り付けと同じ）。

### 配置（手動）

追加するノードの寸法は既存の新規作成と同じ（幅100、高さ60）。

- **森の相対座標**: 取り込む項目から仮のノード（仮の ID は添字）を作り、`layoutNodeForest` で並べる。`layoutNodeForest` は先頭のルートの x・y をそのまま残し、2本目以降の木を前の木の下端から80px（`TREE_VERTICAL_GAP`）下に置き、深さごとの列を120px（`CHILD_HORIZONTAL_GAP`）間隔で並べる。
- **新しいルートとして追加**:
  1. 先頭のルートの左上を `(x0, 40)` に置いて森を並べる。`x0` は既存のノードの x の最小値（マップの左端）。空のマップでは `x0 = 40`。
  2. 既存の `calculateManualOffsetY` と同じ規則で、マップ全体の下端から40px（`SIBLING_VERTICAL_GAP`）空けた位置へ、森全体を真下へ平行移動する。空のマップでは移動しない（先頭のルートは (40, 40) に置かれる）。
- **選択中のノードの子として追加**:
  1. 基準の位置を、既存の子の追加（`createChildNode`）と同じ規則で求める。x は親の右（`parent.x + parent.width + 120`）、y は既存の子が無ければ `parent.y`、あれば既存の子の下端の最大値 + 40。
  2. 取り込む森を、仮の親（親と同じ寸法）の子として並べる（深さ0の項目の兄弟の間隔が、自動配置と同じ40pxになる）。仮の親は結果から除く。
  3. 先頭の項目の左上が基準の位置に来るように、取り込むノード全体を平行移動する。
  - 既存のノードと重なることがある（既存の子の追加と同じ）。
- 共通の規則を1か所にするため、`calculateManualOffsetY` を `nodeSubtreeInsertion.ts` から `nodeManualPlacement.ts` へ移して公開し、`createChildNode` の位置の計算も `calculateChildPlacement(nodes, parentId)` として切り出して、`createChildNode` と `insertNodeForest` の両方から使う（L-048）。切り出すときに `Math.max(...siblings.map(...))` をループに置き換える（L-529。子として10,000件を追加した後の親でも引数の上限に当たらないようにする）。
- 座標の計算は既存の `checkedAdd` などの検査付きの演算を使い、有限でない値や間隔を確保できない丸めが出たら `null` を返して追加しない（L-524）。

### 配置（自動）

- 取り込むノードには仮の座標を入れ（すべて (40, 40)）、`applyTreeChange` の中の `layoutNodeForest` に全体の再配置を任せる。
- 既存のノードがあるマップでは、全体の先頭のルートは既存のノードなので、仮の座標は使われない。空のマップでは、取り込んだ先頭のルートが (40, 40) に置かれる。
- 自動配置の失敗（`layoutNodeForest` が `null`）は、追加の失敗として扱う。

### insertNodeSubtree を拡張するか

**判断: 拡張せず、新しい関数 `insertNodeForest` を `domain/nodes/nodeForestInsertion.ts` に作る。**

理由:

1. `insertNodeSubtree` は、座標を持つ既存のノード（複製元・クリップボード）を受け取り、形を保って平行移動する関数で、結果も根が1つ（`rootId`）の型になっている。箇条書きには座標が無く、まず並べて座標を作る段階が要る。根を複数にすると、結果の型が変わり、複製と貼り付けの呼び出し元とテストの全体に影響する。
2. 子として追加するときの手動配置の規則（親の右、既存の兄弟の下）は、複製（真下への平行移動）とも貼り付け（新しいルートだけ）とも違う。拡張すると、`insertNodeSubtree` に追加先と配置の分岐が増え、既存の `SubtreeGeometryPolicy` と組み合わさって分岐の数が増える。
3. 共通にすべき部分（マップの下端からの平行移動、子の位置、`AllocateNodeIds` の型、ID を1回でまとめて採番する手順）は、共通の関数と型として切り出して両方から使うので、規則は1か所に保たれる。

```ts
// domain/nodes/nodeForestInsertion.ts
export type ForestItem = { label: string; parentIndex: number | null }; // parentIndex は自分より前の添字

export type ForestInsertionTarget =
  | { kind: "root" }
  | { kind: "child"; parentId: number };

export type ForestInsertionResult =
  | { ok: true; nodes: Node[]; rootIds: number[] }   // rootIds は深さ0の項目の新しい ID（入力の順）
  | { ok: false; reason: "parent-missing" | "invalid-items" | "placement-failed" };

// current は変更せず、current の後ろへ items の順で新しいノードを足した配列を返す。
// 自動配置の全体の再配置はここでは行わない（applyTreeChange が行う）
export function insertNodeForest(
  current: readonly Node[],
  items: readonly ForestItem[],
  target: ForestInsertionTarget,
  mode: NodeLayoutMode,
  allocateIds: AllocateNodeIds,
): ForestInsertionResult;
```

- `invalid-items`: `items` が空、最初の項目の `parentIndex` が `null` でない、`parentIndex` が負・自分以上の添字・整数でない、のいずれか。解析の結果からは起きないが、防御として検査し、採番の前に返す。
- `ForestItem` は `domain/nodes` で定義し、`domain/nodes` から `domain/outline` を参照しない。`OutlineItem` は `ForestItem` の形を満たすので、フックがそのまま渡す。
- 重要度は `DEFAULT_NODE_IMPORTANCE`（`"medium"`）、イラストは無し。

### useNodes の操作

```ts
type InsertForestResult =
  | { ok: true; rootId: number; count: number }
  | { ok: false; reason: "parent-missing" | "invalid-items" | "placement-failed" };

insertForest: (items: readonly ForestItem[], target: ForestInsertionTarget) => InsertForestResult;
```

- `applyTreeChange` を1回だけ呼ぶ。コールバックの中で `insertNodeForest` を呼び、失敗なら理由を控えて `null` を返す。`applyTreeChange` が `false` を返し、控えた理由が無い場合（自動配置の失敗）は `placement-failed` にする。
- 成功したら `rootIds[0]` を選択し、`{ ok: true, rootId, count: items.length }` を返す。`documentRevision` は増やさない（既存の追加・複製と同じ）。
- 履歴は1回の commit で、自動配置での既存ノードの再配置も同じ1操作に含まれる。失敗したときは、ノード・選択・履歴・Redo を変えない。

### 履歴を1回の commit にすること

- 取り込み全体（全ノードの追加と、自動配置での再配置）が Undo / Redo の1操作になる。1回の「元に戻す」で、取り込んだノードがすべて消え、自動配置で動いた既存のノードも元の位置に戻る。「やり直す」で、同じ ID・ラベル・座標のまま戻る。
- 1件ずつの追加の繰り返しにはしない（途中で失敗したときに一部だけが残り、Undo も件数分に分かれるため。L-063）。
- 履歴の上限（100操作）は変えない。1回の取り込みは1操作として数える。

### 追加後の選択

- 先頭のルート（新しいルートなら最初の木の根、子として追加したなら最初の子）を選択する。ルートが複数あるデータで、2本目以降の根を選ばないことをテストで確かめる（L-170）。
- ビューポートは動かさない。F キーで選択ノードへ移動できる。
- 子として追加した親が折りたたまれていた場合は、追加に成功したときだけ親を展開する（Tab キーでの子の追加の `addChildNodeExpanding` と同じ結果）。呼ぶのは `useOutlineImport` の `submit` だけで、`insertForest` が成功を返した後に `expandNodes([parentId])` を呼ぶ。追加に失敗したときは呼ばない。

### 通知の文言

| 場面 | 場所 | 種類 | 文言 |
| :--- | :--- | :--- | :--- |
| 追加の成功 | 操作通知バー（7系統目） | status | N件のノードを追加しました。Fキーで選択ノードへ移動できます。見えない場合は表示を『すべて』に切り替えてください。 |
| 親が見つからない | ダイアログ内 | error | 選択していたノードが見つからないため、追加できませんでした。「新しいルートとして追加」を選び直してください。 |
| 配置できない・不正な項目 | ダイアログ内 | error | ノードを追加できませんでした。マップは変わっていません。 |
| 文字数の上限 | 入力欄の下 | error | テキストが長すぎます（1,000,000文字以内）。（現在の文字数「現在 N 文字」はライブリージョンの外に別に表示する） |
| 行数の上限 | 入力欄の下 | error | 行が多すぎます（空行を除いて10,000行以内）。現在 N 行です。 |
| 取り込める行が無い | 入力欄の下 | error | 取り込める行がありません。空行と記号だけの行は取り込みません。 |

- N は `toLocaleString("en-US")` で桁区切りを付ける。上限の数値は定数から組み立てる（上限を変えたときに文言だけが古いまま残らないようにする）。
- 成功の通知の後半は、既存の貼り付けの通知（`useMapClipboardEvents.ts` の `PASTE_SUCCESS`）と同じ案内にする（L-161）。取り込んだノードの重要度は `"medium"` なので、表示が「高のみ」のときなどは見えないことがあるため。
- 成功の通知は `useRevisionScopedNotice(documentRevision)` で持ち、次の取り込みの成功か、`documentRevision` の変化（Undo / Redo、マップの置き換え）で消える。既存の6系統とは独立した枠で表示し、互いに消さない。
- 失敗はダイアログを開いたまま終わるので、ダイアログ内の通知に出し、操作通知バーには出さない（同じ結果を2か所に出さない。L-249）。ダイアログを開いている間はエディタが `inert` で、操作通知バーは支援技術から隠れるため。

### ダイアログの画面と状態

`useOutlineImport`（`hooks/useOutlineImport.ts`）が状態と操作を持つ。引数と戻り値の型は次のとおり。引数はすべて必須にする（L-060）。

```ts
type UseOutlineImportOptions = {
  selectedNodeId: number | null;      // open の時点の値を追加先の候補として控える
  documentRevision: number;           // 成功の通知を useRevisionScopedNotice で持つためと、親の候補が古くなったかの判定（parentCandidateStale）のため
  insertForest: (items: readonly ForestItem[], target: ForestInsertionTarget) => InsertForestResult; // useNodes の操作
  expandNodes: (nodeIds: readonly number[]) => void; // useBranchCollapse の操作
};

type OutlineImportScreen = "closed" | "input" | "preview";

type OutlineInputError = {
  sequence: number;                   // エラーを出すたび（同じ文言でも）進める。消すときも進める
  message: string | null;             // 入力欄の下の常設の欄に出す文言。null なら空
};

type UseOutlineImportReturn = {
  screen: OutlineImportScreen;
  text: string;                       // 閉じても残す。追加の成功で "" にする
  textLength: number;                 // text.length。文字数の表示に使う
  inputError: OutlineInputError;
  outline: ParsedOutline | null;      // preview の画面のときだけ null でない
  preview: OutlinePreview | null;     // buildOutlinePreview の結果。outline と同時に作る
  parentCandidateId: number | null;   // 開いた時点の selectedNodeId
  parentCandidateStale: boolean;      // 開いた時点の documentRevision から変わったか。true なら親は無くなったものとして扱う
  target: "root" | "child";           // 開くたびに "root" に戻す
  dialogNotices: { sequence: number; status: string | null; alert: string | null }; // ダイアログ内の通知
  focusRequest: "input" | "preview" | "header" | null; // 次に当てるフォーカス。当てたら consumeFocusRequest で消す
  notice: OperationNotice | null;     // 操作通知バーの7系統目（成功の通知）
  open: () => void;                   // closed → input
  close: () => void;                  // input → closed（キャンセル、Escape）
  setText: (text: string) => void;
  requestPreview: () => void;         // 解析して preview へ。失敗なら inputError を出す
  back: () => void;                   // preview → input（「戻る」、Escape）
  setTarget: (target: "root" | "child") => void;
  submit: () => void;                 // 「マップに追加」
  consumeFocusRequest: () => void;
};

export function useOutlineImport(options: UseOutlineImportOptions): UseOutlineImportReturn;
```

- `selectedNodeId`・`insertForest`・`expandNodes` は `useLayoutEffect` で同期する ref から読み、`open` と `submit` の参照を変えない（L-521）。
- `submit` は、`target` が `"child"` で `parentCandidateStale` が `true`（または `parentCandidateId` が `null`）なら、`insertForest` を呼ばずに「親が見つからない」の失敗にする。それ以外で `target` が `"child"` なら `{ kind: "child", parentId: parentCandidateId }`、それ以外は `{ kind: "root" }` を作って `insertForest` を1回呼ぶ。成功したら、子として追加した場合に限り `expandNodes([parentId])` を呼び、成功の通知を出し、テキストを空にして閉じ、`focusRequest` を `"header"` にする。失敗したら `dialogNotices` に理由を出し、画面とフォーカスを変えない。
- **親の展開を呼ぶのは `useOutlineImport` の `submit` だけ**にする。`useNodes.insertForest` は展開を知らない（折りたたみの状態を持つのは `useBranchCollapse` で、`useNodes` は持たないため）。`MapEditor` は `branchCollapse.expandNodes` をそのまま渡すだけで、`addChildNodeExpanding` のような包む関数は作らない。
- 親の候補のラベル（プレビューの画面の選択肢に出す）は、`MapEditor` が `nodes` と `parentCandidateId` から `getNodeDisplayLabel` で作ってダイアログへ渡す。フックはノード配列を持たない。

`components/layout/OutlineImportDialog.tsx` は Phase 12 の `MapLibraryDialog` と同じ骨組みにする。

- オーバーレイ（`fixed inset-0`、半透明の黒）の中に、`role="dialog"`、`aria-modal="true"`、`tabIndex={-1}`、固定の名前 `aria-label="箇条書きから追加"` の要素を置く。最大幅は `36rem`（入力欄を広く取るため）、画面の高さを超えるときはダイアログの中を縦にスクロールする。
- 各画面の中身を `role="group"` で包み、`aria-labelledby` で画面の見出しを指す。プレビューの画面では `aria-describedby` で要約と警告を指す。group は画面ごとに `key` を変えて作り直す（L-601）。
- ダイアログの下側に、`role="status"` と `role="alert"` の要素を空のまま常設し、文言だけを差し替える（L-153）。`useReannouncedNotice(dialogNotices.sequence, dialogNotices)` で、同じ文言の失敗が続いても読み上げられるようにする（L-166）。閉じたら通知を消す。
- オーバーレイの `onClickCapture` で、`event.detail > 0` のクリックの時刻を `dialogMouseClickedAtRef` に控える（`MapEditor` が props で受け取っている、シェルと同じ ref）。

**テキスト入力の画面**（見出し「箇条書きのテキスト」）

- 説明文: 「1行を1つのノードにします。行頭の空白（タブ・半角スペース・全角スペース）の深さで親子を決めます。行頭の「- * + ・ •」と「1.」「1)」は取り除きます。空行は無視します。」
- `<label>`「テキスト」付きの `<textarea>`（12行程度、幅いっぱい、`spellCheck={false}`）。`placeholder` だけに頼らず、ラベルを見える文字で置く（L-554）。`aria-describedby` で説明文と、エラーがあればエラーを指す。
- 入力のエラーは、入力欄の下に最初から常設する `role="alert"` の欄（文言が無いときは空）に出す。条件付きで要素を挿入したり、key で作り直したりしない（L-153）。エラーがある間だけ、入力欄に `aria-invalid="true"` を付け、`aria-describedby` にこの欄の id を加える（L-057）。
  - 欄の文言は `useReannouncedNotice(inputError.sequence, inputError.message)` で出す。`sequence` が変わるたびに一度空にし、次のフレームで入れ直すので、同じエラーが続いても読み上げられる（L-166）。
  - `sequence` を進めるのは、(1) 「プレビュー」を押して、解析のエラー（文字数・行数・取り込める行が無い）になったとき（前回と同じエラーでも進める）、(2) 入力中に、文字数の上限を超えていない状態から超えた状態へ変わったとき、(3) エラーを消すとき（上限を超えた状態から戻ったとき、または解析のエラー（行数が多すぎる、取り込める行が無い）が出た後にテキストを変えたときに限る）。入力のたびには進めない。テキストを変えたときの欄の文言は、上限を超えていれば文字数のエラー、超えていなければ null とし、文言が変わったときだけ sequence を進める。
  - 文字数の上限のエラーの文言は「テキストが長すぎます（1,000,000文字以内）。」とし、入力のたびに変わる現在の文字数は、ライブリージョンの外の別の欄（「現在 1,000,123 文字」。上限を超えている間だけ表示）に出す。1文字ごとに読み上げが続かないようにするため。
  - 行数の上限と「取り込める行が無い」のエラーは「プレビュー」を押したときに出し、テキストを変えたら消す。
- `maxLength` 属性は使わない（貼り付けた内容が黙って切り詰められるため。L-057）。
- ボタン: 「プレビュー」と「キャンセル」。どちらも無効にしない（L-157）。エラーがあるときに「プレビュー」を押すと、画面を変えずにエラーを表示する。

**プレビューの画面**（見出し「変換結果の確認」）

- 要約、警告、プレビューの領域（「プレビューの表示」）。
- 追加する位置:
  - 開いた時点でノードを選択していた場合は、`<fieldset>`（`<legend>`「追加する位置」）に2つのラジオボタン「新しいルートとして追加」（既定で選択）と「選択中のノード「<ラベル>」の子として追加」を置く。ラベルは `getNodeDisplayLabel` の値（空なら「新しいノード」）の先頭40コードポイント。親が見つからない場合は「選択していたノードの子として追加」と表示する（選べるままにし、確定時にエラーを出す）。
  - 選択していなかった場合は、「新しいルートとして追加します。」と表示する（ラジオボタンは置かない）。
- ボタン: 「マップに追加」と「戻る」。

| 操作 | 画面の遷移 |
| :--- | :--- |
| ヘッダーの「箇条書きから追加」 | closed → input（`parentCandidateId` を控え、`target` を `"root"` に戻す。`text` は前回の値のまま） |
| 「プレビュー」（解析が成功） | input → preview |
| 「プレビュー」（解析が失敗） | input のまま、エラーを表示 |
| 「戻る」、プレビューの画面での Escape | preview → input（テキストはそのまま。解析の結果は捨てる） |
| 「キャンセル」、入力の画面での Escape | input → closed（テキストは残す） |
| 「マップに追加」（成功） | preview → closed（テキストを空にし、操作通知バーに成功の通知を出す） |
| 「マップに追加」（失敗） | preview のまま、ダイアログ内にエラーを出す |

### キーボード

- Tab と Shift+Tab はダイアログの中で循環する（`useDialogFocusTrap`）。テキスト入力欄の中でも Tab はインデントを入力せず、次の要素へ移る（ユーザーの決定4）。インデントを入れたいときは、全角・半角スペースを入力するか、別のエディタで作ったテキストを貼り付ける。説明文にはこの案内を書かない（タブを含むテキストの貼り付けはそのまま使えるため）。
- テキスト入力欄の中の Enter は改行を入力する（送信しない）。Ctrl/Cmd+Enter などの送信のショートカットは作らない。
- テキスト入力欄の中の Ctrl/Cmd+V・C・Z はブラウザの既定の動作（テキストの貼り付け・コピー・取り消し）のまま。エディタの枝の貼り付けは、ダイアログを開いている間は `enabled: false` で止まり、入力欄では元々ブラウザに任せている。
- ラジオボタンは矢印キーで切り替わる（ブラウザの既定の動作）。

### フォーカスとその戻し先

開いたときと画面が変わったときのフォーカスは、描画の後に `useLayoutEffect` で当てる。`autoFocus` は使わない（L-584）。

| 場面 | フォーカスの行き先 |
| :--- | :--- |
| 開いたとき、プレビューから戻ったとき | テキスト入力欄（カーソルは末尾。全選択はしない） |
| プレビューの画面に移ったとき | プレビューの領域（`tabIndex={0}` の `role="region"`）。「マップに追加」には当てない（下の「押し続け」） |
| 閉じたとき（キャンセル、Escape、追加の成功） | ヘッダーの「箇条書きから追加」ボタン |
| 失敗（解析のエラー、追加の失敗） | 画面とフォーカスを変えない |

- 閉じたときの戻し先は、`focusRequest: "header"` を状態に入れ、`MapEditor` の `useLayoutEffect` でボタンの `ref` へフォーカスしてから要求を消す。閉じる描画で根の `inert` が外れた後に当たる（L-155）。
- ダイアログのボタンと入力欄は、既存のダイアログと同じフォーカスリングを表示する。

### aria

| 要素 | 属性 |
| :--- | :--- |
| ヘッダーのボタン | `aria-haspopup="dialog"`、`aria-expanded` |
| ダイアログ | `role="dialog"`、`aria-modal="true"`、`aria-label="箇条書きから追加"`、`tabIndex={-1}` |
| 画面 | `role="group"`、`aria-labelledby`（見出し）、プレビューでは `aria-describedby`（要約・警告） |
| テキスト入力欄 | `<label>` と関連付け、`aria-describedby`（説明文・エラー）、エラー時は `aria-invalid="true"` |
| 入力のエラー | 常設の `role="alert"`（`aria-live="assertive"`）。`useReannouncedNotice` で入れ直す |
| プレビューの領域 | `role="region"`、`aria-label="変換結果のプレビュー"`、`tabIndex={0}` |

### Escape

- `useDialogFocusTrap` の window の `keydown`（capture）で受ける。フォーカスがどこにあっても効く。
- IME の変換中（`isComposing` または `keyCode === 229`）と押し続け（`event.repeat`）では何もしない（既存のフックの挙動）。変換中の Escape は、変換の取り消しとしてブラウザに任せる。
- 入力の画面ではダイアログを閉じる。プレビューの画面では入力の画面へ戻る（Phase 12 の「画面を開いた元へ戻る」と同じ考え方）。
- 背景（オーバーレイ）のクリックでは閉じない（L-158）。

### IME

- テキスト入力欄の Enter は改行なので、変換の確定の Enter と送信が衝突しない。
- テキスト入力欄の `keydown` で Enter を扱う処理（下の押し続けの対策）は、`isComposing` または `keyCode === 229` のときは何もしない（L-474）。
- Escape と Tab は、変換中は `useDialogFocusTrap` が処理しない。

### 押し続け

- ヘッダーのボタン: `event.repeat` の Enter・Space を `preventDefault` する。
- テキスト入力欄: `event.repeat` の Enter を `preventDefault` する（変換中を除く）。ヘッダーのボタンで押し続けた Enter のリピートが、開いた直後の入力欄に空行を入れ続けないようにする。空行は解析で無視されるので害は小さいが、Phase 12 の入力欄と同じ扱いにそろえる。
- 「プレビュー」: `event.repeat` の Enter・Space を `preventDefault` する。プレビューの画面では最初のフォーカスをプレビューの領域に当てるので、押し続けたリピートが「マップに追加」へ届かない。
- 「マップに追加」: `event.repeat` の Enter・Space を `preventDefault` する。確認を飛ばして追加しないための二重の守り（L-408）。
- 「戻る」「キャンセル」: 押し続けても害が無い（画面が戻るか閉じるだけで、閉じた後の戻り先のヘッダーのボタンはリピートを止めている）ので、止めない。

### ダブルクリック

- 「プレビュー」「戻る」をダブルクリックすると、1回目で画面が変わり、2回目のクリックが次の画面の同じ位置の別の要素に届くことがある（プレビューの画面の追加先のラジオのラベル、入力の画面の「キャンセル」など。ラジオのラベルは幅いっぱいがクリックできる範囲で、`click` の `detail` によらずラジオを選ぶ）。ダイアログのオーバーレイの `onClickCapture` で、`event.detail > 1` の `click` を `preventDefault` と `stopPropagation` で止め、ダイアログの中のどの要素にも届けない。`preventDefault` した `click` ではラベルによるラジオの選択も起きない。同じ `onClickCapture` は、止める前にクリックの時刻（`onMouseClick`）を控える。キーボードによるクリック（`detail` が 0）とマウスの1回目（`detail` が 1）は通す。
- 「マップに追加」も、自身の `click` で `event.detail > 1` を無視する（二重の防御。オーバーレイの判定が外されても、確認を飛ばした追加は起きない）。
- 「マップに追加」「キャンセル」のダブルクリックでは、1回目でダイアログが閉じ、2回目はキャンバスへ届く。オーバーレイの `onClickCapture` で控えた時刻を使い、`MapStage` が 500ms 以内の `dblclick` を無視する（既存の仕組み。ノードの追加とラベルの編集を始めない。L-150）。
- 既知の挙動（Phase 12 と同じ）: 2回目のクリックの `pointerdown` はキャンバスへ届くため、選択は変わることがある。追加の直後に選択した先頭のルートが、空き領域のクリックで選択から外れる場合がある。
- ヘッダーのボタンのダブルクリックは、1回目で開き、2回目はオーバーレイかダイアログの中に届く。オーバーレイの `pointerdown`・`mousedown` は止めているので、閉じない。

### inert とショートカットの停止

- `MapEditor` に `const editorShortcutsEnabled = shortcutsEnabled && outlineImport.screen === "closed";` を作る。
- 今 `shortcutsEnabled` を渡している次のすべてに、代わりに `editorShortcutsEnabled` を渡す（L-061。入口を一部だけ塞がない）。
  - `MapEditor` の根の `inert={!editorShortcutsEnabled}`
  - `useMapHistoryShortcuts`（Undo / Redo）
  - `MapStage` の `shortcutsEnabled`（その先の `useNodeKeyboardShortcuts`、`useMapViewportShortcut`、`useMapClipboardEvents`、`useNodeContextMenu` → `useNodeContextMenuDismissal`）
- ダイアログは根の `<div>` の兄弟として、`MapEditor` が返すフラグメントの中に描く。根に `inert` が付いても、ダイアログは操作できる。
- シェルの「マップ一覧」「新しいマップ」ボタンはエディタのヘッダーの中にあるため、取り込みのダイアログを開いている間は `inert` で押せない。逆に、マップのダイアログを開いている間は「箇条書きから追加」も押せない。2つのダイアログが同時に開くことは無い。
- ダイアログを開くと、ラベルの編集中の入力欄は `inert` の中に入る。編集はボタンを押した時点の `blur` で確定済みなので、入力が失われることはない。
- テストは、各フックの `enabled: false` の単体テスト（Phase 12 で追加済み）に加えて、`Home` からの結合テストで、取り込みのダイアログを開いている間に body へフォーカスを置いて Ctrl/Cmd+Z・Delete・Tab・Enter・`F`・コピー・貼り付けを送っても、マップと選択が変わらないことを1つずつ確かめる（L-173）。

## エラーと境界条件

| 条件 | 扱い |
| :--- | :--- |
| 空の入力、空行と記号だけの行しかない | 入力の画面でエラー「取り込める行がありません。…」。プレビューへ進まない |
| 1,000,001文字以上 | 入力のたびにエラーを表示。「プレビュー」を押しても解析しない |
| 空行を除いて10,001行以上 | 「プレビュー」を押したときにエラー。ラベルの取り出しと階層の判定はしない |
| ちょうど1,000,000文字・10,000行 | 受け付ける |
| 1行目がインデントされている | 0段として扱う。警告しない |
| 1行目より浅い行 | 0段にし、補正として警告する |
| 段が飛んでいる・どの段にも合わない | 補正し、警告する |
| 記号だけの行 | 取り込まず、警告する |
| 200文字を超える行 | そのまま取り込み、警告する |
| `#` で始まる行 | そのままラベルにする |
| タブとスペースの混在 | タブは `W` 文字分として数える |
| 制御文字を含む行 | 半角空白に置き換える |
| 先頭の BOM | 取り除く |
| ゼロ幅スペースだけの行 | 見た目が空のノードとして取り込む |
| 深い鎖 | 受け付ける。反復で処理し、スタックの上限に当たらない。テキストで書ける深さは、文字数の上限のためタブで最大1,412段 |
| 子として追加する親が、確定時に無い | ダイアログ内にエラー。マップ・選択・履歴は変わらない |
| 手動配置で座標が有限でなくなる・間隔を確保できない | ダイアログ内に「ノードを追加できませんでした。…」。何も変わらない |
| 自動配置の失敗 | 同上。採番した ID は欠番になりうる |
| ダイアログを開いている間に JSON 読み込みが終わる | 置き換わったマップに追加する。子として追加する場合は、開いた時点から `documentRevision` が変わっていればエラー（同じ ID のノードがあっても追加しない） |
| 取り込み後の自動保存の容量不足 | 既存の自動保存の失敗の通知を出す。取り込みは成功のまま（履歴に残る） |
| 取り込んだノードが表示フィルターで隠れる | 成功の通知の「表示を『すべて』に切り替えてください」で案内する |
| 同じ内容の取り込みを2回 | 2回とも追加する（重複の検出はしない）。Undo は1回ずつ戻す |
| 成功の通知が同じ文言で続く | 既存の複製・貼り付けの通知と同じく、文言が同じだと読み上げられないことがある（既知の制限。操作通知バーの表示は変える範囲が広いので今回は変えない） |
| 大きなマップへの追加 | マップ全体のノード数には上限を設けない。描画と自動配置の時間は既存の機能と同じく増える |

## 既存の操作との関係

| 既存の操作 | 関係 |
| :--- | :--- |
| 枝の貼り付け（Ctrl/Cmd+V） | 変えない。普通の文章は今までどおり無効の通知。ダイアログの入力欄での貼り付けはテキストの貼り付けになる |

## 受け入れ基準

1. ヘッダーの「箇条書きから追加」でダイアログが開き、テキストを入れて「プレビュー」を押すと、変換結果の木、件数、警告が表示される。
2. 例の表のすべての入力が、表の木と警告になる（単体テスト）。CRLF・CR・LF の混在と先頭の BOM で結果が変わらない。
3. 1,000,000文字と10,000行は受け付け、1,000,001文字と10,001行はエラーになってプレビューへ進めない。
4. プレビューは200件を超えると先頭の200件だけを表示し、全件数を明示する。
5. 「マップに追加」で、手動配置では新しいルートがマップの下端から40px下に、子はその親の右・既存の子の下に置かれる。自動配置では全体が並べ直され、取り込んだ森は既存の木の下に入力の順で並ぶ。
6. ノードを選択して開いたときだけ「子として追加」を選べ、深さ0の項目がすべてその子になる。閉じた親は展開される。
7. 追加の後、先頭のルートが選択され、操作通知バーに成功の通知が出て、フォーカスがヘッダーのボタンに戻る。F キーで移動できる。
8. 1回の「元に戻す」で取り込んだノードがすべて消え、自動配置で動いた既存のノードも元の位置に戻る。「やり直す」で同じ ID・座標で戻る。
9. 失敗（親が無い、配置できない）では、ダイアログが開いたまま理由が表示され、マップ・選択・履歴は変わらない。
10. ダイアログはキーボードだけで操作でき、Tab の循環（入力欄の Tab は次の要素へ移る）、Escape（変換中は無視）、最初のフォーカス、戻し先が「UI」の節のとおりに動く。ダイアログを開いている間は、キャンバスとエディタのショートカットが動かない。
11. ボタンの押し続けとダブルクリックで、確認を飛ばして追加したり、閉じた後のキャンバスにノードを追加したりしない。
12. 保存形式・JSON・履歴の形式は変わらない。
13. `npm run verify` が成功する。`docs/specifications/features.md`、`docs/specifications/data-model.md`、`docs/architecture/overview.md`、`docs/testing/browser-test-cases.md`、`ROADMAP.md` が実装に合っている。

## テスト

### 追加するテストの観点

- 純関数（`domain/outline/`）:
  - 例の表の全行を `parseOutlineText` のテストに1例1テストで写す。段階ごとの関数のテストは、その段階に関係する列だけを、関係する例について写す（行の分割: 例 2、3、12、13、15、23。ラベル: 例 1、4、5、6、7、16、19、20。階層: 例 1、2、3、4、8、9、10、11、14、18、21、22）。
  - 改行: CRLF・CR・LF の混在、`\r\n` を1つの改行と数えること、U+2028 で分割しないこと、末尾の改行。多数派の改行に置き換える変異や `split("\n")` への変異で落ちる入力にする（L-167）。
  - インデント: `W` の決定（下駄のある入力、増分が1つも無い入力、最も多い増分が1つに決まる入力と同数で並ぶ入力、タブだけの入力、タブと空白の混在）、全角スペースの幅、ノーブレークスペースをインデントとして数えないこと。
  - 記号: 各記号の取り除く・取り除かない境界（後ろの空白の有無、行末、`3.14`、10桁の数字、全角数字、`#`）、1つだけ取り除くこと。
  - 階層: 表の3つの場合（一致・深い・揃える）と、揃える場合の内訳（段の間、最初の段より浅い、同じ段の値の間）それぞれ。揃えた後に同じインデントの行が兄弟になり警告が出ないこと（例22）、警告が不揃いな行にだけ出て正しい行に出ないこと（例8・21）、段の不変条件、「深さが直前 + 1 以下」の不変条件。揃えた段の `values` に `v` を加えない変異（例22の D に警告が出て落ちる）、警告を最小の増分で判定する変異で落ちることを確かめる（L-167）。
  - 上限: 文字数・行数の「ちょうど」と「1つ超え」（例23〜25）、空白・制御文字だけの行を行数に数えず記号だけの行を数えること、行数の判定と空行の判定が同じ `isBlankOutlineRest` を使うこと、行数の判定が記号の除去より前に行われること（行数の超過で `extractOutlineLabel` が呼ばれない）。
  - 警告: 行番号が5件で打ち切られ「ほか」が付くこと、件数はすべて数えること、200と201コードポイント（サロゲートペアを含む）の境界。
  - 計算量: 10,000段の鎖と10,000件の兄弟で、操作の回数が入力の定数倍以内（L-431）。10,000段の鎖は文字数の上限を超えるため、段を決める関数（`assignOutlineDepths`）の単体テストで確かめ、`parseOutlineText` では上限に収まる最も深い鎖（タブで1,412段）を確かめる。
  - プレビュー: 200件の打ち切り（199・200・201件）、打ち切った一部も木として閉じること、80コードポイントの切り詰め。
- `insertNodeForest`:
  - 新しいルート・子、手動・自動、空のマップ・既存のマップの組み合わせ。複数のルートがあるデータで `rootIds` の順序と親の対応を確かめる（L-170）。
  - 手動の座標: マップの左端と下端からの位置、仮の親の下に並べたときの兄弟の間隔、`createChildNode` と同じ基準位置。
  - `allocateIds` を1回だけ、検査の後に呼ぶこと（親が無い・不正な項目・座標の失敗では呼ばない）。同じ値を返し続ける生成器でも ID が重ならないこと（L-432）。
  - 有限でない座標で `placement-failed` になること（L-524）。
  - `current` を変更しないこと。
- 共通の関数: `calculateManualOffsetY` と `calculateChildPlacement` を移した後も、複製・貼り付け・子の追加の既存のテストがそのまま通ること。兄弟が多い場合にスプレッドを使わないこと。
- `useNodes.insertForest`: 1回の commit（1回の Undo ですべて消え、Redo で同じ ID と座標で戻る）、成功時の選択、失敗時にノード・選択・履歴・Redo が変わらないこと、自動配置の失敗を `placement-failed` として返すこと。
- `useOutlineImport`: 開いた後に `documentRevision` が変わると、同じ ID の親があっても子としての追加が「親が見つからない」になり `insertForest` が呼ばれないこと（L-037）、画面の遷移の表の各行、テキストが閉じても残り成功で空になること、開くたびに `target` が `"root"` に戻ること、`parentCandidateId` を開いた時点で控えること、通知の `sequence`。
- 部品: 入力のエラーの欄が最初から常設され（エラーが無いときも要素があり中身が空）、エラーの間だけ `aria-invalid`・`aria-describedby` が付くこと。同じエラーで2回「プレビュー」を押すと、欄が一度空になってから同じ文言が入り直すこと（L-153、L-166）。文字数の上限を超えたまま入力を続けても、欄の文言が入れ直されないこと。プレビューの group の名前と説明（L-601）、ラジオボタンの有無、IME の変換中の Enter で何もしないこと。
- 押し続けとダブルクリック（L-408）:
  - 押し続けは `fireEvent.keyDown(button, { key: "Enter", repeat: true })`（Space も同様）で送り、`defaultPrevented` が真になること、追加・画面の遷移が起きないことを確かめる。`repeat: false` の keyDown では止めないことも確かめる（ヘッダーのボタン、テキスト入力欄の Enter、「プレビュー」、「マップに追加」のそれぞれ）。
  - 「マップに追加」は、`fireEvent.click(button, { detail: 2 })` では追加しないこと、`fireEvent.click(button, { detail: 1 })` と、キーボードでの操作にあたる `fireEvent.click(button, { detail: 0 })` では追加できることを確かめる。`detail` の判定を `> 0` に変える変異で、`detail: 0` のテストが落ちるようにする。
  - ダイアログ: プレビューの画面で、追加先のラベルへの `fireEvent.click(label, { detail: 2 })` では `onTargetChange` を呼ばず、`detail: 1` と `detail: 0` では呼ぶこと。「キャンセル」「戻る」への `detail: 2` では `onCancel`・`onBack` を呼ばないこと。`detail: 2` でも `onMouseClick` は呼ぶこと。
  - 結合テスト: ノードを選択して開き、「プレビュー」への `detail: 1` に続けて子の側のラベルへ `detail: 2` を送っても、追加先が「新しいルート」のままであること。「戻る」の `detail: 1` に続けて「キャンセル」へ `detail: 2` を送っても閉じないこと。
- 結合テスト（実際の `Home` から。L-060）: ボタンで開く → 入力 → プレビュー → 追加 → ノード・選択・通知・フォーカス、子として追加と閉じた親の展開、Undo / Redo、ダイアログを開いている間のショートカットの停止（各ショートカットごと。L-173）、Escape と戻し先、Tab の循環（入力欄の Tab が次の要素へ移ること）、閉じた直後の `dblclick` を無視すること。フォーカスの確認は `userEvent` で行い、effect の完了を待つ（L-177、L-183）。
