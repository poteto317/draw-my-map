# Phase 14「ノードだけ削除」設計

作成日: 2026-11-01
対象: ROADMAP.md Phase 14、候補017
状態: featureフローに基づくエージェント判断。設計確認の質問を挟まず、独立レビュー後に実装計画へ進む。

## 目的と範囲

中間の見出しが不要になったとき、そのノード1個だけを取り除き、残した子を元の親へつなぎ直す。既存の Delete / Backspace による「対象と枝全体の削除」は維持する。新しい操作名は「ノードだけ削除」とし、枝の削除やマップ削除と区別する。

対象は現在表示されている実在ノード1個。葉、子を持つノード、ルート、折りたたんだノードを扱う。複数選択、削除確認ダイアログ、右クリックメニューの再設計、他マップの編集、保存形式の変更は対象外。

## 既存実装と制約

- `useNodes.deleteNode` は最新の全ノードから `collectSubtreeIds` を求め、枝全体を削除する。削除対象の選択は解除する。
- `useNodeLayoutState.applyTreeChange` は最新状態・最新配置モードで候補を計算し、自動配置に成功してから履歴へ1回だけcommitする。手動では候補をそのまま確定する。
- `treeChangeOutcome.applyTreeChangeWithOutcome` は候補計算の失敗と、候補計算後の自動配置失敗を呼び出し元へ返す既存の境界。
- ノードの兄弟順は全ノード配列の相対順が正本。配列は深さ優先順や「親の後に子が連続する順」とは限らない。`parentId` で構造を決める。
- `indexNodeForest` はID重複、欠けた親、循環、非有限座標、非正の寸法を拒否する。再帰を増やさず、既存の反復走査を利用する。
- 操作ボタンは `MapEditor` の `AppHeader.operationControls` にあり、親挿入などの構造編集通知は `treeEditNotice` を共有する。
- 折りたたみ・解像度表示は保存データとは別。`useBranchCollapse` は消えたIDを正規化で除く。通常編集は `documentRevision` を変えず、Undo / Redo / マップ置換でのみ進む。
- 全返答・説明・通知は日本語。実装は計画タスクごとに別サブエージェント、仕様レビューと品質レビューも実装者とは別。TDDと最終 `client/npm run verify` を必須とする。

## Approaches

以下の採用判断はユーザーが個別に選んだものではなく、featureフローで委ねられたエージェント判断。

1. **純粋関数で候補全体を作り、一度だけ確定する（採用）**。配列上の対象位置を子の並びで置き換え、直下の子の `parentId` だけを変更する。最新状態・Undo・配置失敗の扱いを既存の構造編集とそろえられる。
2. 子を1個ずつ階層上げしてから既存削除を呼ぶ。既存機能を流用できるが、子の数だけ履歴が増え、途中失敗・順序反転・隠れた子の除外を防ぐ特別処理が必要。採用しない。
3. 全体を深さ優先配列に正規化してから対象を取り除く。書きやすいが無関係な配列順と兄弟順を変える危険があり、今回の範囲を広げる。採用しない。

入口は既存ヘッダーへ単独ボタンを追加する。右クリックメニューはイラスト操作専用の小さい構成であるため今回は拡張しない。新規ショートカットは追加しない。既存削除は修飾キー付きDelete / Backspaceも拾うため、Alt+Deleteなどを追加するより衝突を避けられ、TabとEnter/Spaceで新ボタンを使える。

## 構造と順序の契約

対象を T、元の親を P、全配列から列挙した直下の子を C1…Cn とする。

1. 全配列上で T と `parentId === T.id` の要素を除き、T があった位置へ C1…Cn をこの順で挿入する。挿入した子はそれぞれ `parentId = T.parentId` とする。
2. P の子が `[A, T, B]` なら操作後は `[A, C1, …, Cn, B]`。T がルートならルート一覧のTの位置へC1…Cnを挿入し、全て `parentId = null` とする。
3. T が葉ならTだけを除く。唯一のノードなら空マップになる。
4. 直下の子以外の `parentId` は変更しない。孫以降を平坦化せず、各子の枝を保持する。
5. 直下の子同士、各子の配下、無関係な兄弟・ルートの相対順を保持する。元から配列の別位置にある子も重複させず1回だけ挿入する。
6. ノード数は必ず1減る。IDの生成・再採番は行わない。残る全ノードのlabel、importance、illustrationの有無と内容、width、height等を保持する。手動配置ではx/yも保持する。変更はオブジェクトのspreadを基本とし、保存projectionによる作り直しをしない。
7. 表示配列を構造更新へ渡さない。折りたたみ・解像度により隠れた全ての子・子孫を同じ規則で保持する。

例: `P → T → {C1 → G, C2}` は `P → {C1 → G, C2}` になる。根Tの削除でもGはC1の子のまま。

## 配置と原子性

### 手動配置

残る全ノードの座標を動かさない。親子の線だけをつなぎ直す。自動で左や上に詰めると利用者の手動配置を壊すため、空間の余白や線の交差は許容する。この判断はエージェント判断。

入力の森を `indexNodeForest` で検証してから候補を作る。構造が不正なら `invalid-structure`、数値・寸法による配置不能なら `placement-failed` とする。分類のため必要最小限のgeometry検証を先に行い、森の検証実装を複製しない。失敗では入力・選択・履歴・保存対象が一切変わらない。

### 自動配置

構造候補を `applyTreeChange` へ1回渡し、`layoutNodeForest` が全体の最終座標を決める。配置が失敗した候補は確定しない。ラベル・重要度・イラスト等、配置以外の属性は保持する。

ルート順の先頭が変わる場合は既存の兄弟並べ替えと同じ考え方で、新しい先頭ルートへ削除前の先頭ルートのx/yを渡し、森全体の基準位置を維持する。先頭Tに子があれば最初の昇格子、子がなければ次の既存ルートが引き継ぐ。空になる場合は引継ぎ不要。先頭以外の削除では基準座標を変更しない。

削除と付け替えを別々にcommitしない。処理中の配列を公開・永続化せず、成功した最終候補だけを1操作としてcommitする。

## APIと責務

- `domain/nodes/nodeOnlyDeletion.ts`（仮称）: `canDeleteNodeOnly(nodes, nodeId, visibleNodeIds)` と純粋な `deleteNodeOnly(nodes, nodeId, visibleNodeIds, mode)`。対象の実在・表示を検証し、全配列から候補と結果を返す。
- 成功結果は `{ ok: true, deletedId }`、ドメイン結果のみこれに `nodes` を付ける。失敗理由は `node-missing | node-hidden | invalid-structure | placement-failed`。
- `useNodes.deleteNodeOnly(nodeId, visibleNodeIds)`: 安定したコールバック。`applyTreeChangeWithOutcome` のcompute内で最新の全配列と配置モードを使う。失敗理由を失わず返し、成功したときだけ削除対象の選択を解除する。新たなIDや版は発行しない。
- `useNodeOnlyDeletionAction`（仮称）: 選択中の対象と有効状態、実行結果に応じた通知を持つ。既存の `treeEditNotice` へpublish/clearする。
- `NodeOnlyDeleteControl`（仮称）: 表示・クリックの重複除外を担当する小さいボタン。新規の本番必須propsは省略可能にせず、`MapEditor` で実物を配線する。
- MapStage側に新しい削除ショートカットやpropsを増やさない。既存 `onDeleteNode` の枝削除経路は変更しない。

名前や小さな内部関数の分割は実装計画で確定してよい。結果の契約と一度だけの確定は変えない。

## UI・選択・フォーカス

ヘッダーの「親を挿入」の直後に「ノードだけ削除」を置く。accessible nameは「選択中のノードだけ削除」、titleは「子孫を残して、選択中のノードだけ削除」とする。未選択・削除済み・非表示の選択ではdisabled。クリック時にも実在と表示を再検証する。

成功時、選択中のIDが削除対象なら `null` にする。親や子を自動選択しない。APIで別のノードを削除した場合は残る選択を保持する。失敗時は選択を変えない。Undo / Redoは既存どおり選択を解除し、版を進める。

DOMフォーカスを別の操作やキャンバスへ強制移動しない。削除成功によりボタンがdisabledになった後に、同じ入力が別ノードを削除することがない。キーボード由来のclickで `detail === 0` は許し、マウスの `detail > 1` は無視する。keydownのrepeatからボタンが連続実行されないよう、必要なら既存Controlのキーガードを踏襲する。入力欄の文字削除やラベル編集を壊すグローバルハンドラは追加しない。

成功通知は `kind: status`、文言は「ノードだけ削除しました。子孫は残っています。」。同じ通知枠を使い、新しい通知系列は増やさない。失敗は既存構造編集の文体で「対象のノードが見つかりません。」「表示されているノードを選択してください。」「ノードの構造を確認できないため削除できません。」「配置できないため削除できません。」を返す。成功通知を先に出さない。

折りたたんだTを削除したらTの折りたたみIDは既存の正規化で除かれ、子は新しい親に応じて表示を再判定する。残る子自身の折りたたみIDは維持する。解像度設定は変えないため、昇格子が隠れたままになることはあり得る。隠れた子孫の保存や接続は失わない。Undo / Redoで折りたたみがクリアされる既存仕様は変更しない。

## テストと完了条件

実装前に対応テストを追加しREDを確認する。

- ドメイン: 中間ノード・葉・唯一のルート・複数ルート・先頭以外のルート、複数の子と孫を検証。元配列の不変性、ノード数、全属性とoptional illustrationの保持、子と孫と無関係ノードの親、全兄弟順を明示的にassertする。
- 並び: 深さ優先でない配列、Tより前/後の直下の子、隠れた子と隠れた兄弟、子を持つ兄弟を混ぜ、配列の隣接を親子関係と取り違えないことを確認する。
- 失敗: missing/hidden、ID重複・親欠け・循環、非有限数・不正寸法。自動配置の算術失敗を実際のレイアウト経由で起こし、候補だけ成功してもノード・選択・履歴・Redoが変わらないことを確認する。
- hook: 最新状態の同一batch操作、最初に取得したコールバック、manual/auto、選択保持/解除、1回のUndoで全構造・順序・属性・座標を戻しRedoで再現、通常成功時のdocumentRevision不変。
- 結合: 実物の `MapEditor` → Control → action → useNodes を通し、ボタンでTだけが消えて子が残り、Undoで戻る。枝削除のDelete / Backspaceでは従来どおり子孫も消える。新規propsや別操作への誤配線を区別できるデータを使う。
- UI: accessible name、未選択と非表示でdisabled、成功/失敗の通知、フォーカスを他の操作へ移さない、ダブルクリック/キー連打が他のノードへ波及しない、折りたたみ・解像度で隠れた子を保持する。
- 保存/再読み込み: 昇格した親子関係と兄弟順・属性が既存保存形式で保持されることを確認する。専用の保存処理を追加しない。
- 最終: `client` で `npm run verify`。実ブラウザの確認を実施していなければ実施済みとは書かない。
