# Phase 27（前半）: 枝の別マップ化・マップアーカイブ — 設計

- ROADMAP: Phase 27 のうち **候補 058 / 060**（**059・093 は後続**）
- 日付: 2026-11-23

## 決めたこと

1. **範囲**: **058 と 060 のみ**を 1 PR で実装する（タスクは分離。059 統合・093 関係図は非目標）。
2. **058 — 枝の別マップ化**:
   - 前提: マップ表示・主選択ちょうど 1・**ルート以外**。アウトライン／保護／競合中は不可。
   - **編集ロック（L-1061）**: `assertNodesEditable` 対象＝**枝内全 ID ∪ 離脱元親**（スタブ挿入先。ルート直下なら親検査なし）。どれか locked なら拒否。
   - 手順（1 操作）:
     1. 新マップ作成。名前: `元マップ名 — {表示ラベル}`。表示ラベルは選択根の `label` が空白のみなら「無題の枝」。
     2. 選択根＋子孫を新マップへ **移動**（単一ルート）。`transferNodeBranch` 相当（ID 再採番・mapLinks remap は既存）。
     3. 元マップ: 枝を削除し、**元の選択根と同じ配列位置（兄弟内 index）**にスタブ 1 件を挿入。スタブ座標は旧根の `(x,y)`、寸法は新規ノード既定（100×60）、`importance: "medium"`、`label` は旧根ラベル（空白のみなら表示フォールバック「新しいノード」を **永続ラベルとして書き込む**）。任意属性は **`mapLinks` 以外は持たない**。`mapLinks` はちょうど 1 件 `{ targetMapId: 新マップID }`（マップ全体リンク）。
     4. 成功後は新マップを開く。失敗は両側ロールバック／保護モード（既存枝移動 TX）。
   - **被リンク**: 他マップから旧ノード ID へのリンクは **付け替えない**（既存の別マップ枝移動と同じ割り切り。リンク切れ確認で直す）。
   - Undo: 別マップ保存を伴うため履歴に載せない（既存と同割り切り。ダイアログで明示）。
   - UI 入口: **ノードコンテキストメニュー**のみ「枝を別マップに切り出す」＋確認ダイアログ（開いている間は既存どおり shortcuts／親を inert）。
3. **060 — マップのアーカイブ**:
   - ゴミ箱とは別。本体は `doc.<id>` のまま。
   - `MapUserMeta.archivedAt?: string` — **厳密 ISO 8601**（`lastOpenedAt` と同型）。キーあり＝アーカイブ。不正型は codec 既存どおり corrupt 扱い。
   - 一覧: 第 4 タブ **「アーカイブ」**を追加（トグルではない）。タブ `all` / `favorites` / `recent` ではアーカイブ済みを **出さない**。アーカイブ解除はアーカイブタブから。
   - 全マップ検索: アーカイブを **含める**。結果に「アーカイブ」印。
   - 現在マップのアーカイブ可（編集継続）。削除（ゴミ箱）は現行どおりアーカイブ済みにも可。
   - `libraryMetaStatus !== "ready"` または保護モードではアーカイブ／解除を **disabled**（書込失敗時は通知、本体非タッチ）。
4. **実装順**: ①060 meta＋一覧タブ ②058 ドメイン＋TX ③コンテキストメニュー UI ④docs grep 同期（features / data-model / overview / api / ROADMAP / 型コメント）⑤verify。
