# Phase 11: 枝の折りたたみ・展開 設計

作成日: 2026-10-20
基準: main `aec046d`。設計に基づく実装と自動検証は2026-10-21に完了。実ブラウザの操作確認には未実施項目が残る。

## 目的・範囲

必要な枝だけを表示し、大きなマップを見渡せるようにする。ROADMAP Phase 11の5項目（子孫の折りたたみ、件数表示、解像度との統合、自動配置、検索結果からの展開）を一つの機能として扱う。

## 決めたこと

以下は計画作成者の推奨判断であり、既存の保存・履歴を壊さない構成を選ぶ。

- 折りたたみはメモリ上の表示状態。JSON/localStorage・Undo/Redoの対象外とする。読み込み・成功したUndo/Redoで全展開へ戻す。利用者に方針を質問し、回答がない場合の推奨案として採用する。
- ヘッダーに選択中ノードの「枝を折りたたむ」／「枝を展開」ボタンと「折りたたみで非表示: N件」を表示する。まず既存のヘッダーボタン群と同じ操作方式に揃える。新しいショートカット、コンテキストメニュー追加、キャンバス内バッジ、一括折りたたみは対象外。
- 折りたたみは対象自身を残し、すべての子孫を隠す。内側の折りたたみ指定は保持し、外側を展開しても内側は閉じたまま。
- 自動配置は表示用の投影として計算する。保存元のnodesと座標は変更しない。手動配置は既存座標をそのまま使用する。
- 検索結果選択は対象までの閉じた祖先のみを展開する。対象自身の折りたたみと無関係の枝は維持する。
- 既知の制約: 自動配置で別の枝が閉じた状態からさらに枝を閉じると、消えるノードと接続線がフェードアウトの間（約160ms）だけ詰める前の正本座標に描かれる。表示座標の契約（隠れたノードは正本座標を保つ）を変えないため、利用者の判断で修正せず既知の制約とする。

保存形式へ折りたたみを追加する案は、マイグレーションと履歴仕様まで広がるため今回採らない。既存nodesの座標へ表示用再配置を書き戻す案も、表示操作が保存・履歴へ漏れるため採らない。

## Global Constraints

- 新規依存なし。Node、NodeMapState、V3保存形式、履歴形式を変えない。折りたたみ・展開・検索による祖先展開ではdocumentRevisionを増やさず履歴に積まない。
- 元の全nodesを正本とし、表示用配列は保存・複製・コピー・削除・生成処理へ渡さない（L-015, L-460）。
- 状態はノードIDとdocumentRevisionで識別。文書変更後は旧状態を描画時点で無効にする（L-035, L-037）。
- 表示条件・状態遷移は純関数、React hookは状態管理、Homeは配線、MapStageは表示・操作という既存境界を維持（L-317）。
- 新規props/callbackは必須。実HomeからMapStageまで通る結合テストで配線を検証（L-060）。
- 深い木を再帰で処理しない。索引・子孫数・可視判定は全体O(N)、祖先展開はO(depth)。順序はnodes配列順を保持。
- 実装時は `.worktrees/codex/phase11-branch-collapse` の `codex/phase11-branch-collapse` を使用。タスク単位のサブエージェント実装、別担当の仕様・品質レビュー、TDD、各client変更後の `npm run verify` を必須とする。
- コミット・push・PR作成は依頼時のみ。最後にROADMAPを実態に合わせて更新し、Phase 12以降を完了にしない。

## 折りたたみと表示の規則

1. 子を持つ実在ノードだけを折りたたみ対象にできる。未選択・葉ではボタンdisabled。「折りたたみで非表示: 0件」を表示する。
2. 全nodesを一度索引化し、各ノードの全子孫数を後順走査で求める。選択中のノード自身が折りたたまれていればその全子孫数を表示し、展開中なら0件。重要度で既に非表示の子孫も含む「その折りたたみ配下にある総数」であり、フィルターによる増減数ではない。
3. 折りたたみ集合には内側の指定も保持する。ノード削除や最後の子の移動で葉になったIDは有効集合から除外し、物理的にも整理する。後日そのIDへ子を追加しても過去の無効指定を復活させない。
4. 折りたたみによる可視集合Cは「厳密な祖先に折りたたみ指定がないノード」。解像度可視集合Rは既存collectVisibleNodeIdsを全nodesに適用したもの（高重要度の子の祖先を含む）。最終可視集合V = C ∩ R。折りたたみを高重要度が突き破らない。
5. 低重要度の折りたたみ根に高重要度の子孫がある場合、既存Rがその根を含めるため根は残り、子孫のみ隠れる。Rを先に枝刈りした配列へ適用してこの根を消してはいけない。
6. 最終Vを描画・接続線・hit test・メニュー・編集・選択解除・fitに共通利用する。既存の可視性遷移を利用し、フェード中も非表示ノードは操作不可。
7. 折りたたむ対象は選択中の親なので、その親の選択を維持する。構造変更等で選択・編集対象が隠れた場合は既存useHiddenNodeInteractionResetで選択解除・編集取消・gesture取消を行う。

## 保存座標と表示座標

- `useNodes().nodes`は従来どおり全ノードと正本座標。保存・画像出力（PNG/SVG）・コピー・複製・削除は全内容を扱う。画像出力は現在と同じ全マップを出し、折りたたみ中でも欠落させない。UIの補足文に「折りたたみは保存・画像出力に反映されません。」と示す。
- 手動配置: displayNodesはnodesそのもの。親ドラッグ時の非表示子孫の移動も既存moveNodeSubtreeで保持。
- 自動配置: 折りたたみで隠れる子孫を除いたCだけを既存layoutNodeForestへ渡し、得た座標を同じIDのdisplayNodesに合成する。displayNodes自体は全IDを保持し、隠れたノードの座標は正本のまま。正本nodesへ書き戻さない。
- 有効な折りたたみが0件ならdisplayNodesはnodesをそのまま返す。折りたたみ中だけ表示用再配置を計算する。解像度ズーム変化だけで再配置しない（Rは配置入力に含めない）。
- 配置不能なら正本座標へfallbackし、可視性は折りたたみ状態を維持。status「表示用の自動配置ができないため、元の位置で表示しています。」を表示する。nullを空マップに変換しない。
- MapStageのnodesはdisplayNodesを受け取る。描画、ラベル編集位置、hit test、viewport fit/focusはすべてこの座標を使用。IDベースの編集callbackは従来のuseNodesへ渡す。
- auto→manualでは、保存されている正本座標に戻る（表示用座標を確定しない）。ボタン補足にも「手動配置へ戻すと元の座標に戻ります。」を明示する。これにより非表示子孫を含む配置や履歴が壊れない。

## 検索との連携

- 全nodesを検索する現行規則・50件上限・順序を維持。検索一覧のhiddenは最終Vに基づく。既存「非表示」表記はそのまま用いる。
- 選択時に最新nodesで存在を再確認。missingでは展開/表示段階/選択/移動要求を変更しない。
- 対象の厳密な祖先を展開する。同時に、対象がRに入っていない場合だけ既存resolveMinimumVisibleLevelに従って表示段階を切り替える。折りたたみだけで隠れている場合はautoモードも保持する。
- 上記更新・選択・要求発行を同じイベントで行う。要求consumerはその描画で最新のdisplayNodesを読み、展開後の座標へ移動する。screen待ち・文書世代の失効・連番の既存契約を維持。
- 通知は折りたたみのみ「検索結果を表示するため、祖先の枝を展開しました。」、段階のみは現行文言、両方は祖先展開文言と現行段階文言を半角空白で連結。いずれも既存の世代付き通知を利用。
- navigateToNodeの結果は既存のnavigated/revealed/missingを維持。祖先展開または段階変更があればrevealed。

## 編集と寿命

- 成功したUndo/Redo、import、自動復元によるdocumentRevision変更で全展開。失敗/no-op Undoでは保持。折りたたみ操作自体はUndo対象にならない。
- 削除・複製・コピーは非表示子孫も含む。複製・貼り付けの新しいIDに折りたたみ指定をコピーしない。元の枝は現状態を保持。
- 閉じた親へTabで子を追加した場合、成功したときだけ親を展開し、新規ノードの編集が見える状態にする。解像度による非表示の扱いは既存仕様を維持。兄弟追加は親の祖先を既に表示しているため特別処理不要。
- 折りたたんだノードに既存枝を接続する操作は現在の状態を保持する。接続された子が隠れる場合は既存の非表示選択解除が働く。後で親を展開すると接続結果が見える。
- 同一イベントの複数expand/toggleはfunctional updateで順に適用し、古いclosureで先の更新を消さない（L-453）。返り値のためにstate updater内で副作用を起こさない。

## 受け入れ条件

- 根A→B→C、A→D。Bを閉じてからAを閉じ、Aを開くとA/B/Dが表示されCは隠れたまま。A閉時の表示件数は3、B閉時は1。
- RにA/B/Cが含まれていてもB閉ならCは非表示。C検索選択でA/Bの指定を除き、無関係の枝とC自身の指定は保持。
- 自動配置で折りたたむと空白を詰めるが、JSON・localStorage・履歴の正本座標と全件数が変わらない。展開・検索移動・手動切替がそれぞれ規定座標を使う。
- 閉じた親へ子追加、非表示子孫込みコピー/複製/削除、Undo/Redo、同じIDを含むimportを結合テストで確認。
- 10,000ノードの深い木でstack overflowせず、可視・件数計算の線形性を確認。domain（索引・可視・祖先・検索の祖先展開）に加え、hook（useBranchCollapse・useMapDisplayState）と表示用の配置計算（projectCollapsedLayout）まで通す。Homeから実MapStageまで通す経路は、jsdomで10,000ノードを描画・再描画すると1ケース約7.5秒かかり既定のタイムアウトを超えるため、深い木では行わず、Homeの結合テストは小さな木で同じ経路を確認する。
