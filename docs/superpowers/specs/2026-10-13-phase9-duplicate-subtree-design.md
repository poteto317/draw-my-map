# Phase 9: 枝の複製 設計

作成日: 2026-10-13

## 目的と範囲

選択したノードと全子孫をアプリ内で複製し、似た構造を作り直す手間を減らす。Phase 9の複製、ID再発行、配置、複製のUndo／Redoを対象とする。クリップボードのコピー＆ペーストは後続機能として残す。

## 方針の比較

- 固定距離だけずらす方式は簡単だが、大きな枝や連続複製で既存ノードに重なる。
- 手動配置ではマップ全体の下へ置く方式を採用する。枝の形を保ち、既存ノードと重ならない位置を決定できる。大きなマップでは離れた位置になるため、既存のFキーで選択ノードへ移動できることを案内する。
- 自動配置では既存の`applyTreeChange`に候補全体を渡し、既存のレイアウト規則で並べる。別のレイアウト実装を追加しない。

入口はヘッダーの「枝を複製」ボタンとする。右クリックメニュー拡張・新しいショートカット・複製先へのviewportの自動移動・キャンバスへのフォーカス移動は今回の対象外。

## Global Constraints

- `NodeMapState`とV3保存形式を変更しない。新規依存を追加しない。
- フィルターで見えない子孫も含め、選択ノードの部分木全体を複製する。
- 元ノードと枝外のノードは変更しない。ただしautoモードでは既存の自動配置に伴う座標変更を許す。
- 複製は`applyTreeChange`を1回だけ呼んで確定し、追加と自動配置をUndo／Redoの1操作として扱う。`applyTreeChange`のコールバックへ、`getPresent()`から得た最新の`layoutMode`を第2引数として渡すよう拡張する（既存の1引数のコールバックとは互換）。描画時点の`layoutMode`を閉じ込めて使わない。
- 失敗時はマップ、選択、履歴、Redoを保持する。採番済みIDの欠番は許し、allocatorを巻き戻さない。
- 実装は`codex/phase9-duplicate-subtree`ブランチ、`.worktrees/codex/phase9-duplicate-subtree`で、タスクごとのサブエージェントと独立した仕様・品質レビューを順番に行う。
- TDDを行い、client変更後は`cd client && npm run verify`を成功させる。最終タスクでROADMAP.mdを更新し、未実装の貼り付けを完了にしない。

## 複製するデータと親子関係

全複製ノードへ未使用IDを割り当てる。選択ノードがルートなら複製もルート、親があるなら複製根は同じ親の子になる。子孫のparentIdは対応する複製親IDへ置き換える。祖先や別の枝は複製しない。

label、importance、illustration、width、heightはそのまま引き継ぐ。ラベルに「コピー」等の接尾辞は付けない。画像は既存data URLを共有し、再生成しない。元配列の順序を保った複製群を配列末尾に追加し、親が子より後ろにある配列でもID対応表を先に作って処理する。入力は既存アプリ／読み込み検証を通った有効なforestとする。

## 配置

手動配置の移動量は`dx = 0`、`dy = max(全ノードのy + height) + SIBLING_VERTICAL_GAP - min(複製元部分木のy)`。現在の`SIBLING_VERTICAL_GAP`は40。枝内の相対座標と寸法を維持し、フィルターで見えないノードも配置判定に含める。既存マップ内の重なりや複製元枝内の重なりは修正対象外。

autoモードでは座標の平行移動をせず複製候補を生成してから、既存のforestレイアウトに任せる。手動用配置計算のoverflowでautoモードを不要に拒否しない。手動の移動量・複製後座標・下端が非有限値になる場合、または丸めによって必要な40の間隔を確保できない場合は失敗とする。

## 採番・履歴・成否

`useNodes.duplicateSubtree(sourceId): number | null`は成功時に複製根IDを返して選択し、対象不在・配置不能・自動配置失敗ならnullを返す。元の選択ノードがあることはhook内で最新状態から再確認する。連続呼び出しや同一イベント内の追加直後の複製も最新状態を使う。

IDは`NodeIdAllocator`に追加する一括採番`nextAvailableIds(nodes: readonly Node[], count: number): number[]`で、複製するノード数ぶんを1回で得る。占有集合（全既存ノードのID）は1回だけ作り、生成器から占有IDを飛ばしながら、採番したIDも占有集合に加えて`count`個を返すため、返すID同士も既存IDとも重ならない（生成器が同じ値を返しても重ならない）。1件ずつ`nextAvailableId`を呼んで占有配列を作り直す方式は、深い枝で計算量がO(n²)になるため使わない。既存の`nextAvailableId`の契約は変えない。Undo後に再複製してもallocatorをresetしない。Undo1回で全複製を消し、Redoで同じID・画像・座標を戻す。選択解除などの復元時動作は既存Undo／Redoに従う。

ドラッグ中に複製した場合は既存履歴hookが移動グループを閉じ、移動と複製を別の操作として記録する。旧ドラッグleaseから後続の移動が届かないことを検証する。複製成功時にdocumentRevisionは増やさない。生成中の結果は既存の対象IDへ紐付き、複製先IDへ転用しない。

## UI

ヘッダーoperationControlsへ「枝を複製」ボタンを追加する。ノード未選択・選択ID不在ではdisabled。ボタンが複製する対象はクリック時の選択ノード。ラベル編集中にクリックした場合は既存blurで確定した値を複製する。

成功時は通知領域に「枝を複製しました。Fキーで選択ノードへ移動できます。」を表示する。フォーカスはボタンに残す。既存のFキー判定（`resolveViewportFocusRequest`）は入力欄だけを除外し、ボタンにフォーカスがあってもFキーが効くため、キャンバスへフォーカスを移す必要はない。キャンバスへ移すと、ボタン上で押し続けたEnterのキーリピートやその後のTab・Deleteがノード用ショートカット（兄弟追加・子追加・削除）に届くため移さない（L-408）。ボタンの`onKeyDown`では`event.key === "Enter" && event.repeat`のとき`preventDefault()`し、Enterの押し続けで連続複製しない（`MapHistoryControls`と同じ扱い）。クリック（ダブルクリックを含む）は1クリックごとに1回複製する。

失敗時は「枝を複製できませんでした。」を通知し、成功通知は出さない。通知は既存MapOperationNoticeへ統合する。成功／失敗の次の複製要求で通知を更新し、マップ置換やUndo／Redo（documentRevision変更）で消す。非表示ノードを複製元に直接指定したhook操作ではデータ複製は許すが、既存の非表示選択解除規則を優先する。

## 検証と知見

ドメインで親子変換・占有ID・非有限値・不変性、hookで原子性・履歴・auto、ページ結合で最新ラベル・選択・通知と、フォーカスがボタンに残った状態でのFキー・Enterリピートを検証する。深い枝の走査は再帰を使わず、隣接表とqueueで行いスタック上限に依存させない。採番は上記の一括採番を使う。1万段の枝を再帰エラーなしで正しく複製できることをテストし、採番と部分木の走査が線形であることは、時間計測ではなく、配列要素の読み取り回数と（一括採番では）各ノードの`id`の読み取り回数がノード数の定数倍以内であることで確かめる（Jestは同期テストをタイムアウトで失敗させないため）。

review-lessonsのL-001（失敗を成功扱いしない）、L-037（生成結果の対象）、L-038/L-063（一括操作の原子性）、L-048（既存の親子操作）、L-060（ページ配線）、L-061（ドラッグ割り込み）、L-107（不要なeffect実行）、L-157／L-408（フォーカス移動先へのキーリピートの到達。フォーカスをボタンに残し、Enterのリピートを抑止する）、L-419（保存のテストは`setItem`をspyし、書き込みの回数と各回の値を確かめる）を適用する。

## 決めたこと

- 設計レビューにより、当初の「複製後にキャンバスへフォーカスを移す」案を取りやめた。Fキーはボタン上でも既に効くため目的を満たし、フォーカス移動はL-408の事故（Enterリピートで兄弟ノードが増え続ける、Tab・Deleteがノード操作になる）を招くため。
- 採番は一括採番`nextAvailableIds`を追加して行う（深い枝でのO(n²)回避）。
- 成功通知は次の複製要求か`documentRevision`の変化（Undo／Redo・マップ置換）まで表示し、複製したノードを別操作で削除しても消さない。
- 複製ボタンのダブルクリックは2回の複製として扱う（Undoで1回ずつ戻せる）。Enterの押し続けだけは抑止する。
