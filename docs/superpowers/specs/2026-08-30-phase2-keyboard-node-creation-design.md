# Phase 2: キーボードによる親子・兄弟ノード作成 設計

## 目的

マインドマップの親子構造を導入し、選択中のノードからキーボード操作で子ノードまたは兄弟ノードを素早く作成できるようにする。作成した親子ノード間には接続線を自動表示する。

今回の実装は、将来のマウスによる既存ノード同士の接続へ拡張できるデータ構造を採用する。

## 対象範囲

- ノードへの `parentId` の追加
- `Tab` による子ノード作成
- `Enter` による兄弟ノード作成
- 作成直後の選択とテキスト編集開始
- 親子関係から導出した接続線の描画
- ノード削除時の子孫ノード一括削除
- 上記機能のユニットテスト

次の機能は今回の対象外とし、ロードマップ上の後続タスクとして扱う。

- マウスによる既存ノード同士の接続
- ノード同士の重なりを避ける自動レイアウト
- 親ノード移動時の子孫ノード一括移動

## データ構造

`Node` に `parentId: number | null` を追加する。

- `parentId === null`: ルートノード
- `parentId` が数値: 指定したIDのノードを親に持つ子ノード

接続線は独立した配列として保存せず、描画時に各ノードの `parentId` から導出する。この方法により、ツリー構造を単一の情報源として扱う。将来のマウス接続では、接続対象ノードの `parentId` を変更する。

## コンポーネントの責務

### `useNodes`

- ノード一覧と選択状態を保持する
- ルートノード、子ノード、兄弟ノードを作成する
- 新規ノードの初期座標を計算する
- 作成したノードのIDを呼び出し元へ返す
- 指定ノードと配下の子孫をまとめて削除する

### `MapStage`

- PixiJSで接続線とノードを描画する
- `Tab` と `Enter` のキーボード入力を処理する
- 新規ノード作成後、そのノードの編集モードを開始する
- 編集中の `Enter` は兄弟作成ではなく編集確定として扱う
- ノードの移動に合わせて接続線を再描画する

### `page.tsx`

- `useNodes` の操作を `MapStage` へ渡す
- ノード状態の管理とキャンバス表示を接続する

## 操作仕様

### 子ノード作成

1. ユーザーがノードを選択する。
2. `Tab` を押す。
3. 選択ノードの右側に子ノードを作成する。
4. 作成した子ノードを選択する。
5. 子ノードのテキスト編集を自動的に開始する。

選択中のノードがない場合、`Tab` は何もしない。

### 兄弟ノード作成

1. ユーザーがノードを選択する。
2. 編集中でない状態で `Enter` を押す。
3. 選択ノードと同じ `parentId` を持つノードを、既存兄弟の下に作成する。
4. 作成したノードを選択する。
5. テキスト編集を自動的に開始する。

ルートノードを選択している場合は、既存ルートノードの下に新しいルートノードを作成する。選択中のノードがない場合、`Enter` は何もしない。

### テキスト編集中のキー操作

- `Enter`: 編集内容を確定する
- `Escape`: 編集内容を破棄する
- `Tab`: 通常の入力フォーカス操作とし、子ノードを作成しない
- `Delete` / `Backspace`: テキスト入力に使用し、ノードを削除しない

### 削除

子を持つノードを削除すると、そのノードを祖先とするすべての子孫も削除する。循環した不正データが存在しても無限ループしないよう、探索時に訪問済みIDを記録する。

## 配置規則

- ノードの既定サイズは既存の `RECT_WIDTH` と `RECT_HEIGHT` を使用する。
- 最初の子は、親ノードの右端から120px離れた位置に配置する。
- 2個目以降の子は、同じ親を持つ既存兄弟の最下部から40px下に配置する。
- 兄弟ノードのX座標は、同じ親を持つ既存兄弟と揃える。
- ルートの兄弟は、既存ルートの最下部から40px下に配置する。

この規則は簡易配置であり、別の枝との重なりまでは解消しない。重なり回避は自動レイアウト機能で対応する。

## 接続線の描画

- 親ノードの右中央を始点とする。
- 子ノードの左中央を終点とする。
- 始点と終点の中間X座標を制御点に使った3次ベジェ曲線とする。
- 線幅は2px、色は青灰色とする。
- 接続線をすべて描画した後にノードを描画し、線がノードの背面に表示されるようにする。
- `parentId` に対応する親ノードが存在しない場合、その接続線だけを描画しない。

ノードのドラッグでは選択ノードの座標だけを変更する。子孫ノードは移動しないが、接続線は最新座標に追従して再描画する。

## テスト方針

### `useNodes`

- ルートノードの `parentId` が `null` になる
- 子ノードが正しい `parentId` と座標で作成される
- 複数の子ノードが下方向に配置される
- 兄弟ノードが同じ `parentId` で作成される
- ルートの兄弟がルートとして作成される
- 作成したノードが選択され、IDが返される
- 親ノード削除時にすべての子孫が削除される
- 関係のないノードは削除されない

### `MapStage`

- 親子関係に対応する接続線がノードより先に描画される
- 親が存在しない接続線は描画されない
- 選択中の `Tab` で子作成コールバックが呼ばれる
- 編集中でない `Enter` で兄弟作成コールバックが呼ばれる
- 作成後に新しいノードの編集入力が表示される
- 選択なしの `Tab` / `Enter` は何もしない
- 編集中のキー操作がノード作成・削除と競合しない

既存のノード追加、選択、編集、ドラッグ、削除、PixiJSライフサイクルのテストも維持する。

## 完了条件

- 選択中のノードから `Tab` で子ノードを作成できる
- 選択中のノードから `Enter` で兄弟ノードを作成できる
- 作成直後にテキスト編集を開始できる
- 親子ノード間の曲線が座標変更に追従する
- 親ノード削除時に子孫ノードも削除される
- lint、型チェック、ユニットテスト、本番ビルドが成功する
