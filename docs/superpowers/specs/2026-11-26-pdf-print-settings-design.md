# Phase 30 PDF書き出し・印刷設定の設計

日付: 2026-11-26
対象: カード #56 / 候補067
状態: 設計レビュー済み。実装状態と検証結果は実装計画およびPRを参照する。

## 目的と採用方式

既存SVG出力を用紙へ配置した印刷用文書を作り、ブラウザの印刷ダイアログを開く。利用者はプリンターへの印刷、または「PDFとして保存」を選ぶ。アプリがPDFバイナリを直接生成する機能ではない。

A4・A3・Letter、縦横、上下左右の余白、全体を1ページに収める配置、実寸で複数ページに分割する配置を提供する。依存ライブラリは追加しない。新規機能の責務を、ページ計算、印刷文書とその寿命管理、UI状態へ分離する。

## 既存実装との関係

- `services/imageExport/createMapSvgExport.ts` がテキスト計測、出力境界、SVG生成を調停し、`MapSvgDocument` の `svg / width / height` を返す。この経路をそのまま再利用し、Canvasやマップ画面DOMのスクリーンショットは使わない。
- `MapEditor.tsx` の `resolveExportNodes` で決まる `exportNodes` を入力とする。印刷用に全ノードへ取り直したり、exchange用の閉包・親補正を流用したりしない。
- 形式の可否は `domain/exportScope/exportFormatAvailability.ts` に `print` を追加して一元管理する。SVGと同じく `all / visible` で有効、`selection` で無効とする。`visible` は既存の `visibleNodeIds` の意味を引き継ぎ、画面のビューポート矩形による切り抜きではない。空の `visible` は既存の無効理由、空の `all` は実行時の「書き出すノードがありません。」で扱う。Hook側でも対象・可否を検査し、ボタンの無効化だけに依存しない。
- SVGの既存描画範囲・表現を継承する。白背景、32pxの出力パディング、既存のノード・親子線・ラベル・許可されたイラスト等が対象となる。画面上のグループ・関連線などSVG生成へ渡されない情報や、既存SVGで再現しない装飾を新たに補完しない。既存PNG/SVGの可否や出力制約も緩和しない。
- `mapExportBounds.ts` の有限性・精度飽和の検査、ラベルのXMLエスケープ、`isIllustrationDataUrl` による画像制限を維持する。印刷のために外部画像URLや任意SVGの取り込みを追加しない。

## UIと操作

既存画像出力の近くに「PDF・印刷設定」ボタンと専用の `MapPrintControls` を配置する。設定フォームは既存ダイアログの作法に合わせ、名前付き入力、エラーとの関連付け、フォーカス移動と復帰、Escapeによる取消に対応する。

設定はコンポーネント内だけに保持する。初期値はA4・縦・余白各10mm・「全体を1ページ」。入力は用紙サイズ、方向、上下左右の余白（mm、0.1mm単位）、配置方式。余白は各0〜50mmの有限数とし、空欄、NaN、Infinity、負値、範囲外、小数精度超過をエラーにする。用紙の幅から左右余白、高さから上下余白を引いた領域がそれぞれ1mm未満なら実行不可とする。数値を黙って補正しない。

実行前にページ数と「列×行」を表示する。プレビュー用のノード描画や独立した縮尺スライダーは追加しない。「実寸」は96pxを1インチ（25.4mm）として扱うことを説明する。「PDF保存は次の印刷画面で選択。用紙サイズを合わせ、倍率100%、ヘッダーとフッターをオフにしてください」と案内する。プリンターの非印字領域、印刷画面での用紙・倍率・余白の変更はブラウザ／プリンター側が最終的に決めるため、物理的な寸法を強制できるとは表示しない。

「印刷画面を開く」で、現在の対象ノードと設定をスナップショットとして確定する。その後のマップ編集・scope変更は進行中の印刷内容を変更しない。生成中は二重実行を同期的なガードでも防ぐ。準備中には取消を提供し、印刷ダイアログ中はブラウザ側で取り消す。通知には既存の `OperationNotice` と表示領域を利用する。

## ページ計算

`domain/printExport/mapPrintLayout.ts` に純粋関数と型を置く。入力は `MapSvgDocument` の正の有限な幅・高さと検証済み設定。出力は用紙寸法、印字領域寸法、行列数、各ページの元SVG上の切り出し位置・配置寸法とする。

- 用紙の縦寸法はA4: 210×297mm、A3: 297×420mm、Letter: 215.9×279.4mm。横向きでは幅と高さを入れ替える。
- `k = 25.4 / 96`、SVGの実寸を `W = width * k`、`H = height * k`、印字領域を `Pw / Ph` とする。
- 全体1ページは `s = min(Pw / W, Ph / H)` で縦横比を維持し、拡大も許して1ページ中央配置する。ノードを再レイアウトしない。
- 実寸タイルは `s = 1`、列数 `ceil(W / Pw)`、行数 `ceil(H / Ph)`。用紙に対する浮動小数点誤差だけで余分なページを作らないよう、商が整数から1e-9以内なら整数へ寄せてから切り上げる。クリッピング位置も同じ値から計算する。
- 左上を原点として左から右、上から下の順で出力する。ページ `(c, r)` は `c * Pw, r * Ph` だけ元画像を移動し、印字領域で切り抜く。最終行・列の余りは白のままとし、中央寄せしない。重なり、トンボ、ページ番号は付けない。
- 改ページ指定は「全体1ページ」またはこの自動タイル分割の選択を意味する。ノード単位の手動改ページ、区切り線のドラッグ、印刷ページ範囲指定は今回の対象外。線やノードが紙境界をまたぐ場合はその位置で分割する。
- 計算の全段階で有限性・正値・安全な整数の行列数を検査し、100ページを超えたらDOM生成前に拒否する。SVG Blobは10MiB以下とする。上限ちょうどは許可し、超過時には用紙拡大または全体1ページへの変更を案内する。これはアプリの資源制限であり、既存SVG出力の上限ではない。

## 印刷文書とライフサイクル

### 一時iframeを採用する理由

同一originの空の一時iframeを親documentに作り、印刷文書をDOM APIで組み立てる。`display:none` や `visibility:hidden` は使わず、画面外へ配置し、フォーカス対象とアクセシビリティツリーから除外する。iframeのCSSはアプリのTailwindやグローバルCSSから隔離される。印刷はiframeの `contentWindow.print()` に対して行う。

ポップアップ案ではクリック同期で空ウィンドウを確保してもブロック・利用者による途中閉鎖への対応が必要になる。一時iframeはこの拒否経路を避ける。MDNにも別文書をiframeで印刷する例がある。ただしブラウザ差がなくなるわけではなく、下記のChromium実機確認をリリース条件とする。Firefox・Safariは補助確認対象とし、未検証ならその制約をPRに記録する。

### 文書構造と安全性

SVG文字列をHTMLへ埋め込まない。既存 `createMapSvgBlob` から生成したBlob URLを各ページの `img.src` に共有する。SVGは画像コンテキストで表示する。利用者由来のラベルやマップ名を `innerHTML / document.write / srcdoc` やCSS文字列に挿入しない。文書タイトルは `textContent`、スタイルに入れる値は検証済み数値と用紙の固定列挙値だけとする。データURLやBlob URLをログや通知へ出さない。

用紙は `@page { size: <幅>mm <高さ>mm; margin: 0 }`、html/body余白0、ページ要素は用紙の幅・高さ、`box-sizing:border-box` と指定余白のpaddingを持つ。印字領域は `position:relative; overflow:hidden` とし、各画像は明示した物理寸法と位置に置く。ページは `break-inside:avoid`、最終ページ以外 `break-after:page` とし、末尾の強制改ページを付けない。画面用の説明や操作ボタンは印刷文書に入れない。

### 状態と結果

`idle → preparing → printing → idle` を基本とする。サービスは `dialog-closed | cancelled | failed` を区別し、failedにはinvalid-settings/page-limit/size-limit/preparationの安全な理由コードを付けて返すが、`dialog-closed` は印刷・PDF保存の成功を意味しない。`print()` の戻り値や `afterprint` では利用者の保存／取消を区別できないため、「PDFを書き出しました」「印刷しました」と通知しない。呼び出しが行われた時点の通知は「印刷画面を開きました。PDF保存は印刷画面で選択してください。」に限定する。

1. 設定、対象、SVG生成結果、Blobサイズ、ページ数を検査する。親documentの `fonts.ready` を待ってからSVGの文字幅を確定する。準備開始から合計15秒のタイムアウトとAbortSignalを適用する。
2. 自分が作ったiframe参照だけを保持し、空documentの準備を待つ。イベントは開始前に登録する。DOM作成後はiframeの `fonts.ready` と全imgの `load`（既にcompleteならnaturalWidthも確認）を待つ。`decode()` がある場合はその完了も待ち、失敗を握りつぶさない。SVG内のイラストも既存の許可形式に限定したまま、最終SVG画像のロード／デコード経路で扱う。
3. 準備が完了し、取消されていないことを再確認してからiframeをfocusし、`print()` を一度だけ呼ぶ。ブラウザ内蔵フォントは既存SVGと同じものを使い、新規Webフォントを読み込まない。
4. `afterprint` で寿命を終了する。準備中の取消、生成・ロード・print例外、15秒超過、Hookのアンマウントでも自分の資源だけを解放する。印刷呼び出し後は準備タイムアウトを解除し、印刷中に固定時間でiframeを破棄しない。
5. `afterprint` が届かない環境では、親UIに「印刷画面を閉じたら『印刷を終了』を押してください」を表示する。この明示操作で解放し再実行可能にする。`print()` が戻ったことや親windowのfocusだけを根拠に即時解放しない。ブラウザの印刷完了イベント自体が扱えない環境も、保存成功とは判定しない。
6. cleanupは一回だけ行う。保持しているiframe、作成したBlob URL、イベントリスナー、タイマー、AbortControllerだけを対象とする。古い処理の遅延イベントは世代トークンで無視する。cleanupの失敗を印刷失敗へ変換したり自動再印刷したりしない。マップ状態・自動保存・他のiframeには触らない。

準備エラーは「印刷の準備ができませんでした。設定を確認して再試行してください。」、上限超過や入力不備は原因を示す専用通知とする。内部例外文字列は利用者へ表示しない。取消はエラーにしない。

## 責務と実装の分割案

詳細な実装計画は別途 `docs/superpowers/plans/` に作る。この設計は次の2タスク程度で実装できる範囲に限定する。

1. **ページ計算とブラウザ印刷サービス**: `types/mapPrintExport.ts`、純粋な `domain/printExport/mapPrintLayout.ts`、DOM文書構築を担う `services/printExport/mapPrintDocument.ts`、待機・取消・cleanupを担う `services/printExport/printMapSvg.ts`。既存SVG生成器は変更せず利用する。各責務のテストを先に追加してREDを確認する。
2. **設定UIと接続、受け入れ確認**: `hooks/useMapPrintExport.ts` がスナップショット、排他、通知を管理し、サービスを注入可能にする。`MapPrintControls` は入力と表示だけを担当する。`MapEditor` は既存scope・mapName・通知との配線だけを追加する。availabilityにprintを追加し、関連テスト、実ブラウザ確認、`client` の `npm run verify` を行う。最後に実装済み範囲に限って `ROADMAP.md` のチェック・現在地・次の未完了項目・日付を更新する。

## 検証と受け入れ条件

Jestの既存 `domain / services / hooks / components` の配置に合わせる。ページ計算はA4/A3/Letter、方向、非対称余白、境界ちょうど／わずかな超過、タイル順、余り、100ページちょうど／超過、巨大値・非有限値を検証する。DOMサービスは画像ロード前にprintしないこと、font待機、decode失敗、準備タイムアウト、同期例外、取消後の遅延完了、二重実行、afterprint未発火、複数回cleanupを検証する。悪意あるマップ名・ラベルがHTML要素にならないこと、URLが一度だけ解放されること、他のiframeを削除しないことも含める。

Hook／UIテストではscopeごとの可否と理由、空対象、変更後のスナップショット、失敗・取消で成功通知を出さないこと、印刷終了の手動解除を確認する。MapEditorの接続テストでprintの可否・対象・通知の配線漏れを検出する。既存PNG/SVGテストも通ることを確認する。

jsdomでは実際の改ページや印刷画面を保証できない。Chromiumのデスクトップ版を必須、Firefox・Safariは利用可能なら補助確認として、PDF保存のページ数・用紙寸法・非対称余白・縦横・タイル境界・末尾の白紙なし、日本語／絵文字／イラスト、印刷取消後の再実行を手動確認する。各ブラウザの印刷設定を記録し、未検証の環境を検証済みと扱わない。CSS寸法の丸めによる余分なページが発生した場合は、実寸や余白を黙って縮めず、ページ構造を調整して再確認する。

設計に反映したレビュー知見はL-001（ダイアログ終了と保存成功の分離）、L-003（print前の検査）、L-004（所有資源だけのcleanup）、L-047（有限性・丸め境界）、L-048（既存SVG/scopeの維持）、L-052（準備待機の上限）、L-059（実ブラウザ確認）、L-060（配線テスト）である。

## 代替案と非目標

- PDFライブラリによる直接生成: 保存完了をアプリ側で扱いやすいが、依存増加、フォント・画像・SVG対応の再実装が必要なため今回は採用しない。
- PNGをPDFへ配置: 既存PNG処理を使えるが、巨大Canvas制限と文字の解像度低下があるため採用しない。
- アプリ画面そのものを印刷: CSS・ツールバー・ズーム・折り畳みとの結合が強く、既存SVGと対象がずれるため採用しない。
- ポップアップ: 独立プレビューとして見やすいが、拒否・閉鎖の対応が増えるため採用しない。

印刷設定の永続化、PDFバイナリの直接ダウンロード、モバイルの印刷UI保証、独自のPDFビューワー、手動ノード改ページ、カスタム用紙サイズ、縮尺指定、画像出力の表現拡張は非目標とする。
