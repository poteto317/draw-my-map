# Phase 10: ノード検索と移動 設計

作成日: 2026-10-14

## 目的と採用方針

大きなマップでも、目的のノードをラベルの一部から見つけて選択し、キャンバスの中央へ移動できるようにする。ROADMAPのPhase 10の4項目（部分一致の検索・結果の一覧・選択したノードへのフォーカス・解像度フィルターで隠れたノードの検索と表示）をすべて対象にする。

dev-flow-kitの`feature`手順（設計 → 設計レビュー → 実装プラン → プランレビュー）に従う。以下は今回採用する仕様。複数キーワードのAND検索、ひらがなとカタカナの同一視、正規表現、ラベル以外（イラスト・重要度）の検索、検索語の保存、検索結果のハイライト描画、検索欄へ移動するショートカットは対象外。

| 選択肢 | 判断 |
| --- | --- |
| ヘッダーに常設の検索欄＋欄の下に開く候補リスト | 採用。追加の操作なしで使え、既存のヘッダーの部品と同じ置き方になる |
| 右パネルの上部に検索欄と一覧 | 右パネルはイラストの操作に使っており、選択の変化で内容が変わるため採用しない |
| ボタン／ショートカットで開くオーバーレイ | 開く操作が増え、フォーカスの戻り先の管理も要るため採用しない |

隠れたノードの表示方法は、表示モードを、そのノードが見える段階へ切り替える方式にする（利用者の判断）。表示モードを変えずに一時的に表示へ加える方式は、解像度フィルターの表示条件に新しい状態を増やし、Phase 11の折りたたみとの統合を難しくするため採用しない。

## Global Constraints

- 新規依存なし。マップのV3保存形式（JSON・localStorage）と編集履歴を変えない。検索・結果の選択・表示モードの切り替え・表示位置の移動は、いずれも履歴に積まず、`documentRevision`も増やさない。
- 検索はメモリ上の現在の`nodes`だけを対象に、入力のたびに同期で行う。デバウンスや非同期処理は入れない（L-399）。
- 検索結果は配列の位置ではなくノードIDで扱い、選択を実行する時点で、そのIDのノードが現在のマップに実在するかを確かめ直す（L-035, L-037）。
- 検索欄への入力中に、既存のキーボード操作（Tab・Enter・Delete・Backspace・F・Ctrl/Cmd+Z・Ctrl+Y）と枝のコピー＆ペーストを発火させない。文字入力先の判定は既存の`isEditableTarget`と各フックの既存の判定に従い、独自の判定を足さない（L-061, L-191）。
- IME変換中（`isComposing`または`keyCode === 229`）のEnter・Escape・矢印キーは検索欄の操作として扱わない（L-157）。
- 新しく追加するコールバック・状態のpropsは必須にし、ページの結合テストで配線を確かめる（L-060）。
- 実装は`codex/phase10-node-search`ブランチ、`.worktrees/codex/phase10-node-search`で、タスク順にサブエージェント駆動と独立した仕様・品質レビューを行う。
- 各実装タスクでTDDと`cd client && npm run verify`を行う。最後にROADMAP.mdを更新し、Phase 11以降を完了にしない。

## 検索の規則

照合用の文字列は`text.normalize("NFKC").toLowerCase()`で作る（全角英数と半角英数、半角カナと全角カナ、大文字と小文字を同一視する）。検索語は、この正規化の後に前後の空白を取り除く（NFKCで全角空白も半角空白になるため、全角空白だけの検索語も空になる）。ラベルは前後の空白を取り除かずに正規化する。

- 検索語が空なら検索しない（結果なし・一覧を閉じる）。
- 正規化したラベルが正規化した検索語を部分文字列として含むノードを一致とする。ラベルが空のノード（画面には「新しいノード」と表示される）は、どの検索語にも一致しない。表示用の代わりの文言では照合しない。
- 改行を含むラベルもそのまま照合する。検索語の途中の空白は、その文字として照合する（AND検索にはしない）。
- 結果の順序は`nodes`配列の順（読み込み時の配列順も維持し、時系列の作成順とは限らない）。解像度フィルターで隠れているノードも結果に含める。
- 一覧に出すのは先頭50件（`MAX_NODE_SEARCH_RESULTS = 50`）まで。一致した総数は別に数える（L-160）。

性能: 正規化したラベルの索引は`nodes`配列が変わったときだけ作り直し、キー入力ごとの処理は索引の走査だけにする。索引の作成も検索も、ノード数に対して線形で終わる。親のラベルはIDから引く表で求め、結果ごとに配列を探さない（L-378, L-421, L-431）。

各結果は、ノードID・表示用のラベル（`getNodeDisplayLabel`）・親の表示用のラベル（根なら`null`）・フィルターで隠れているか（`visibleNodeIds`に無いか）を持つ。

## 結果を選んだときの動作

結果を選ぶと、次を同じイベント処理の中で行う。

1. 現在のマップにそのIDのノードが無ければ、何も変更せず、エラーの通知「ノードが見つかりませんでした。」を出して終わる。
2. ノードが`visibleNodeIds`に無ければ、表示モードを、そのノードの重要度が見える段階へ切り替える（対応表: high → "high"、medium → "medium"、low → "all"。純関数`resolveMinimumVisibleLevel(importance)`で決定）。自動モードからも手動の段階へ切り替わる。高重要度のノードは常に見えるため、この経路に入らない。切り替えた場合は通知「表示を『すべて』に切り替えました。ズームに連動させるには『自動』を選んでください。」（段階の名前は切り替え先）を出す。
3. ノードを選択する。
4. キャンバスの表示位置を、そのノードの中心が画面の中央に来るよう移動する。拡大率は変えない（既存のFキーのフォーカスと同じ計算`focusViewportOnNode`を使う。L-048）。

表示モードの切り替えと選択を同じバッチで確定するため、既存の「隠れたノードの選択を解除する」処理（`useHiddenNodeInteractionReset`）は、切り替え後の表示集合を見て選択を解除しない。同じノードを続けて選んでも、毎回表示位置を中央へ戻す（利用者がパンした後に、もう一度選んで戻れるようにする）。

選択の結果は`"navigated" | "revealed" | "missing"`として呼び出し元へ返す（L-001）。表示モードを切り替えなかった選択では、通知を変更しない。

### 表示位置の移動の受け渡し

表示位置はMapStageの中で管理しているため、Homeからは移動の要求`NodeFocusRequest = { nodeId: number; sequence: number; documentRevision: number }`をMapStageの必須props `focusRequest: NodeFocusRequest | null`で渡す。選択のたびに`sequence`を1増やし、その時点の`documentRevision`を添えた新しい要求を作る。sequenceは文書の復元後も巻き戻さない。Homeのフックは現在のdocumentRevisionと異なる要求を描画時にnullとして公開し、MapStage側でも要求の世代を再確認する。

MapStage内部では専用フック`useNodeFocusRequest({ request: NodeFocusRequest | null; documentRevision: number; nodes: readonly Node[]; screen: ScreenSize | null; hasActiveGesture: () => boolean; cancelActiveGesture: () => void; onFocusNode: (node: Node, screen: ScreenSize) => void })`で処理する。要求のdocumentRevisionが現在と違えば失効させ、移動もジェスチャー中断も行わない。前回処理した`sequence`と異なる有効な要求を受け取ったら、画面サイズの有無に先立って最新の`nodes`からノードを探し、Pixiの画面サイズが得られていれば移動する。画面サイズがまだ無い（初期化前で`screen === null`）なら、要求を保留し、`screen`が得られた再描画で処理する。ノードが無ければ、その要求を処理済みにして何もしない。ジェスチャー（ドラッグ・パン）の途中なら、先に`cancelActiveGesture()`を呼んでから移動する（ホイールでの拡大と同じ扱い）。`nodes`が変わったときも未処理の要求の対象消失は検出するが、処理済みの要求をもう一度実行しない。初期化待ちの間のJSON読み込み・Undo／Redoで、同じIDのノードが現れても古い要求では移動しない。

## 検索欄と結果の一覧

ヘッダーのタイトルの直後に、新しい枠`searchControls: ReactNode`として検索欄を置く（配置は既存コントロールと同じ形式だが、この新規propsは必須）。欄の下に、キャンバスに重ねて結果の一覧を開く。

- 入力欄は`type="text"`（ブラウザ独自のEscapeでの消去を避ける）、`role="combobox"`、`aria-label="ノードを検索"`、プレースホルダー「ノードを検索」、`aria-autocomplete="list"`、`aria-expanded`、`aria-controls`、一覧が開いていて選択中の候補があるときだけ`aria-activedescendant`。`autoComplete="off"`、`spellCheck={false}`。
- 一覧は`role="listbox"`・`aria-label="ノード検索結果"`、各候補は`role="option"`と`aria-selected`。候補のidは`useId`の接頭辞とノードIDから作る。
- 一覧を開く: 検索語が空でない状態で入力したとき、検索語が空でない状態で入力欄にフォーカスしたとき、下矢印キーを押したとき。
- 一覧を閉じる: Escape、入力欄からフォーカスが外れたとき（外側のクリックやTabによる移動を含む。L-248）、検索語が空になったとき。
- 選択中の候補（キーボードで動かす強調）はノードIDで持つ。描画時に、そのIDが現在の候補に無ければ先頭の候補を選択中とする（候補が無ければなし）。effectで直さず描画時に求める。
- 下矢印・上矢印で選択中の候補を次・前へ動かす（端では反対の端へ回る）。選択中の候補は`scrollIntoView({ block: "nearest" })`で見える位置へ動かす（jsdomに無いため、存在するときだけ呼ぶ。L-285）。
- Enterで選択中の候補を選ぶ。候補が0件の場合や一覧が閉じている場合は何も選択せず、イベントの既定動作のみ抑止（`preventDefault`）する。キーリピート（`event.repeat`）と、Ctrl・Cmd・Altを伴うEnterは扱わない（L-408）。
- Escapeは、一覧が開いていれば閉じ、閉じていて検索語があれば検索語を消す。
- 候補のクリックで、その候補を選択中にして選ぶ。候補と一覧の`mousedown`は既定動作を止め、入力欄のフォーカスを保つ（Safariで`focusout`がクリックより先に一覧を閉じる問題を避ける。L-148, L-155）。
- 選んだ後も一覧は開いたまま、フォーカスは入力欄に残す。続けて別の候補を選べる。一覧が閉じないため、候補のダブルクリックの2回目が背面のキャンバスへ届いてノードを追加することはない（L-150）。また、Enterの押し続けや続く入力がキャンバスのショートカット（Enterでの兄弟の追加など）へ届かない（L-408）。キャンバスでの操作に戻るには、キャンバスをクリックする。
- 処理するキー（矢印・Enter・Escape）は`preventDefault`する。キーの判定は、イベントから事実を集める → 純関数で操作を決める → 副作用を実行する、の3段に分ける（L-317）。

候補の表示: 1行目に表示用のラベル（1行に切り詰め、全文は`title`）、2行目に「親: ラベル」または「ルート」、隠れているノードには「非表示」の印を付ける。
候補のアクセシブルネーム（全パターン。L-156）:
- 親あり・表示: `"${displayLabel}（親: ${parentLabel}）"`
- 親あり・非表示: `"${displayLabel}（親: ${parentLabel}、非表示）"`
- ルート・表示: `"${displayLabel}（ルート）"`
- ルート・非表示: `"${displayLabel}（ルート、非表示）"`

一覧の下部の状態表示（`role="status"`、一覧の外側）: 一致なしは「一致するノードはありません。」、上限を超えたら「全120件中50件を表示しています。キーワードを絞り込んでください。」、それ以外は「5件」（L-057, L-154, L-160）。

マップの置き換え・Undo／Redo・ラベルの変更の後も、結果は最新の`nodes`から描画のたびに求め直すため、古い結果は残らない。検索語は保持する。

## 責務の分割

| 置き場所 | 責務 |
| --- | --- |
| `domain/search/nodeLabelSearch.ts`（新規） | 正規化、索引の作成、検索（純関数） |
| `domain/nodes/nodeResolution.ts` | 重要度から、そのノードが見える段階を求める純関数`resolveMinimumVisibleLevel(importance)`を追加 |
| `config/resolutionLevelLabels.ts`（新規） | 段階の表示名（「高のみ」「中以上」「すべて」）。表示切り替えの部品と通知の両方で使う（L-191） |
| `hooks/useNodeLabelSearch.ts`（新規） | 検索語の状態、索引と結果のメモ化、隠れているかの付与 |
| `hooks/useNodeSearchNavigation.ts`（新規） | 結果の選択（存在確認・表示モードの切り替え・選択・移動の要求・通知） |
| `components/layout/NodeSearchBox.tsx`（新規）と`nodeSearchKeyAction.ts`（新規） | 検索欄と一覧の表示、キー操作の判定 |
| `components/map/useNodeFocusRequest.ts`（新規） | MapStageの中で移動の要求を処理する |
| `components/layout/AppHeader.tsx`, `components/map/MapStage.tsx`, `app/page.tsx` | 枠の追加、propsの接続、通知の表示 |

通知は既存の`useRevisionScopedNotice`で`documentRevision`に合わせて失効させ、`operationNotices`（`data-testid="operation-notices"`）内に既存の通知（保存・画像出力・複製・コピー＆ペースト）とは独立した`<MapOperationNotice notice={searchNotice} />`として表示する。

## 検証・参照

純関数（正規化・検索・段階の算出・キー操作の判定）、フック（検索・選択・移動の要求）、部品（検索欄と一覧）、実Home/MapStageの結合に分けてテストする。結合テストでは、低重要度のノードを「高のみ」の表示で検索して選ぶと、表示が「すべて」に切り替わり、選択され、表示位置（Pixiのワールドのコンテナの位置）が動くことを確かめる。検索欄への入力中に既存のショートカットとコピー＆ペーストが発火しないことも結合テストで確かめる。

索引作成の線形性は元の配列と各ノード、検索の線形性は作成済みの索引配列と各エントリをそれぞれProxyで包み、読み取り回数が件数の定数倍以内であることで確かめる。元ノードへの再アクセスがないことだけでは、索引の多重走査を検出できない（L-431）。文字列処理のコストはラベルと検索語の長さにも依存し、ノード数のみで一定時間を保証するものではない。

jsdomは`mousedown`によるフォーカスの移動やIMEの実際の挙動を再現しないため（L-183）、実ブラウザでの確認手順（日本語入力の確定のEnter、Safariでの候補のクリック、タッチでの候補のタップ、候補のダブルクリック、隠れたノードの表示、一覧がキャンバスに重なったときの操作）を`docs/testing/browser-test-cases.md`に追加し、実施結果と未確認の環境を記録する。

関連知見: L-001（結果を返す）、L-035/L-037（IDで扱い、実行時に確かめ直す）、L-048（既存のフォーカスと同じ計算）、L-057/L-154/L-160（件数と0件の表示）、L-060（必須props）、L-061/L-191（既存の入口と判定の共有）、L-148/L-150/L-155（一覧のクリックとフォーカス）、L-156（アクセシブルネーム）、L-157（IME）、L-183/L-285（jsdomの限界）、L-248（Tabで閉じる）、L-317（キー判定の分離）、L-378/L-421/L-431（計算量）、L-399（デバウンスしない）、L-408（キーリピート）。

## 決めたこと

- Phase 10の4項目を1つの設計と実装プランにまとめる（利用者の判断）。
- 隠れたノードを選んだら、表示モードをそのノードが見える段階へ切り替え、通知する（利用者の判断）。
- 検索欄はヘッダーに常設し、欄の下に候補の一覧を開く（利用者の判断）。
- 検索欄へ移動するショートカットは追加しない。ブラウザのCtrl/Cmd+Fは奪わない（利用者の判断）。
- 正規化はNFKC＋小文字化。ひらがなとカタカナは同一視しない（推奨案を採用）。
- 結果は現在のnodes配列順で先頭50件まで、総数を表示する（推奨案を採用）。
- 選んだ後も一覧を開いたままにし、フォーカスを検索欄に残す（推奨案を採用。ダブルクリックとキーリピートの事故を避けるため）。

## レビュー修正（2026-10-14）

- 移動要求にdocumentRevisionを追加し、読み込み・Undo／Redoをまたぐ保留要求を失効させる。
- 検索の計算量は元ノードではなく索引自体へのアクセスを測る。
- searchControlsを必須に統一し、結果順を実際のnodes配列順として明記する。
- 結果一覧自体にも「ノード検索結果」というアクセシブルネームを付ける。
