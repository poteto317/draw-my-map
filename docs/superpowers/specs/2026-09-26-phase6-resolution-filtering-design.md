# Phase 6 解像度フィルタリング設計

## 目的

ノードへ重要度を設定し、ズーム倍率または利用者が指定した表示レベルに応じて、マインドマップの詳細度を切り替えられるようにする。ズームアウト時は重要な内容を俯瞰し、ズームイン時は詳細を確認できる状態を、ツリー構造と既存の編集・保存機能を壊さず提供する。

## スコープ

Phase 6として次を実装する。

- ノードの重要度（高・中・低）
- 選択中ノードの重要度を編集するUI
- ズーム倍率に連動した自動フィルタリング
- 表示レベルを固定する手動フィルタリング
- ノードとエッジのフェードイン・フェードアウト
- 重要度を保存するJSON V2形式とV1形式からの読み込み互換

## 用語と型

重要度は次の文字列リテラルで表す。

```ts
export type NodeImportance = "high" | "medium" | "low";
```

表示レベルは画面へ表示する重要度の下限を表す。

```ts
export type ResolutionLevel = "high" | "medium" | "all";
export type ResolutionFilterMode = "auto" | ResolutionLevel;
```

- `high`: 高重要度ノードだけを基準対象とする。
- `medium`: 高・中重要度ノードを基準対象とする。
- `all`: 全ノードを基準対象とする。
- `auto`: viewportのズーム倍率から表示レベルを導出する。

`Node`へ`importance: NodeImportance`を追加する。新規ノードとV1から読み込んだノードの既定値は`medium`とする。

## 状態境界

### 永続化する状態

- ノードごとの`importance`
- 従来から保存しているノード情報とレイアウトモード

### 永続化しない状態

- `ResolutionFilterMode`
- 自動モードから導出した`ResolutionLevel`
- ノードとエッジのopacity、アニメーション進捗
- viewportのパン位置とズーム倍率
- 選択・編集・ポインター操作中の状態

フィルターはノード配列を書き換えない派生表示状態とする。レイアウト、ノード操作、JSON保存、localStorage、画像出力は常に完全な`Node[]`を利用する。

## 自動表示レベル

現在のviewport範囲`0.25`から`4`に対して、次を初期しきい値とする。

- `scale < 0.6`: `high`
- `0.6 <= scale < 1.0`: `medium`
- `1.0 <= scale`: `all`

しきい値は純粋関数の名前付き定数として管理する。境界付近での連続切替を防ぐため、現在レベルを入力として受け取るステートレスな判定関数へ上下`0.05`のヒステリシスを適用する。

- `high`から`medium`へは`scale >= 0.65`で移行する。
- `medium`から`high`へは`scale < 0.55`で移行する。
- `medium`から`all`へは`scale >= 1.05`で移行する。
- `all`から`medium`へは`scale < 0.95`で移行する。
- 初回判定はヒステリシスなしの基本しきい値を使う。

手動モードではズーム倍率を無視し、選択したレベルへ固定する。「自動」を選ぶと、現在のズーム倍率から表示レベルを再判定する。

## 可視ノードの導出

可視ノードIDはDOMやPixiJSへ依存しない純粋関数で計算する。

1. 適用中の`ResolutionLevel`を決める。
2. レベル条件を満たすノードを基準対象として選ぶ。
3. 各基準対象から`parentId`をたどり、すべての祖先を可視集合へ追加する。
4. 入力順を変更せず、可視ID集合を返す。

親参照が欠損したデータや循環は永続化Codecで拒否されるが、表示関数単体でも無限ループしないよう訪問済みIDで走査を打ち切る。深いツリーでcall stackを消費しないよう反復処理を使う。

ルートを特別扱いして常時表示するのではなく、表示対象ノードの祖先として必要な場合に表示する。`all`では全ノードが表示される。

## エッジの表示

エッジは親と子の両方が可視集合に含まれる場合だけ表示対象とする。基準対象ノードへ至る祖先が可視化されるため、表示中のツリー経路は途中で切れない。

フェード中はノードと対応エッジが同じ目標可視状態へ遷移する。非表示へ移行するノードに接続するエッジも同時にフェードアウトする。

## UI

### `NodeImportanceSelector`

ヘッダーへ独立コンポーネントとして配置する。

- 「重要度」のラベルと「高・中・低」のボタンを表示する。
- ノード未選択時は全ボタンを無効化する。
- 選択中ノードの現在値を`aria-pressed`で表現する。
- ボタンは`type="button"`を指定する。
- 色だけで状態を表現せず、日本語の文字列とアクセシブル名を持たせる。
- 重要度変更は構造変更ではないため、自動レイアウトを再計算しない。

### `ResolutionFilterSelector`

ヘッダーへ独立コンポーネントとして配置する。

- 「表示」のラベルと「自動・高のみ・中以上・すべて」のボタンを表示する。
- 選択中モードを`aria-pressed`で表現する。
- 自動モードでは、現在適用中の段階を日本語で併記する。
- ヘッダーが折り返されても、DOM上の操作順を維持する。

`AppHeader`は両コンポーネントへ値とcommandを渡す配置責務だけを持ち、表示判定やノード更新を実装しない。

## 選択・編集・ポインター操作

フィルター変更またはズーム変更で選択中ノードが非表示対象になった場合、次を同期して解除する。

- ノード選択
- ラベル編集とdraft
- ドラッグ・接続を含むアクティブなポインター操作
- 接続候補のハイライト

非表示へ移行するノードはフェードアウト開始時点でPixiJSの`eventMode`を無効化し、当たり判定から除外する。opacityが残っている間も新しい操作は開始できない。

表示中ノードだけをダブルクリック編集、選択、ドラッグ、接続候補の対象とする。自動レイアウト、削除、子・兄弟追加などのドメイン操作は完全なノード配列を対象とする。

## アニメーション

PixiJS固有のopacity遷移は表示判定から分離する。

- 時間: 160ms
- 補間: ease-out
- 表示開始: 現在opacityから`1`へ遷移
- 非表示開始: 現在opacityから`0`へ遷移
- 途中で目標が変わった場合: その時点のopacityから新しい目標へ遷移
- 非表示完了後: 描画オブジェクトを保持してもよいが、描画と当たり判定を無効化する
- `prefers-reduced-motion: reduce`: アニメーションせず目標値を即時適用する

ノード単位とエッジ単位の表示オブジェクトを識別できる構成へ`renderMapNodes`と`renderMapEdges`を拡張する。フレーム更新、時間取得、reduced motion判定は注入可能にし、fake timerや決定的な時刻でテストできるようにする。

## 永続化形式

### V2

新しい書き出しとlocalStorage保存は`MapDocumentV2`を使う。

```ts
export type MapDocumentV2 = NodeMapState & {
  version: 2;
};
```

V2ノードでは`importance`を必須とし、`high`、`medium`、`low`以外を拒否する。JSON生成時は既知フィールドだけを出力する。

### V1互換

既存の`version: 1`は読み込み可能なまま維持する。

- V1のノードへ`importance: "medium"`を補完する。
- V1を読み込んだ結果はV2のマップ状態として返す。
- 次回の自動保存またはJSON書き出しはV2になる。
- V1に未知の`importance`フィールドが存在しても、従来どおり未知フィールドとして無視する。
- V2で`importance`が欠損または不正な場合はドキュメント全体を拒否する。
- `version: 3`以降は未対応として拒否する。

Storageキーは既存の`draw-my-map.map.v1`を維持する。キーは保存スロット名であり、ドキュメントversionとは独立して扱う。これにより既存利用者の保存値を同じ場所から復元できる。

## 既存機能との連携

- 自動レイアウト: 非表示ノードを含む全ツリーで計算する。
- 手動レイアウト: 非表示ノードの座標も維持する。
- JSON・localStorage: 全ノードと重要度を保存する。
- PNG・SVG出力: 現在のフィルターに関係なく全マップを出力する。
- マップ置換: フィルターモードを`auto`へ戻し、viewportと一時操作状態も従来どおり初期化する。
- ノード削除: 非表示の子孫を含むsubtree全体を削除する。
- 子・兄弟追加: 新規ノードの重要度は`medium`とし、現在の表示レベルで非表示になる場合でもデータとして追加する。追加直後に非表示となる場合は選択を残さない。
- フォーカスショートカット: 可視かつ選択中のノードだけを対象とする。

## 責務境界

### 型

- `types/nodeImportance.ts`: 重要度型
- `types/nodeResolution.ts`: 表示レベル型、フィルターモード型
- `types/node.ts`: `Node`へ重要度を追加
- `types/mapDocument.ts`: V1入力型、V2出力型、Codec結果型

### ドメイン

- `domain/nodes/nodeImportance.ts`: 新規ノードとV1移行で使う既定重要度
- `domain/nodes/nodeImportanceUpdate.ts`: 重要度更新の純粋変換
- `domain/nodes/nodeResolution.ts`: 表示レベル条件の純粋判定
- `domain/nodes/nodeResolutionFilter.ts`: 自動レベル判定、ヒステリシス、祖先を含む可視ID導出
- `domain/persistence/*`: V1/V2ノード正規化、V2投影、version別Codec

### Hook

- `useNodes`: 重要度更新commandを提供する。
- `useMapResolutionFilter`: モード、適用レベル、可視IDを調停する。
- `useMapVisibilityTransition`: PixiJS表示対象のopacity遷移を調停する。
- `useMapStageInteractions`: 可視IDだけをポインター対象として扱う。

### UI・描画

- `NodeImportanceSelector`: 選択ノードの重要度編集UI
- `ResolutionFilterSelector`: 自動・手動表示モードUI
- `MapStage`: viewport、表示フィルター、選択・編集・操作解除を接続する。
- `renderMapNodes`: ノードごとの可視状態、opacity、当たり判定を描画へ反映する。
- `renderMapEdges`: エッジごとの可視状態とopacityを描画へ反映する。
- `page.tsx`: 完全なノード状態、重要度command、表示モードUI、MapStageを配線する。

## データフロー

### 重要度変更

1. 利用者が選択中ノードの重要度ボタンを押す。
2. `useNodes.updateNodeImportance`が対象ノードだけを更新する。
3. 永続化スナップショットがV2として更新される。
4. 現在レベルから可視IDを再計算する。
5. 対象ノードと関連エッジを新しい目標opacityへ遷移させる。
6. 対象が非表示になる場合は選択・編集・操作を解除する。

### 自動フィルタリング

1. viewportのscaleが変化する。
2. 前回レベルとscaleからヒステリシス付きレベルを決める。
3. 基準対象と祖先から可視IDを導出する。
4. 非表示へ移行するノードの操作を即時無効化する。
5. ノードとエッジを160msで新しいopacityへ遷移させる。

### 手動フィルタリング

1. 利用者が「高のみ・中以上・すべて」を選ぶ。
2. 選択したレベルをズーム倍率より優先する。
3. 自動フィルタリングと同じ可視ID導出・遷移処理を行う。
4. 「自動」を選ぶまでズーム変更でレベルを変更しない。

## エラー処理

- UIから存在しないノードIDや不正な重要度を更新しようとした場合は状態を変更しない。
- V2の重要度欠損・型不一致・未知値は、ノードindexを含む日本語エラーで全体を拒否する。
- V1互換読み込みの失敗時は従来と同様、現在マップを変更しない。
- 表示判定で欠損親や循環を検出しても例外や無限ループを起こさず、到達済みの可視集合を返す。永続化境界では同じデータを不正として拒否する。
- アニメーションのcancel時はフレーム要求を解放し、unmount後にPixiJSオブジェクトを更新しない。

## テスト方針

### ドメイン単体テスト

- 重要度と各表示レベルの包含関係
- 新規ノードの既定値が`medium`
- 基本しきい値の直前・一致・直後
- 上下ヒステリシスの境界
- 手動モードでscaleを無視すること
- 高・中・低が混在する複数階層ツリー
- 条件を満たすノードの祖先を含めること
- 同じ親を共有する表示・非表示ノード
- 親が配列後方にある入力
- 欠損親、自己参照、循環で停止すること
- 10,000階層でもcall stackを消費しないこと

### 永続化テスト

- V2 JSON往復で重要度を維持すること
- V1を読み込み、全ノードへ`medium`を補完すること
- V1の未知フィールドを無視すること
- V2の重要度欠損・型不一致・未知値を拒否すること
- V3以降を拒否すること
- JSON生成がV2と既知フィールドだけを出力すること
- V1復元後の自動保存がV2になること

### Hookテスト

- 重要度更新が対象ノードだけを変更すること
- 重要度更新で自動レイアウトを再計算しないこと
- モード変更とscale変更による適用レベル
- マップ置換でモードを`auto`へ戻すこと
- 選択中ノードが非表示になると選択を解除すること
- 編集・ドラッグ・接続中に非表示になると操作を解除すること
- 途中で目標可視状態が反転したとき現在opacityから遷移すること
- unmount時にアニメーションを破棄すること
- reduced motionで即時切替すること

### 描画・UIテスト

- 重要度UIの表示、無効状態、`aria-pressed`、callback
- フィルターUIの4モードと自動時の適用レベル表示
- 可視ノードだけが操作可能であること
- 非表示ノードのopacityとevent mode
- 両端が可視なエッジだけが表示されること
- 160ms後のopacityと中間フレーム
- `page.tsx`が重要度、フィルター、MapStageを正しく配線すること

すべての実装は失敗するテストを先に追加し、対象実装でGREENにする。各PRで`client`ディレクトリから`npm run verify`を実行する。
