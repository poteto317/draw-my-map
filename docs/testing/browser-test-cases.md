# 実ブラウザでの確認テストケース

対象: Draw My Map（Phase 0〜13 の全機能。Phase 9 は枝の複製とコピー＆ペースト、Phase 10 はノード検索と移動、Phase 11 は枝の折りたたみ・展開、Phase 12 は複数マップの保存・切り替え、Phase 13 は箇条書きからマップを作成）と、Phase 14 の兄弟ノードの順序変更。
目的: 自動テスト（Jest + jsdom）では確認できない、実ブラウザでの表示・操作・保存・書き出しを確認する。

## 使い方

- 各ケースの「結果」欄に、実施した結果を記録する（○: 期待どおり、×: 不具合、△: 気になる点、-: 未実施）。
- 優先度: **高**は、リリース前に必ず確認する。**中**は、できるだけ確認する。**低**は、余裕があれば確認する。
- 「自動テストでは確認できない理由」を持つケースは、実ブラウザでしか見つからない不具合を狙っている。特に、**★**を付けたケースは、実装の過程で「未検証」と記録した点なので、優先して確認する。
- 不具合を見つけたときは、ケース ID、ブラウザとバージョン、手順、実際の結果、画面のスクリーンショット（またはブラウザのコンソールのエラー）を記録する。

## 事前準備

1. `cd client && npm install`（初回のみ）。
2. イラスト生成を試すときは、`client/.env.local` に Cloudflare の認証情報を設定する（`docs/setup/illustration-generation-setup.md` を参照）。**トークンをチャットや画面共有、スクリーンショットに出さない**。
3. `npm run dev` で起動し、`http://localhost:3000` を開く。
4. ブラウザの開発者ツールのコンソールを開いておく（エラーが出ていないかを、全ケースを通して見る）。
5. 確認の前に、ブラウザの保存データを消す。開発者ツール → Application → Local Storage → `http://localhost:3000` を開き、`draw-my-map.maps.v1` で始まるキー（一覧の `draw-my-map.maps.v1`、各マップの `draw-my-map.maps.v1.doc.<id>`、あれば `draw-my-map.maps.v1.corrupt-backup`）と、残っていれば Phase 11 までの `draw-my-map.map.v1` を、1つずつ選んで削除する（右クリック →「Delete」）。同じオリジンのほかの保存データを消さないよう、「Clear All」（すべて消去）は使わない。削除したら再読み込みする。保存データがある状態を確認するケース以外は、空の状態から始める。

### 確認するブラウザ・環境

| 区分 | 内容 |
|---|---|
| 必須 | Chrome（最新版）、macOS |
| 推奨 | Safari（最新版）、Firefox（最新版） |
| 備考 | L 節（枝のコピー＆ペースト）では、Chrome と Firefox の両方が必須（Safari は L-12 で確認する）。他の節では上の区分のままとする |
| 任意 | 高解像度ディスプレイ（Retina など）、タッチ操作ができる端末（ピンチ） |
| 表示 | ライトモードとダークモード（OS の設定で切り替える） |

### 無料枠について

イラストを生成するケース（Cloudflare を呼ぶケース）は、1回あたり約 173 Neurons を使う（1日の無料枠は 10,000 Neurons で、約 57 枚）。生成を伴うケースは、末尾の「イラスト生成の実施回数の目安」にまとめた。確認が済んだ画像は、他のケースで使い回す。

## A. 画面の基本（Phase 0）

### A-01 起動と初期表示【高】
- 前提: 空の状態。
- 手順: ページを開く。
- 期待: ヘッダー（レイアウトモード、重要度、表示、JSON・PNG・SVG の操作）、キャンバス、右パネル「イラスト」が表示される。キャンバスは残りの幅を使い、右パネル（幅 240px）と隙間なく並ぶ。コンソールにエラーが出ない。ノード未選択のパネルには「ノードを選択してください」が出る。
- 結果: 

### A-02 ダークモード【中】
- 前提: OS をダークモードにする。
- 手順: ページを再読み込みして、ヘッダー、パネル、ボタン、ノードを表示する。
- 期待: 文字と背景のコントラストが十分で、読めない箇所がない。ライトモードに戻しても同様。
- 結果: 

### A-03 高解像度ディスプレイでの描画【中】
- 前提: 高解像度ディスプレイ（またはブラウザの拡大率 200%）。
- 手順: ノードを1つ追加して、文字と枠線を見る。
- 期待: ノードの枠線と文字がぼやけず、くっきり表示される。
- 結果: 

### A-04 ウィンドウサイズの変更【低】
- 手順: ウィンドウの幅を変える。
- 期待: キャンバスが残りの幅に追従し、右パネルは 240px のまま。キャンバスの描画が、サイズ変更に追従する。
- 結果: 

### A-05 表示中に、拡大率やディスプレイを変える【低】
- 前提: ノードを数個表示している。
- 手順: ページを開いたまま、ブラウザの拡大率を変える（Cmd + / Cmd -）。外部ディスプレイがあれば、解像度の異なるディスプレイへ、ウィンドウを移す。最後に、ページを再読み込みする。
- 期待: アプリは壊れない。キャンバスの解像度は、ページを開いた時点の値（`devicePixelRatio`）で固定されるため、再読み込みまでの間に、文字や枠線がぼやけるかを記録する。再読み込みすると、くっきり表示される（A-03 と同じ）。
- 結果: 

### A-06 通知でヘッダーが伸びたときのキャンバス【中】
- 前提: 空の状態（通知が出ていない）。ウィンドウのサイズは変えない。
- 手順: 「PNG書き出し」を押して、通知「書き出すノードがありません。」を出す（ヘッダーに通知の行が増える）。キャンバスの下端の近くを、ダブルクリックしてノードを追加する。そのノードを選び、F キーを押す。最後に、ウィンドウのサイズを少し変える。
- 期待: キャンバスの描画の大きさは、ウィンドウのサイズ変更にだけ追従する（PixiJS の `resizeTo`）。そのため、通知でヘッダーが伸びたときに、キャンバスの下端のノードが隠れないか、ダブルクリックした位置にノードが追加されるか、F キーでノードが表示領域の縦の中央に来るかを確認し、挙動を記録する。ウィンドウのサイズを変えたあとは、表示領域に合う。
- 結果:

## B. ノードの基本操作（Phase 1）

### B-01 ノードの追加【高】
- 手順: キャンバスの空白を、ダブルクリックする。
- 期待: ダブルクリックした位置が中心になるように、四角形のノードが追加される。
- 結果: 

### B-02 ノードの編集（テキスト入力）【高】
- 手順: ノードをダブルクリックして、入力欄に「企画の背景」と入力し、Enter を押す。
- 期待: 入力欄がノードの位置に出る。Enter で確定し、ノードにテキストが表示される。
- 結果: 

### B-03 編集のキャンセル【中】
- 手順: ノードのテキストを編集している途中で、Escape を押す。
- 期待: 入力が破棄され、元のテキストに戻る。
- 結果: 

### B-04 空のテキスト【中】
- 手順: 新しいノードを追加し、テキストを入力せずに確定する。
- 期待: ノードに「新しいノード」と表示される（キャンバス、右パネル、画像書き出しで共通）。
- 結果: 

### B-05 長いテキストの折り返し【中】
- 手順: 非常に長いテキスト（例: 50 文字以上）を入力する。
- 期待: ノード内で折り返して表示される。右パネルの対象ノードのテキストは3行で省略され、マウスを乗せると全文が出る。
- 結果: 

### B-06 ノードの移動（手動配置）【高】
- 前提: 「手動配置」モード。
- 手順: ノードをドラッグする。
- 期待: ノードが、ドラッグに追従して動く。ドラッグ中に、意図せずテキスト編集や、選択の解除が起きない。
- 結果: 

### B-07 ノードの選択【高】
- 手順: ノードをクリックする。別のノードをクリックする。空白をクリックする。
- 期待: クリックしたノードが選択状態（枠の色が変わる）になる。別のノードを選ぶと、選択が移る。空白をクリックすると、選択が外れる。選択に連動して、右パネルの対象ノード表示と、重要度の選択が切り替わる。
- 結果: 

### B-08 ノードの削除【高】
- 手順: ノードを選択して、Delete キー（または Backspace）を押す。
- 期待: 選択中のノードが削除される。子孫のノードも、一緒に削除される。
- 結果: 

### B-09 日本語入力（IME）での編集★【高】
- 前提: OS の日本語入力（IME）を有効にする。
- 手順: ノードの編集中に、「きかく」と入力して変換し、変換を確定する Enter を押す。続けて、もう一度 Enter を押す。
- 期待: 変換を確定する Enter では、**編集が終了しない**（文字が「企画」に確定するだけ）。2回目の Enter で、編集が確定する。変換の途中の文字（下線付き）のまま、ノードのテキストが確定してしまう場合は、不具合として記録する（自動テストでは、IME の変換を再現できない）。Safari と Firefox でも確認する。
- 結果: 

### B-10 入力欄の外をクリックして確定する【中】
- 手順: ノードの編集中に、キャンバスの空白、または別のノードをクリックする。
- 期待: 入力した内容で、テキストが確定する（Escape と違い、破棄されない）。
- 結果: 

### B-11 拡大・移動した状態での編集【中】
- 手順: ズーム（例: 2 倍、0.5 倍）とパンをした状態で、ノードをダブルクリックして編集する。
- 期待: 入力欄が、表示中のノードの位置と大きさに合わせて出る（ずれない）。文字の大きさも、倍率に合う。
- 結果: 

### B-12 編集中はショートカットが働かない【高】
- 手順: ノードの編集中に、Backspace、Delete、Tab、Enter 以外の文字、F キーを押す。
- 期待: Backspace と Delete は、入力中の文字を消すだけで、**ノードは削除されない**。Tab で子ノードは追加されない（Tab は、ブラウザの標準の動作で、フォーカスを入力欄から右パネルのボタンへ移すため、入力欄の外をクリックしたときと同じく、編集が確定する。このあとに Enter を押すと、フォーカスのあるボタン（「イラストを生成」など）が押されるので注意する）。F キーで、表示位置は変わらず、「f」が入力される。
- 結果: 

### B-13 クリックとドラッグの区別【中】
- 手順: ノードをクリックするときに、マウスを、ごくわずか（数ピクセル）動かす。空白でも同じように行う。
- 期待: わずかな動きは、ドラッグではなく、クリック（選択、選択解除）として扱われる。ノードや画面が、意図せず動かない。
- 結果: 

### B-14 絵文字・記号・空白だけのテキスト【中】
- 手順: ノードに、「🍎りんご」「👨‍👩‍👧 家族」（結合した絵文字）、「A&B <C> "D" 'E'」を、それぞれ入力する。別のノードに、スペースだけ（「   」）を入力する。PNG と SVG を書き出し、SVG をブラウザで開く。
- 期待: キャンバス、右パネル、PNG、SVG で、同じ文字が表示される。SVG は、記号（`&`、`<` など）を含んでも壊れずに開ける。絵文字の色や形、結合した絵文字が折り返しの位置で分かれないかは、ブラウザごとに記録する。スペースだけのノードは、「新しいノード」ではなく、空白のまま表示される（「新しいノード」に置き換えるのは、空文字のときだけ）。スペースだけのノードで「イラストを生成」を押すと、H-03 と同じメッセージが出る。
- 結果: 

### B-15 改行を含むテキスト（JSON から読み込む）【低】
- 前提: JSON の `label` を、改行を含む文字列（例: `"1行目\n2行目"`）に書き換えたファイル。
- 手順: そのファイルを読み込む。キャンバスと、PNG・SVG の書き出しを見る。そのノードをダブルクリックして、何も変えずに Enter で確定する。
- 期待: 読み込める。書き出しでは、改行の位置で行が分かれる。キャンバスでの改行の表示を記録する。入力欄は1行の入力欄（`input`）のため、改行が表示されない。確定したあとに、テキストから改行が消えるかを記録する（ブラウザによって、入力欄の値から改行が取り除かれる）。
- 結果:

## C. ノード間の接続（Phase 2）

### C-01 子ノードの追加（Tab）【高】
- 前提: ノードを選択する。マウスのフォーカスが入力欄やボタンにない状態。
- 手順: Tab キーを押す。
- 期待: 選択中のノードの子ノードが追加され、接続線（曲線）が引かれ、新しいノードが選択される。新しいノードは、すぐにテキストの編集状態（入力欄が出る）になる。
- 結果: 

### C-02 兄弟ノードの追加（Enter）【高】
- 手順: ノードを選択して、Enter キーを押す。
- 期待: 同じ親を持つ兄弟ノードが追加され、新しいノードが選択される。新しいノードは、すぐにテキストの編集状態になる。続けて文字を入力し、Enter で確定し、さらに Enter で次の兄弟を追加する、という流れで、キーボードだけでツリーを作れる。
- 結果: 

### C-03 接続線の描画【中】
- 手順: 親子のノードを作る。ノードを動かす。
- 期待: 親から子へ、曲線で結ぶ接続線が引かれる。ノードを動かすと、接続線が追従する。
- 結果: 

### C-04 既存のノード同士の接続（Shift + ドラッグ）【高】
- 手順: 2つのノードを作る。Shift キーを押しながら、一方のノードをドラッグして、もう一方のノードの上で離す。
- 期待: ドラッグ中、接続先の候補のノードが強調表示される（緑の枠）。離すと、接続線ができる。**ドラッグを始めたノードが親、離した先のノードが子**になる（自動配置に切り替えると、子が親の右側に並ぶ）。
- 結果: 

### C-05 循環する接続の拒否【中】
- 手順: 親→子の関係があるとき、子から親へ、Shift + ドラッグで接続を試みる。
- 期待: 循環ができる接続は、拒否される（接続されない、またはアプリが壊れない）。
- 結果: 

### C-06 ボタンにフォーカスがあるときのショートカット【中】
- 前提: ノードを選択する。
- 手順: ヘッダーのボタン（例: 重要度の「高」）をクリックしたあと、Tab、Enter、Delete を押す。
- 期待: フォーカスがボタンにある間は、ノードのショートカットが働かない（Tab はフォーカスの移動、Enter はボタンの押下になる）。キャンバスのノードをクリックし直すと、ショートカットが再び働く。Safari と macOS の Firefox では、クリックしてもボタンにフォーカスが移らない（ブラウザの仕様）ため、ボタンを押したあとでも、Tab、Enter、Delete がノードのショートカットとして働くことがある。ブラウザごとに記録する。
- 結果: 

### C-07 すでに親があるノードへの接続（親の付け替え）【中】
- 前提: 親 A の子 B（B には子 C がある）と、別のノード D を作る。
- 手順: D から B へ、Shift + ドラッグで接続する。
- 期待: B の親が A から D に付け替わる（A と B の接続線が消え、D と B の接続線ができる）。B の子 C は、B の子のまま。自動配置では、全体が整列し直される。
- 結果: 

### C-08 接続の取りやめ【低】
- 手順: Shift + ドラッグを始めて、空白の上、または、ドラッグを始めたノード自身の上で離す。
- 期待: 何も接続されない。ノードは動かない。アプリは壊れない。
- 結果: 

### C-09 表示領域の外に追加されたノードの編集【中】
- 前提: 手動配置。倍率 1 倍。
- 手順: キャンバスの下端の近くにあるノードを選び、Enter で兄弟ノードを追加し、テキストを確定する流れ（C-02）を繰り返して、新しいノードがキャンバスの下端より下に追加されるまで続ける。同じように、右端の近くにあるノードで Tab を押して、右端より右に子ノードを追加する。（親のないノードで Enter を押すと、新しいノードは、親のないすべてのノードのうち一番下のものより下に、接続線なしで追加される。下の方に別のノードがあると、すぐに表示領域の外へ出る。）
- 期待: 新しいノードは、表示領域の外でも選択され、入力欄がノードの位置に出る（アプリは、表示位置を新しいノードへ動かさない）。入力欄にフォーカスが移るときに、ブラウザが、キャンバスと右パネルの領域を、入力欄が見えるようにスクロールさせるか（ヘッダーより下の領域全体がずれるか）を記録する。ずれた場合は、確定したあとに元に戻るか、パン、ズーム、ダブルクリックでの追加の位置がずれないか（D-07 と同じ確認）を記録する。確定したあとに F キーを押すと、新しいノードが中央に表示される。
- 結果:

## D. キャンバス操作（Phase 3）

### D-01 パン（空白ドラッグ）【高】
- 手順: 空白をドラッグする。
- 期待: キャンバス全体が、ドラッグに追従して動く。
- 結果: 

### D-02 ズーム（ホイール）【高】
- 手順: ホイール（またはトラックパッドのスクロール）で拡大縮小する。
- 期待: カーソルの位置を中心に、拡大縮小する。倍率の範囲は、0.25 倍から 4 倍。範囲を超えない。
- 結果: 

### D-03 ズーム（ピンチ）【低】
- 前提: タッチ操作ができる端末。
- 手順: 2本指でピンチする。
- 期待: ピンチに追従して、キャンバスが拡大縮小する。キャンバス上のピンチで、ブラウザのページ自体が拡大縮小しない（キャンバスはブラウザの標準のタッチ操作を無効にしている）。
- 結果: 

### D-04 選択ノードへのフォーカス（F キー）【中】
- 手順: ノードを選択して、F キーを押す。
- 期待: 選択中のノードが、キャンバスの中央に表示される。倍率は変わらない。ノードを選択していないときは、何も起きない。
- 結果: 

### D-05 親ノードの移動と子孫の追従【高】
- 前提: 手動配置。親、子、孫のノードを作る。
- 手順: 親ノードをドラッグする。
- 期待: 子と孫も、まとめて動く。
- 結果: 

### D-06 操作のヒント表示【低】
- 手順: 手動配置と自動配置を切り替える。

### D-13 タッチ操作（ダブルタップと長押し）【低】

- 手順: キャンバスの空白を、1本指でダブルタップする。ノードをダブルタップする。ノードと空白を、それぞれ長押しする。

- 結果: 

### D-14 トラックパッドの横スワイプと、倍率の上限・下限でのピンチ【中】
- 前提: macOS のトラックパッド。ノードを数個作り、1秒以上待つ（自動保存が終わる）。
- 手順: キャンバスの上で、2本指で真横にスワイプする（左右とも）。次に、ピンチで最大の 4 倍まで拡大し、指を離さずに、さらに広げる。同じように、最小の 0.25 倍まで縮小し、さらに縮める。Chrome、Safari、Firefox で行う。
- 期待: アプリは、ホイールの縦の量（`deltaY`）だけで拡大縮小し、倍率が変わらないホイールの通知（真横のスワイプ、上限・下限を超える方向の操作）では、ブラウザ標準の動作を止めない。そのため、横スワイプで、ブラウザの「戻る」「進む」（ページ間のスワイプ）が起きないか、上限・下限でのピンチで、ページ全体の拡大縮小（ヘッダーや右パネルまで大きくなる。D-08）が起きないかを、ブラウザごとに記録する。ページを離れてしまった場合は、戻ると、マップが表示されるか（F-19）を記録する。
- 結果:

## L. 枝のコピー＆ペースト（Phase 9）

## Phase 11: 枝の折りたたみ・展開

このセクションの共通の決まり:

- **起動**: N-01 は本番ビルドで行う（手順は N-01 の前提に書く）。N-02 以降は、事前準備のとおり `npm run dev` で起動した `http://localhost:3000` で行う。
- **基本の木**: 事前準備の 5 のとおり保存データを消して再読み込みし、マップが空であることを確かめる。手動配置のまま、キャンバスの空白をダブルクリックしてノードを追加し、ノードをダブルクリックしてラベルを「A」にする（Enter で確定）。A をクリックして選択し、Tab で子を追加してラベル「B」を入力して Enter で確定する。続けて Tab で B の子「C1」を追加して確定し、Enter で兄弟「C2」を追加して確定する。A をクリックして選択し、Tab で子「D」、確定後に Enter で兄弟「E」を追加して確定し、Tab で E の子「E1」を追加して確定する。できあがる木は A→B→C1・C2、A→D、A→E→E1 の 7 ノードで、重要度はすべて「中」（初期値）。
- **表示**: 特に書かない限り、ヘッダーの表示を「すべて」にしてから始める（ズーム連動の「自動」で、倍率によってノードが隠れないようにする）。
- **選択と件数の見方**: ノードの選択はキャンバス上のクリックで行う。ヘッダーの「枝を折りたたむ」/「枝を展開」と「折りたたみで非表示: N件」は、選択中のノードについて表示される。N は、選択中のノードが閉じている間はその全子孫数（重要度で隠れている子孫も含む）で、未選択・子のないノード・開いているノードでは 0件。
- **ボタンを押した後の Tab**: Chrome ではマウスで押したボタンにフォーカスが残り、その間の Tab はノードの子の追加にならない（C-06）。ボタンを押した後に Tab で子を追加するときは、キャンバスの対象ノードをクリックし直してから押す。
- **実施の順**: 各ケースは前提に書いた状態を作ってから始める（前のケースの結果に依存しない）。

## Phase 12: 複数マップの保存・切り替え

このセクションの共通の決まり:

- **起動**: 普段の保存データを消さないよう、`cd client && npm run build` の後に `npm run start -- -p 3112` で本番ビルドを起動し、`http://localhost:3112` を開く（`localhost:3000` や `localhost:3111` とは別のオリジンで、保存データも別になる）。確認が終わったら、起動した端末で Ctrl+C を押してサーバーを止める。
- **保存データを消す**: 開発者ツール → Application → Local Storage → `http://localhost:3112` を開き、消すキーを名前で1つずつ選んで削除する（右クリック →「Delete」）。消す対象は、`draw-my-map.maps.v1` で始まるキー（一覧の `draw-my-map.maps.v1`、各マップの `draw-my-map.maps.v1.doc.<id>`、あれば `draw-my-map.maps.v1.corrupt-backup`）と、残っていれば `draw-my-map.map.v1`、各ケースで自分で置いたキー（例: `draw-my-map.test-filler`）だけ。「Clear All」（すべて消去）は使わない。以下、この手順を「保存データを消す」と書く。
- **キーの値を見る・書き換える**: Application の Local Storage の一覧で、キーの行を選ぶと下に値が表示される。値の欄をダブルクリックすると書き換えられる。コンソールでキーを置くときは、ケースに書いた1行だけを貼り付けて Enter を押す（Chrome で貼り付けが止められた場合は、表示に従って `allow pasting` と入力してから貼り付ける）。
- **基本のマップ**: 保存データを消して再読み込みし、ヘッダーに「マップ: 無題のマップ」が出ていることを確かめる。ヘッダーの「新しいマップ」で「A」を作り、キャンバスの空白をダブルクリックしてノードを追加し、ラベルを「A1」にする。「新しいマップ」で「B」を作り、同じ方法でノード「B1」を追加する。一覧には B、A、無題のマップの順（更新日時の新しい順）に並ぶ。
- **通知の場所**: マップの作成・切り替え・開いているマップの削除の結果と、起動時の通知は、ヘッダーの上の1行（シェルの通知）に出る。名前の変更、開いていないマップの削除、操作の失敗は、ダイアログの中の下側に出る。自動保存の失敗などエディタ内の通知は、ヘッダーの下側（操作通知バー）に出る。
- **結果の記録**: 結果は、実ブラウザで実際に確かめたものだけを記録する。Jest の結合テストが通っていても、実機で確認したことにはしない。確かめていない部分があるときは、その部分を書いて △ にする。

## Phase 13: 箇条書きからマップを作成

ヘッダーの「箇条書きから追加」で開くダイアログで、インデント付きの箇条書きテキストを解析し、プレビューで確かめてからノードとしてまとめて追加する（仕様は features.md の 13 章）。

このセクションの共通の決まり:

- **起動**: 普段の保存データを消さないよう、`cd client && npm run build` の後に `npm run start -- -p 3113` で本番ビルドを起動し、`http://localhost:3113` を開く（`localhost:3000`・`3111`・`3112` とは別のオリジンで、保存データも別になる）。確認が終わったら、起動した端末で Ctrl+C を押してサーバーを止める。
- **保存データを消す**: 開発者ツール → Application → Local Storage → `http://localhost:3113` を開き、消すキーを名前で1つずつ選んで削除する（右クリック →「Delete」）。消す対象は、`draw-my-map.maps.v1` で始まるキー（一覧の `draw-my-map.maps.v1`、各マップの `draw-my-map.maps.v1.doc.<id>`、あれば `draw-my-map.maps.v1.corrupt-backup`）と、残っていれば `draw-my-map.map.v1` だけ。「Clear All」（すべて消去）は使わない。
- **テスト用のマップ**: 各ケースは、ヘッダーの「新しいマップ」でケースの ID を名前にしたマップ（例: 「P-01」）を作ってから行う。前のケースのノードや編集履歴を持ち越さない。
- **入力の作り方**: 入力欄の中の Tab はインデントを入力せず、次の要素へ移る。タブ・全角スペース・大きな入力は、開発者ツールのコンソールで `copy("…")`（Chrome の `copy` 関数。Safari の Web インスペクタにもある）を実行してクリップボードへ入れ、入力欄で Ctrl+V（macOS では Cmd+V）で貼り付ける。`\t` はタブ、`　` は全角スペース、`\n` は改行。コンソールへの貼り付けが止められた場合は、表示に従って `allow pasting` と入力してから貼り付ける。入力欄に前の内容が残っているときは、Ctrl+A（Cmd+A）で全選択してから貼り付ける。
- **表示**: 特に書かない限り、ヘッダーの表示を「すべて」にしてから始める（取り込んだノードの重要度は「中」なので、「自動」の倍率や「高のみ」で隠れないようにする）。
- **結果の記録**: 結果は、実ブラウザで実際に確かめたものだけを記録する。Jest の結合テストが通っていても、実機で確認したことにはしない。確かめていない部分があるときは、その部分を書いて △ にする。

## Phase 14: 兄弟ノードの順序変更

選択中のノードの枝を、同じ親の見えている兄弟（ルート同士を含む）の中で、ヘッダーの「上へ」「下へ」か `Alt`（macOS では `Option`）+ `↑` / `↓` で1つ上・1つ下へ移す。自動配置では、ノードのドラッグで兄弟の間へ移す（仕様は features.md の 14 章）。

このセクションの共通の決まり:

- **起動**: 普段の保存データを消さないよう、`cd client && npm run build` の後に `npm run start -- -p 3114` で本番ビルドを起動し、`http://localhost:3114` を開く（`localhost:3000`・`3111`・`3112`・`3113` とは別のオリジンで、保存データも別になる）。確認が終わったら、起動した端末で Ctrl+C を押してサーバーを止める。
- **保存データを消す**: 開発者ツール → Application → Local Storage → `http://localhost:3114` を開き、消すキーを名前で1つずつ選んで削除する（右クリック →「Delete」）。消す対象は、`draw-my-map.maps.v1` で始まるキー（一覧の `draw-my-map.maps.v1`、各マップの `draw-my-map.maps.v1.doc.<id>`、あれば `draw-my-map.maps.v1.corrupt-backup`）と、残っていれば `draw-my-map.map.v1` だけ。「Clear All」（すべて消去）は使わない。
- **テスト用のマップ**: 各ケースは、ヘッダーの「新しいマップ」でケースの ID を名前にしたマップ（例: 「Q-01」）を作ってから行う。前のケースのノードや編集履歴を持ち越さない。
- **表示**: 特に書かない限り、ヘッダーの表示を「すべて」にしてから始める。
- **基本の木**: 手動配置で、キャンバスの空白をダブルクリックしてノードを追加し、ラベルを「R」にして Enter で確定する。R を選択したまま Tab で子を追加してラベルを「A」にし、Enter で確定する。続けて Enter で兄弟を追加して「B」、もう一度 Enter で兄弟を追加して「C」にする（それぞれ Enter で確定する）。C を選択したまま Tab で子「C1」を追加し、確定後に Enter で兄弟「C2」を追加して確定する。このとき A・B・C は縦に 40px 間隔で並び（A の上端は R の上端と同じ高さ）、C の枝（C・C1・C2）の範囲は C の上端から C2 の下端までの 160px になる。
- **通知の見方**: 並べ替えの通知はヘッダーの下の操作通知バーに出る。
- **結果の記録**: 結果は、実ブラウザで実際に確かめたものだけを記録する。Jest の結合テストが通っていても、実機で確認したことにはしない。確かめていない部分があるときは、その部分を書いて △ にする。

## 確認でよく見る不具合のパターン

実装の過程で見つかった、実機でしか分からない種類の問題。再現したときは、記録して報告する。

- PNG の書き出しで、イラストが空白になる（SVG 内の画像の読み込みが、ラスタライズに間に合わない）。
- イラストが、ノードの枠からはみ出す、または、ぼやける（縮小、表示のスケール）。
- テキストの編集欄が、イラストを覆う、または、テキストの位置と食い違う。
- メニューの文字が、枠に収まらない。
- ズームの境目（自動フィルタの切り替え）で、ノードが点滅する。
- ページを再読み込みしたときだけ、イラストが表示されない（保存と復元の不整合）。
