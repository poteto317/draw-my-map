# Draw My Map

Draw My Map は、**少ない操作で素早くマインドマップを作れる**ビジュアル思考ツールです。  
Figma のような自由度の高い無限キャンバスと、マインドマップならではの素早いツリー構造化・操作性を融合し、シンプルさと快適な使い心地を両立しています。

---

## 主な特徴・差別化ポイント

1. **解像度フィルタリング（Zoom-linked Resolution Filtering）**
   - 各ノードに重要度タグ（高 / 中 / 低）を付与。
   - ズームレベルに連動して自動で表示ノードをフィルタリング。ズームアウト時は重要な要点だけを俯瞰し、ズームインすると詳細なノードが現れます。
   - ヒステリシス制御により境界付近でのチラつきを防止し、切り替え時には滑らかなフェードイン・フェードアウトアニメーションを適用。
   - 画面上部の UI から手動での表示レベル絞り込みも可能です。

2. **AI イラスト生成（Cloudflare Workers AI 連携）**
   - ノードを選択し、右クリックコンテキストメニューまたは右サイドパネルから AI イラストを自動生成。
   - Cloudflare Workers AI（FLUX.1 schnell）を採用。日本語のノードテキストも自動翻訳モデル（`@cf/meta/m2m100-1.2b`）を介して英語プロンプト化し、高品質なイラストを生成します。
   - 生成画像は 128px JPEG に自動最適化され、ノードに紐付けられてキャンバス上に描画されます。
   - イラストの再生成・削除にも対応し、画像エクスポートや永続化データにも含まれます。

3. **快適なキーボード＆キャンバス操作**
   - **素早いツリー入力**: `Tab` キーで選択ノードの子ノードを作成、`Enter` キーで兄弟ノードを作成。
   - **直感的な接続**: ノード同士をドラッグ＆ドロップして接続可能（滑らかなベジェ曲線エッジの自動ルーティング）。
   - **子孫連動移動**: 親ノードをドラッグすると、傘下の子孫ノードがまとまって移動（枝を折りたたんだ親では、隠れた子孫も同じ量だけ移動）。
   - **スムーズなナビゲーション**: キャンバスのドラッグによるパン、マウスホイール / ピンチによるズーム、ノードへのフォーカス（中央表示）に対応。

4. **ツリー自動レイアウト**
   - ノードの重なりを検出し自動で回避するフォレスト / ツリー配置アルゴリズム。
   - ノードの追加・削除・接続変更時に自動的にレイアウトを再計算。
   - 自由な配置ができる「手動配置モード」と「自動レイアウトモード」をワンクリックで切り替え可能。

5. **データ永続化と多彩なエクスポート**
   - **ブラウザ自動保存**: `localStorage` へのリアルタイム自動保存により、作業の中断・再開がシームレス。名前を付けた複数のマップを、マップごとに保存します（10 を参照）。
   - **JSON インポート / エクスポート**: マップ全体の構造・重要度・イラストデータを JSON 形式で保存・復元（旧バージョン形式からの自動マイグレーション対応）。枝の折りたたみ状態は自動保存・JSON とも保存しません（9 を参照）。
   - **画像エクスポート**: プレゼン資料や共有に便利な高解像度 PNG および ベクター SVG 形式での書き出しに対応。

6. **編集履歴（Undo / Redo）**
   - ヘッダーの「元に戻す」「やり直す」ボタン、または `Ctrl`/`Cmd` + `Z`、`Ctrl`/`Cmd` + `Shift` + `Z`、`Ctrl` + `Y` で操作を取り消し・やり直し。
   - ノードの追加・削除・接続・ラベル・重要度・イラスト・移動・配置モードの変更（枝の複製・貼り付け、箇条書きからの追加、兄弟ノードの順序変更、階層の上げ下げ、親ノードの挿入、ノードだけ削除を含む）を、最大 100 操作まで戻せます。ドラッグによる一連の移動は 1 操作として扱います。
   - 履歴はメモリ上にのみ保持し、JSON や `localStorage` の保存形式は変わりません。

7. **枝の複製とコピー＆ペースト（Phase 9）**
   - ノードを選択して、ヘッダーの「枝を複製」を押すと、そのノードと全子孫（表示フィルターや折りたたみで隠れた子孫を含む）を複製できます。新しいIDを割り当て、親子関係・ラベル・重要度・イラストを引き継ぎます。
   - 手動配置ではマップ全体の下に、自動配置では既存の自動配置で並べます。複製全体は 1 回の Undo / Redo で戻せます。
   - ノードを選択して `Ctrl`/`Cmd` + `C` で、そのノードと全子孫（表示フィルターや折りたたみで隠れた子孫を含む）を専用形式でクリップボードへコピーします。`Ctrl`/`Cmd` + `V` で、同じ画面・別タブ・別マップへ、新しいルートとして貼り付けます（選択ノードの子にはならず、ノードを選択していなくても貼り付けられます）。複製・貼り付けとも折りたたみ指定は引き継がず、新しい枝は展開した状態で追加します。ラベル入力中やページ上の文字を選択している間は、ブラウザ標準のコピー＆貼り付けが優先されます。貼り付け全体は 1 回の Undo / Redo で戻せます。
   - 貼り付けられるのは、このアプリがコピーした枝データだけです（上限 10,000 ノード・5,000,000 文字）。普通の文章や JSON マップ、画像ファイルは貼り付けられません（箇条書きのテキストは 11 のダイアログから追加します）。切り取りには対応していません。対象ブラウザは Chrome・Firefox で、Safari は選択範囲が無いと copy / paste イベントが発火しない場合があり、その場合は既知の制約です。実ブラウザでの実キーボード確認は未実施です。

8. **ノード検索と移動（Phase 10）**
   - ヘッダーの「ノードを検索」へラベルの一部を入力すると、NFKC正規化と大文字・小文字を区別しない照合で、現在のノード配列順に最大50件を表示します。ひらがなとカタカナは区別します。
   - `↑` / `↓` で候補を循環し、`Enter` またはクリックで対象ノードを選択して中央へ移動できます。選択後も一覧は開いたままです。`Escape` は一覧を閉じ、閉じた状態でもう一度押すと検索語を消します。
   - 解像度フィルターで隠れたノードや折りたたまれた枝の中のノードも検索でき、選択時に必要な表示モードへ切り替え、閉じた祖先の枝を展開します。検索、表示切り替え、祖先の展開、移動は Undo / Redo の履歴に追加されず、JSON や `localStorage` の保存形式も変えません。ブラウザ標準の `Ctrl`/`Cmd` + `F` はそのまま利用できます。
   - Codex In-app Browser のダーク配色で、最大50件と総件数、候補選択、隠れたノードの表示切り替えと移動、狭い画面、一覧上の操作遮断を確認済みです。実日本語IME、実キーボード、Safari、タッチ端末、ライト配色は未確認です。

9. **枝の折りたたみ・展開（Phase 11）**
   - 親ノードを選び、ヘッダーの「枝を折りたたむ」から子孫をまとめて隠せます。対象自身は表示したまま、内側の折りたたみ指定も保持します。「折りたたみで非表示」は、選択中の親が閉じている間はその全子孫数（解像度フィルターですでに隠れているノードも含む）で、未選択・葉・展開中の親では 0件です。閉じた親で `Tab` を押して子の追加に成功したときだけ、その親を展開して新しい子の編集を表示します。
   - 既存の編集操作は隠れた子孫も対象にします。削除・複製・コピーは隠れた子孫を含み、手動配置で閉じた親をドラッグすると隠れた子孫も同じ量だけ動きます。複製・貼り付けした枝は展開した状態で追加し、元の枝は閉じたままです。閉じた親への `Shift` + ドラッグの接続では親を開かないため、接続した子は隠れて選択も外れます。詳しくは [features.md の 10.4 節](./docs/specifications/features.md#104-既存の編集操作との関係) を参照してください。
   - 最終表示は折りたたみと解像度フィルターの両方を満たすノードです。検索は非表示の枝も対象にし、結果を選ぶとそのノードまでの閉じた祖先だけを展開して中央へ移動します。
   - 自動配置では表示中の枝を詰めた表示用座標を使いますが、保存座標は変更しません。手動配置へ戻すと保存座標へ戻ります。保存座標が自動配置の結果と一致しないマップ（手編集した JSON など）を読み込んだ場合は、最初の構造変更か「自動配置」の選び直しまでは、折りたたむたびに表示中の枝全体が並べ直されます（展開すると戻り、保存データは変わりません）。折りたたみは Undo / Redo、JSON、`localStorage`、PNG / SVG に保存されず、読み込み・復元・成功した Undo / Redo 後は全展開になります。画像には折りたたみ中も全ノードを出力します。
   - Chrome の本番ビルドで起動、空状態、未選択時の折りたたみボタン disabled を確認済みです。実データでの折りたたみ操作、自動配置、検索移動、画像出力、狭幅、実IME、タッチ操作は未確認です。

10. **複数マップの保存・切り替え（Phase 12）**
   - ヘッダーに開いているマップの名前と「マップ一覧」「新しいマップ」ボタンを表示します。名前を付けてマップを作成し（空欄なら「無題のマップ」。50文字まで。同じ名前も可）、一覧から別のマップを開いて切り替えられます。一覧は更新日時の新しい順に並び、各行に「更新: YYYY/MM/DD HH:mm」を表示します。
   - 一覧から名前の変更と削除ができます。削除は確認ダイアログを出し、開いているマップを削除すると最後に更新した別のマップを、最後の1つを削除すると新しい空の「無題のマップ」を開きます。
   - 切り替えの前に保存待ちの変更を書き込み、書き込めなければ切り替えを中止します。切り替えると編集履歴（Undo / Redo）・表示状態・検索・折りたたみは初期状態に戻り、切り替えの前に始めた JSON 読み込みや PNG 書き出しの結果は新しいマップに混ざりません。
   - `localStorage` には、マップの一覧（インデックス）を `draw-my-map.maps.v1` に、各マップの中身（Version 3 の JSON）を `draw-my-map.maps.v1.doc.<id>` に保存します。Phase 11 までの単一の保存データ（`draw-my-map.map.v1`）は、初回の起動で「無題のマップ」として移行し、次の起動で消します。すべてのマップで約 5MB の容量を共有します。容量が足りないときは「ブラウザへ自動保存できませんでした。不要なマップを削除するか、JSONで書き出してください。」と表示します。
   - JSON の形式は変わらず、マップ名は書き出すファイルの名前（`<マップ名>-YYYYMMDD-HHmmss.json`。PNG・SVG も同じ規則）にだけ使います。JSON の読み込みは、開いているマップの中身だけを置き換えます。
   - ダイアログはキーボードだけで操作でき、Tab の循環、Escape、操作後のフォーカスの戻し先に対応します。ダイアログの表示中はキャンバスとマップのショートカットが働きません。ほかのタブとの同時編集には対応しておらず、最後に書き込んだタブの内容が残ります。詳しくは [features.md の 12 章](./docs/specifications/features.md#12-複数マップ) を参照してください。
   - 実ブラウザでの確認（[docs/testing/browser-test-cases.md](./docs/testing/browser-test-cases.md) の O 節）は未実施です。

11. **箇条書きからマップを作成（Phase 13）**
   - ヘッダーの「箇条書きから追加」でダイアログを開き、メモや議事録などのインデント付きの箇条書きテキストを貼り付けて「プレビュー」を押すと、変換結果の木、件数、警告を確かめてから「マップに追加」でまとめて追加できます。
   - 行頭の空白（タブ・半角スペース・全角スペース）の深さで親子を決め、行頭の記号（`-` `*` `+` `・` `•`）と番号（「1.」「1)」）を1つ取り除きます。「-5度」「3.14」「# 見出し」のように記号の後に空白が無い行や見出しは、そのままラベルにします。空行と記号だけの行は取り込みません。階層が飛んでいる行は補正し、補正した行・記号だけの行・200文字を超える行は、件数と行番号を警告で示します。
   - 上限は1,000,000文字と、空行を除いて10,000行です。プレビューは先頭の200件まで表示します。
   - 追加先は新しいルート（一番上の階層が複数なら複数の木）か、開いた時点で選択していたノードの子です。手動配置ではマップの下（子ならその親の右）に、自動配置では既存の木の下に入力の順で並べます。取り込み全体は 1 回の Undo / Redo で戻せます。追加したノードの重要度は「中」です。
   - ダイアログはキーボードだけで操作でき、ダイアログの表示中はキャンバスとマップのショートカットが働きません。保存形式（V3）と JSON の形式は変わりません。詳しくは [features.md の 13 章](./docs/specifications/features.md#13-箇条書きからの追加) を参照してください。
   - 実ブラウザでの確認（[docs/testing/browser-test-cases.md](./docs/testing/browser-test-cases.md) の P 節）は未実施です。

12. **兄弟ノードの順序変更（Phase 14 の最初の項目）**
   - ノードを選択して、ヘッダーの「上へ」「下へ」か `Alt`（macOS では `Option`）+ `↑` / `↓` を押すと、そのノードの枝（子孫を含む）を、同じ親の見えている兄弟の中で1つ上・1つ下へ移せます。ルート同士も並べ替えられます。表示レベルで隠れた兄弟は飛び越え、消さずに残します。端では理由を通知し、隠れた兄弟が先にあれば表示を「すべて」に切り替えるよう案内します。
   - 自動配置では、ノードをドラッグして同じ親の兄弟の間へ落とすと、その位置へ移せます（挿入位置に青い線が出ます。`Escape` やキャンバスの外で離すと中止します）。手動配置のドラッグは今までどおり位置の移動で、手動配置では並びと一緒に縦位置も入れ替え、画面の上下と並びを一致させます。
   - 1回の並べ替えは 1 回の Undo / Redo で戻せます。順序は `nodes` 配列の順で表すため、保存形式（V3）と JSON の形式は変わりません。詳しくは [features.md の 14 章](./docs/specifications/features.md#14-兄弟ノードの順序変更) を参照してください。
   - 実ブラウザでの確認（[docs/testing/browser-test-cases.md](./docs/testing/browser-test-cases.md) の Q 節）は未実施です。

13. **階層の上げ下げ（Phase 14 の2番目の項目）**
   - ノードを選択して、ヘッダーの「階層を下げる」か `Alt`（macOS では `Option`）+ `→` を押すと、そのノードの枝（子孫を含む）を、見えている直前の兄弟の子の末尾にします。「階層を上げる」か `Alt`（`Option`）+ `←` を押すと、元の親の兄弟にし、兄弟の並びで元の親の直後に入れます（元の親がルートなら、ルートになります）。後ろの兄弟は元の親の子のまま残ります。
   - 表示レベルで隠れた兄弟は飛び越え、元の階層のまま残します。端では理由を通知し、隠れた兄弟が前にあれば表示を「すべて」に切り替えるよう案内します。閉じた兄弟の下へ下げたときは、その兄弟を開きます。
   - 手動配置では、下げると子の追加と同じ位置（新しい親の右）へ、上げると元の親と同じ列で元の親の枝の下へ、枝ごと平行移動します。自動配置では全体を並べ直します。
   - 1回の上げ下げは 1 回の Undo / Redo で戻せます。親子は `parentId`、順序は `nodes` 配列の順で表すため、保存形式（V3）と JSON の形式は変わりません。詳しくは [features.md の 15 章](./docs/specifications/features.md#15-階層の上げ下げ) を参照してください。
   - 実ブラウザでの確認（[docs/testing/browser-test-cases.md](./docs/testing/browser-test-cases.md) の R 節）は未実施です。

14. **途中への親ノード挿入（Phase 14 の3番目の項目）**
   - ノードを選択して、ヘッダーの「親を挿入」か `Alt`（macOS では `Option`）+ `Enter` を押すと、そのノードと親の間に新しいノードを1つ入れ、選択中のノードの枝（子孫を含む）を新しいノードの唯一の子にします。新しいノードは元のノードがいた兄弟の位置に入り、重要度は元のノードから引き継ぎます（ルートに入れると、新しいノードが新しいルートになります）。入れた直後に新しいノードのラベルの入力欄が開きます。
   - 手動配置では、新しいノードを元のノードの位置に置き、元のノードの枝を子の追加と同じ位置（新しいノードの右）へ平行移動します（右側のノードとの重なりは避けません）。自動配置では全体を並べ直します。表示レベルで隠れた兄弟や閉じた枝は消さず、折りたたみを保ちます。
   - 1回の挿入は 1 回の Undo / Redo で戻せます（続くラベルの確定は別の操作）。成功したときは通知を出さず、失敗したときだけ通知します。`Enter` の押し続けでは、兄弟の追加も親の挿入も1回だけで、入力欄が開いたまま残ります。親子は `parentId` で表すため、保存形式（V3）と JSON の形式は変わりません。詳しくは [features.md の 16 章](./docs/specifications/features.md#16-途中への親ノード挿入) を参照してください。
   - 実ブラウザでの確認（[docs/testing/browser-test-cases.md](./docs/testing/browser-test-cases.md) の S 節）は未実施です。

15. **枝の切り取り・移動（Phase 14 の4番目の項目）**
   - ノードを選択してヘッダーの「枝を移動」を押すと、ダイアログで移動先を選び、ノードと全子孫を同じマップの別の親・新しいルート、または別のマップの新しいルートへ移せます。
   - 同一マップの移動は 1 回の Undo / Redo で戻せます。別のマップへの移動は元に戻せず、保存に成功した後に移動先を開きます（実行前に注意を表示します）。
   - 別のマップへの移動はジャーナルに原本を残してから書き、途中で失敗・中断しても原本へ戻します。戻せないときは保護モードへ移り、JSON の書き出しを案内します。
   - 実ブラウザでの確認（[docs/testing/browser-test-cases.md](./docs/testing/browser-test-cases.md) の T 節）は、T-01〜T-11 を Claude Code 内蔵ブラウザと開発サーバーで実施しました。本番ビルド、VoiceOver、Enter の押し続け、JSON のダウンロード、stale の表示、実行中の保護モードへの移行は未確認です。Safari・実 IME・タッチも未確認です。

16. **ノードだけ削除（Phase 14 完了）**
   - ヘッダーの「親を挿入」の直後にある「ノードだけ削除」で、表示中の選択ノード1個だけを削除し、直下の子を元の親へつなぎ直します。隠れた子孫も残り、葉・ルートにも使えます。従来の `Delete` / `Backspace` は枝全体の削除です。
   - 全ノード配列の相対順を基準に子を元の位置へ挿入し、手動配置では残る座標を維持、自動配置では全体を再配置します。1回の Undo / Redo に対応し、成功時は選択を解除します。V3 の保存形式は変わりません。
   - 詳細は [features.md の 18 章](./docs/specifications/features.md#18-ノードだけ削除)。実ブラウザ確認は [U 節](./docs/testing/browser-test-cases.md#phase-14-ノードだけ削除) を含め未実施です。Phase 14 は実装完了、次は Phase 15「アウトライン表示・編集」（候補004、未着手）です。

## クイックスタート

### 前提条件

- **Node.js**: 20.x 以上（推奨: 最新の LTS バージョン）
- **npm**: 10.x 以上

### 起動手順

1. **リポジトリのクローンと移動**
   ```bash
   git clone https://github.com/poteto317/draw-my-map.git
   cd draw-my-map/client
   ```

2. **依存パッケージのインストール**
   ```bash
   npm install
   ```

3. **開発サーバーの起動**
   ```bash
   npm run dev
   ```
   ブラウザで [http://localhost:3000](http://localhost:3000) を開くと、Draw My Map が利用できます。

4. **テスト・型チェック・ビルドの検証**
   ```bash
   npm run verify
   ```
   Tailwind CSS スキャン、ESLint、TypeScript 型チェック、Jest テスト、Next.js プロダクションビルドを一括で実行します。

### AI イラスト生成機能のセットアップ（任意）

AI イラスト生成機能を利用するには、Cloudflare Workers AI のアカウント設定が必要です（無料枠の範囲で利用可能）。  
詳細は [イラスト生成環境構築ガイド](docs/setup/illustration-generation-setup.md) を参照してください。

```bash
# client ディレクトリで設定ファイルを準備
cp -n .env.example .env.local
# .env.local に CLOUDFLARE_ACCOUNT_ID と CLOUDFLARE_API_TOKEN を設定
```
